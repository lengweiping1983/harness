# 当前项目协作约束

本页维护随产品演进的模块边界、协议和业务行为。修改前按工作范围核对；变更约束时同步实现、调用方和回归，不能通过移动文档取消现有约束。稳定协作原则见根目录 `AGENTS.md`，验证方法见 [开发与测试](development.md)。

## 产品概念与术语

本节是产品概念的完整定义来源。产品自有中文使用“智能体”，英文使用 Agent，复数按语境使用 Agents；子级和父级分别为“子智能体”“父智能体”。网络代理仍称“代理”。用户名称、指令、原始日志、第三方名称、代码、工具名、路径和协议字段不改写；例如 `AGENTS.md`、`spawn_agent`、`agent_id` 保持原样。内置内容更新不覆盖用户已修改的技能和提示词。

| 中文 | 英文 | 含义 |
|---|---|---|
| 智能体 | Agent | 使用模型、指令和工具执行工作的主体；配置定义与运行实例分别呈现 |
| 子智能体 | Subagent | 接受另一个智能体委派的执行主体 |
| 团队 | Team | 具有成员、职责和协作关系的智能体组合 |
| 团队负责人／团队成员 | Team lead / Team member | 团队角色，不代替父子委派关系 |
| 模型 | Model | 智能体调用的推理能力来源 |
| 模型接口 | Model API endpoint | 提供商下共享协议、地址、认证和 Key 列表的模型配置单元；中文统一称“接口” |
| 对话 | Conversation | 持续协作的上下文容器 |
| 轮次 | Turn | 对话中具有明确开始和结束边界的交互过程 |
| 运行 | Run | 可追踪、停止及检查恢复状态的执行实例；单次运行的界面详情称“执行任务 / Execution task” |
| 任务 | Task | 具有范围和完成要求的工作事项 |
| 计划 | Plan | 实施前讨论或确认的方案 |
| 执行清单／待办项 | Task checklist / Todo item | 当前工作的步骤集合及其中一项 |
| 任务队列 | Task queue | 等待执行的工作及其顺序 |
| 持续目标 | Goal | 具有预算和停止条件的跨轮次目标 |
| 项目／工作目录 | Project / Working directory | 开发工作组织对象及实际执行目录 |
| 工作区／工作树 | Workspace / Worktree | 操作与检查界面及 Git 独立检出目录 |
| 变更／交付物 | Changes / Deliverables | 明确比较范围的文件变化及可使用或交接的输出 |
| 验证／验收 | Verification / Acceptance | 运行检查取得证据及按需求判断结果 |
| 工具／技能／插件 | Tool / Skill / Plugin | 可调用能力、可复用工作方法及能力包装 |
| 连接器 | Connector | 接入外部服务的连接能力；外部 MCP 连接与 Harness MCP 服务方向不同 |
| 上下文／记忆 | Context / Memory | 当前模型请求可用的信息及以后可召回的信息 |
| 权限／审批／授权 | Permissions / Approval / Grant | 能力边界、作出决定的过程及授予的具体能力与作用域 |
| 钩子／自动化 | Hook / Automation | 指定事件的处理规则及触发执行机制；定时任务是一种自动化 |

“已停止”“已中断”“已取消排队”“执行失败”“结果未知”分别表达真实状态；“运行结束”“交付物已生成”“验证通过”“验收完成”不能互相替代。同一动作在导航、按钮、通知、无障碍名称及帮助中使用一致名称；读取失败后的重新读取不等于重放执行。

请求内容、文件、传输数据及序列化结果的尺寸统一称“大小”；模型 Token 使用“用量”或“占用”，字节大小不等同于 Token 用量。按请求原始顺序展示的列表称“输入项”，仅按大小排序的工具列表称“最大工具定义”。

## 模块边界

模块职责与源码入口统一维护在 [架构与模块](architecture.md#模块职责)。跨模块修改须保持宿主业务装配、核心执行、持久事实与界面投影的边界。

HTTP 线程使用 WebContext 调度协程；WS 和 HTTP 的任务提交都通过 RunController。持久事件先写盘再广播，运行恢复不得重复执行未知副作用。

## 当前格式与公共协议

- 只支持当前 Harness 数据和协议，不增加旧字段别名、旧解析器或自动迁移。
- 新建存储正常初始化；已有文件损坏或格式不符时保留原文件并返回明确错误。
- 不把操作系统支持、MCP 标准协商、第三方模型适配或故障恢复误删为历史兼容。
- 当前 HTTP API 统一使用 `/api/v1`。
- 公共协议变更同步更新生成器、调用方、示例和测试。生成文件不手工编辑。
- 工具副作用使用 `unknown`、`read`、`workspace_write`、`external_write`、`execute`；远程工具无声明时保持未知，不按名称猜测只读。
- 前端使用共享 HTTP 传输，保留操作专用超时；写请求结果未知时先读回状态，不自动重放。

## 必须保持的业务行为

- 常驻智能体／团队选择持续生效，包括尚未物化的新对话；只有用户显式输入 `/agent` 才执行一次性调用，不能用它代替常驻选择。
- 计划和目标输入模式互斥。选择模式不创建任务；当前无目标时，裸 `/goal` 先打开设置表单。
- 编辑已发送消息在原位置进行，不覆盖底部草稿，不自动切换分支。运行中的普通编辑作为持久引导在安全边界采用，不发送手动停止。
- 普通发送仍排队；队列“引导”保留独立语义。重排使用后端完整快照比较并持久化，结果未知只回查。
- 右侧任务队列复用对话附件展示：图片可放大、文件可打开，纯附件任务显示“附件消息”。编辑只修改原文字，保留原附件引用；有附件时允许清空文字，无附件时仍拒绝空内容。列表及编辑区保持附件身份，不把附件描述拼入用户正文。
- 对话正文的本人用户消息使用靠右、随内容收缩的气泡；助手正文和过程活动靠左。本人名称与发送时间保留辅助技术语义，不额外占据气泡首行；其他参与者身份及引导状态仍可见。用户消息操作靠右，其他消息操作靠左；不增加引用或回复回填入口。操作条不占据气泡内部空间。选中单条用户消息正文复制时使用可见纯文本，保留所选空白与段落，按实际选中文本的尾部换行限制可见选区补出的尾部换行，不使用 trimEnd 删除原文空白，不携带富文本段落容器；完整消息复制按钮继续复制原始正文。消息操作栏不参与文字选择，三击选区越过操作栏及正文末尾的段落空白边界时仍复制正文；对话层接收落在正文外的复制事件，关闭或切换对话后撤销原监听。跨到其他消息正文、附件、链接文字或控件文字的选择及编辑器保留浏览器原有复制行为。
- 工具详情默认收起；展开后使用完整边框与圆角标明起止，顶部以独立底色集中显示工具名、真实状态、耗时与退出码，正文分开呈现输入、输出及运行期间输出，底部学习入口与执行证据分隔。JSON 与所属输入／输出分区共用一层边界，下一条活动与详情卡片之间保留间距。交互问题即使轮次折叠仍保留可见入口。参数校验拒绝有明确未执行证据时显示“参数有误，未执行”，不视作命令执行失败；write 的 FS_EXISTS 显示文件已存在且未覆盖，提示先读取后修改。原始诊断保留在技术详情中。bash 的 timeout 使用秒，2 分钟填写 120，不接受毫秒值 120000 或隐式单位转换。
- 文件读取路径依据实际目录、搜索结果、已读配置或用户明确提供的路径，不能按框架惯例猜测入口。缺失路径保留失败状态和 `FS_NOT_FOUND`；同名候选用于定位，不自动读取替代文件。无同名候选时，在工作目录内提供最近存在父目录的最多 32 个可见条目并标明截断；目录定位不建立文件内容观察。新增文件不要求预先读取不存在的路径，也不能仅为消除错误盲目创建入口。
- `todo_update` 只修改已有任务，ID 必须来自所选清单的真实快照；新增、删除用 `todo_write` 提交合并后的完整清单，保留已有任务身份、状态和证据，仅新任务省略 ID。未知任务 ID 拒绝整个更新批次；恢复提示区分修改已有任务与新增任务，不把省略 ID 当作 `todo_update` 的有效调用方式。
- 普通开发未建执行清单时，连续成功写入只触发有限建议，不跳过后续工具、不强制增加收尾轮次，也不因提醒次数耗尽终止任务。用户已批准计划时，实施前仍须建立非空真实清单；普通提醒不能绕过该约束。清单提交的版本、任务身份和证据仍按原协议核对。
- 同一轮内相邻的思考与工具活动共用一个默认收起的过程摘要，以真实当前活动作为主标签，思考段数和工具调用次数作为次级信息；不显示字符数。连续思考只占一个入口，展开过程组后，各条思考仍默认收起，通过各自摘要查看原文。单独思考和组内思考使用同一折叠入口，流式开始不自动展开，流式结束重新收起。正文回复、轮次、成员身份及交互问题保持分组边界，运行中和失败的工具仍独立可见。
- 轮次摘要显示开始到结束的经过时间，包含模型、工具与等待。仅当前确认为运行中的最新轮次按秒刷新；完成后显示固定用时，停止与其他终态保留区别。缺少起止依据不填零值，断线或未确认运行时显示待同步，不把历史未结束轮次作为活动任务计时。计时不依赖过程是否展开，页面隐藏暂停刷新。
- 轮次、执行任务和生成进度共用整秒经过时间格式，中文数字与单位留空格（如“2 分钟 20 秒”），超过一小时显示小时、分钟和秒。执行任务不足一秒保留“不到 1 秒”，工具等精细耗时保留毫秒精度。正常停止显示“已停止”，重启等异常中断显示“已中断”；队列移除、引导和请求层取消保留各自语义，未知工具副作用仍须核实。
- 运行图标依赖真实活动任务，结束或停止后隐藏，切换对话也必须同步。
- 任务结束时，当前窗口中实际可见且聚焦的对话不新增完成通知或未读标记；其他对话显示蓝色未读点并提供完成通知。选中的对话不显示蓝点，恢复到可见对话或打开通知目标后清除未读。设置、覆盖抽屉及全屏检查器遮挡正文时不视为正在阅读。完成、失败和中断通知保留真实状态，运行事件与快照不得重复通知。
- 目标消息靠显式序号关联，不能用相同正文猜测；不得覆盖未完成目标或复制原消息。
- 严格团队验收必须有可核验依据。工具成功、轮次结束和 Git 提交都不能替代业务完成证据。
- 终端、原生浏览器、下载、对话框及截图保持对话、来源和生命周期隔离。

## 界面规则

- 沿用系统中文字体及统一等宽字体，不引入远程字体加载。
- 默认字号使用 12／13／14／16／20／28 六档，选择语义化 Tailwind 类；保留根字号 10–22 的用户设置。
- 不添加任意像素或 rem 字号；代码、公式、图表和截图标注保留内容排版需要。
- 尺寸、圆角、行高、层级及布局使用 Tailwind 标准类或 `web/tailwind.config.js` 中的共享语义令牌；阅读正文统一 `leading-reading`，代码统一 `leading-code`，不在组件内重复近似任意值。
- 使用主题、状态颜色和公共 UI 原语；透明度 12% 必须使用可编译的 `/[0.12]` 语法。收展入口统一使用线条箭头，收起时向右、展开时向下；原生 `details/summary` 沿用共享样式，不显示浏览器实心三角。普通刷新操作统一使用无边框的公共刷新按钮，空间充足时显示刷新图标和“刷新”，容器空间不足时只显示图标；两种形式都用当前语言的完整无障碍名称说明刷新对象。

同类信息按语义选字号：设置页与面板标题使用 `ui-section-title`（16px），卡片标题使用 `ui-card-title`（14px），分组标签使用 `ui-group-title`（12px），字段与紧凑列表正文使用 13px，阅读正文使用 16px，20／28px 留给独立大标题。分组标签不强制大写或增加字距，文件名、代码与用户原文保持大小写。

圆角按容器层级分配：紧凑徽标与工具按钮 6px，标准控件 8px，普通卡片 12px，对话框 16px，composer 使用独立的 26px 外轮廓，圆形发送按钮保持圆形；按钮尺寸变化不改变标准控件圆角。卡片留白按密度选择：活动与紧凑列表 8–12px，设置表单与普通卡片 12–16px，对话框与输入正文 20–24px；同一种容器不随页面任意变化。按钮高度使用公共 xs／sm／md／lg 的 24／32／36／44px，composer 发送为 36px，同排紧凑操作为 32px 并居中对齐。

品牌 teal 表达主要操作、焦点与选择；ok 表达成功与文件增加；warn 表达需关注的权限与风险（包括完全访问）；danger 表达错误、破坏性操作与文件删除。警告不因需要醒目而改用 danger。原生 checkbox／radio／range 与共享开关沿用品牌色，select 使用主题表面与品牌焦点；原生弹出菜单的选中行由操作系统绘制。动作图标沿用 Lucide 线条，选中或运行状态可填充；文件类型使用专用图标与明暗自适应配色，不能依赖颜色作为唯一识别方式。第三方网页、语法高亮与图表的内容色不强制映射成产品状态色。

中文产品句子使用中文标点，英文使用英文标点；命令、路径、正则、JSON 与第三方原文保留原样。中文与独立英文术语／数字之间留半角空格，如“钩子统计信息”“模型 1”“第 1 条用户消息”；完整文案与空格维护在源资源，不对用户原文运行全局替换。

- 工具目录说明通过原生展开控件提供完整正文，键盘和触屏均可读取；机器工具名保持原样。内置工具搜索独立成行，按名称、说明和分类筛选，区分匹配数与全部数量；清除搜索后回到输入框，空目录与无匹配结果分别说明，分组保留原文大小写。目录浏览按钮标明目录操作，并通过无障碍名称关联目标字段；插件刷新保持只读，不隐式同步远端内容。
- 统计页区分首屏摘要和展开明细；未知用量与计量异常不能随明细折叠而隐藏，也不能把团队总量与所选对话的统计范围混为一谈。空目录不重复展示零比零计数，读取失败不能显示为已确认的空列表。
- 对话统计先并排展示实际请求尝试与已报告用量的请求，再依次展示工具调用、工具失败和直属子智能体；阅读顺序与页面布局一致，标签与数值保持对应。
- 右侧执行清单用图标及文字共同区分未开始、进行中、已完成和未知状态，不只依赖颜色。进度条提供已完成项数与总数的可访问说明；空清单不显示虚构的零进度，任务原文及长路径保持完整并允许换行。完成标记仍是智能体报告的进度，不代替验证证据。
- 计划区有已读取版本时，在标题中显示版本总数，例如“计划（1 个版本）”，不再单独占一行重复计数。版本选择框保留可访问名称，切换语言不改变选择；首次加载、读取失败且没有可用列表或空列表时不虚构版本数量。
- 文本、数值输入框及选择框使用与边界重合的单层焦点描边，不叠加外圈与阴影；带外框的组合搜索和消息编辑卡片使用 `ui-input-group` 将焦点描边放在完整外框，内部输入及文本区不重复描边。消息编辑区随正文增长，短消息保持紧凑，长消息在高度上限内滚动。全局保留可见的键盘焦点。
- 对话正文与输入区共用随中栏可用宽度伸展的通道，超宽时限制工作区宽度；正文段落、列表、代码、表格和交付物共用完整通道，不为段落单独设置较窄的换行宽度。过程摘要、思考与普通工具摘要共用 xs 密度的紧凑活动行，不叠加外层纵向留白；默认根字号下行高为 24px，图标与文字之间、文字与收展箭头之间均为 6px，并随用户字号缩放。图标靠左，收展箭头紧跟摘要文字或工具详情摘要，不推到行右边界；长文件名和命令在可用宽度内截断，并为箭头保留空间。轮次用时与过程分组摘要共用 text-xs、常规字重和紧凑控件；分组主标签、统计与状态计数位于同一横向内容通道，空间充足时单行显示，宽度不足时自然换行，不为状态计数固定另起一行。过程组以浅色底区分层级，统计作为次级信息，失败仍保留图标与颜色；悬停和键盘焦点提供行反馈。可视化工具的摘要与详情位置见 [对话内可视化](conversation-visualizations.md#交互状态与隔离)。消息从对话区顶部按时间顺序排列，日期分隔位于消息之前；不显示底层历史事件计数，历史控制行仅在还有更早记录、正在读取、读取失败或需要重读时出现；短对话的剩余空间留在消息下方，不在用户消息上方撑出留白，长对话沿原虚拟列表滚动并按用户意图跟随新回复。有消息的输入区靠近页面底部，空编辑器保持紧凑，随草稿增长并在高度上限内滚动。生成状态与执行清单在空间允许时并排显示为轻量状态行，窄容器换行；详情默认收起，展开后独占一行，完整模型名与清单仍可通过键盘和触屏读取。异常、未确认写入和停止反馈保留各自入口。卡片下方只保留紧凑间距与移动设备安全区，不常驻文件粘贴提示与快捷键说明栏；附件操作和全局快捷键说明入口继续可用。
- 页面修改检查明暗主题、中英文、窄屏、键盘焦点、空态、错误态与加载态。
- 隐藏面板暂停观察和轮询，异步回包不得覆盖另一对话或已关闭页面。
- 后台任务面板在加载、空态、列表与读取失败时保留同一刷新入口；手动刷新与定时读取共用一次在途请求。上次读到空列表后再次读取失败，仍须显示错误，不能继续宣称当前没有后台任务。下一次成功读取后清除错误；隐藏时取消只读请求，恢复后重新核对。
- 加入后的受邀对话与本机对话共用中间页面及输入区呈现组件，不挂载左右栏；权限差异通过业务适配器控制，不另写一套对话页面。

### 工作区与导航

- 新对话先选择项目，需要持久对话的显式操作受理时才创建记录。项目、分支与 Worktree 使用 [新对话接口](api.md#web-api) 中的统一流程；添加项目页面与输入区共享检出选项，不隐式切分支、不在工作树失败后回退原目录。
- 输入框下方的项目设置栏使用 24px 紧凑控件与上下各 2px 留白，项目、分支、Worktree 和刷新优先同行排列；窄屏允许换行，首次提交限制、脏目录警告及读取失败仍完整显示。目录选择器中的检出控件保持标准尺寸。
- 分支选择使用跟随明暗主题的浮层，当前分支有勾选标识，长名称在列表中完整换行；浮层沿用共享锚点定位并限制在视口内。键盘支持方向键、Home/End、Enter/空格选择、Escape 关闭及 Tab 离开，组合输入不触发操作。切换项目或检出模式、隐藏页面或禁用控件时关闭原浮层；选择只更新检出草稿，首次发送仍沿原检出确认流程。

- 三栏按职责组织：左侧选择项目与对话，中间协作执行并展示本轮结果，右侧检查进度、变更、文件、预览及终端。窄屏沿用同一组件切换。启动器提供进度、变更、文件／预览／终端三组主要入口；执行详情紧跟进度，学习与帮助位于主要入口之后，各组默认展开并可独立收起。分区选择器沿用同一分组顺序。审批、失败与待核实事项仍沿对话和运行状态呈现。
- 凭据遮罩统一遵循 [API 密钥显示规则](api.md#模型连接与设置提交)，只供展示，不能把遮罩当作新凭据提交。
- 密码、密钥及配对码的显隐操作统一放在输入框右侧内部，仅显示眼睛图标；按钮保留随语言切换的无障碍名称、键盘焦点与禁用状态。Web 页面复用 `SecretInput`，异步读取凭据仍由原业务拥有，不因渲染或语言切换读取明文。
- 设置目录由 `web/src/lib/settingsCatalog.ts` 维护，导航、搜索及命令面板共用页面身份和资源。分为基础设置、智能体与能力、连接与扩展、高级与自动化；首次默认展开全部分组，用户可独立收起，搜索跨全部分组，定向入口展开所属组。隐藏页面不参与方向键选择。
- 运行中停止入口始终保留，草稿或附件存在时另行显示排队发送；普通发送与立即引导保持独立。停止不清除尚未发送的草稿。保存状态共用词义，配置已保存与正在执行的实际配置分别解释；未知结果先回查，不自动重放保存。
- 右侧工作区入口命名为“启动器”。终端页签优先显示用户名称，未命名时显示终端类型及列表序号；内部会话 ID 仍用于协议定位。命令模式的上方区域仅展示输出，不提供禁用的键盘输入入口，下方命令框负责整行发送；交互模式保留直接键盘输入。
- 检查器固定面板的标识、标签资源、目录顺序、搜索关键词和诊断分组由 `web/src/lib/inspectorPanels.ts` 统一维护，供启动器、分区选择器、命令面板和持久页签恢复使用。已打开页签保留打开顺序，成员页签仍按对话注册，不强行按目录重排。
- `runtime` 面板统一显示“后台任务 / Background tasks”，页签、分区选择器、启动器、面板标题及相关提示共用这一名称；内部协议和持久页签标识保持 `runtime`。
- 检查器页签支持方向键、Home/End 切换和 Delete 关闭；输入法组合标记及键码 229 期间均保留当前页签、数量和焦点。关闭当前页签后聚焦相邻页签，关闭最后一个后回到对话。
- 队列中的“任务历史 / Task history”展示跨次任务的输入、结果及恢复入口；单次运行的查看入口和详情统一称“执行任务 / Execution task”，关闭按钮只显示“关闭 / Close”。独立的“请求与工具日志 / Request and tool log”展示模型请求、工具调用和子智能体活动。日志先读完当前层级的轻量列表，再按本地日期及小时分组，后续页面中的小时不依赖前一组的展开而显示；小时分组可独立收展，组内“显示更多”位于日志列表末尾，与请求条目同级缩进；只增加该组呈现的条目，沿用尾数合并规则。刷新保留各组的收展状态与已展开数量；后续页失败时保留此前完整列表并显示错误。模型请求按当前对话的时间顺序编号，详情沿用列表序号与样式；内部请求 ID 仍用于协议定位，不作为列表与详情的用户标题。详情返回入口使用面板全名，请求大小、发送前的对话状态、请求参数、工具定义及消息顺序使用无外围框的收展标题，消息角色统一使用同款徽标，以角色名称区分系统指令、用户消息、模型回复和工具结果。工具调用中的“查看关联请求 / View related request”打开产生该调用的模型请求详情。发送前的对话状态只展示记录与内容片段数量，实际发送内容以请求体为准；说明中的“请求体”可点击并直接切换右侧内容。请求大小中的输入按原始顺序展示，少于 20 项全部显示，达到 20 项时先显示 10 项并可继续展开；最大工具定义按大小排序最多显示 8 项。工具说明在请求详情及工具日志的名称上停留或聚焦时提示，不常驻占用列表空间；旧日志未保存说明时按需读取对应请求档案。请求结果的流耗时、解析事件数和首个解析事件分行展示；Token 只用于模型用量，字节用于请求大小，紧凑列表可使用 B。查看请求体紧跟请求参数收展项，沿用同一无外围框样式。列表“显示更多”与对话活动共用无边框的展开式入口。两者的导航、提示和无障碍名称按各自功能统一命名，机器协议保持其原有含义。
- 变更面板的比较端点按底层差异的基准到结果顺序显示：历史轮次为修改前到修改后，其余范围为 `left` 到 `right`；新增与删除计数沿用同一方向。比较失败时保留顶部刷新入口，错误提示中不重复显示刷新操作。
- 设置页面直接呈现对应功能，不常驻显示通用作用域或保存说明；保存方式与反馈由具体表单提供。权限与预算页面保留可编辑权限及预算，不重复展示只读模型能力摘要。
- 设置导航保留 `aria-current="page"` 的页面导航语义，支持方向键及 Home/End；分段页签复用共享键盘处理，带修饰键和输入法组合输入不切换页面。设置搜索有内容时按 Escape 先清空搜索且不关闭设置，切换子页面后内容从顶部开始显示。

## 代码生成的具体边界

新增和修改代码遵循 [代码生成与防回归](code-generation.md)：运行时双语资源解析、请求代次隔离、组合输入保护、当前协议校验、真实组件回归及未知写入回查。

## 快捷键

- 应用主修饰键在 macOS 显示为 `⌘`，Windows／Linux 显示为 `Ctrl`；设置、快捷键说明与侧栏使用共享快捷键定义和格式化。终端专用的字面 Control 组合保留 `Ctrl`。
- 新建对话使用 `⌘⇧U`（macOS）或 `Ctrl+Shift+U`（Windows／Linux），与桌面原生菜单一致；不再使用裸 `N`。网页输入框中组合键可用，输入法组合输入和已打开的设置／快捷键等浮层不触发新建；终端内的 Shell Control 编辑组合保持原有归属。

## 文本编码

框架自有源码、文件与通信默认严格 UTF-8，特殊编码由工具参数或协议适配器明确声明，不猜测、不自动转换历史数据。所属 Python 进程在启动边界统一 UTF-8 默认；嵌入 SDK 不修改宿主编码或内置 open。命令解码完整性与实际进程退出结果分开记录，失败不重放。详情见 [文本编码](text-encoding.md)。
