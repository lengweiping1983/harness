# 扩展能力

Harness 通过智能体、团队、技能、连接器和插件扩展运行能力。各扩展共用宿主工具注册、权限和生命周期管理；配置入口与使用边界如下。

## 智能体与团队

智能体声明由 `harness/agents/parser.py` 解析，使用目录及 `AGENTS.md`。团队通过成员、角色、依赖和提示词定义协作；工具权限由宿主分配，不在智能体声明中自行授权工具。

界面选择的智能体或团队持续生效，包括尚未物化的新对话。显式输入 `/agent <name> <任务>` 是单次调用。宿主维护成员上下文、运行身份、派工权限和证据验收；工具成功、轮次结束或 Git 提交不能单独证明业务完成。

成员等待与列表的模型摘要带实际花名册 ID，任务描述相同不会改变成员身份。依赖交付使用结构化原文，保留成员、运行、上下文和状态；转交原文不代表其业务主张已被宿主验证。

派工的 `member` 使用团队花名册成员 ID，`agent` 才是引用定义名；错误成员调用会返回当前可派工的成员 ID，不自动映射或猜测。 成员尚未落定时重复派工会拒绝创建，并返回该成员真实运行 ID 与状态；即使已满并发也优先给出原成员的等待／续接入口，不能用重复派工代替等待。 团队运行时，模型可见的 `spawn_agent.member` 参数按当前冻结花名册列出合法值并要求提供；该投影只作用于本轮团队负责人，不改共享工具定义，结束后恢复。参数投影不能代替宿主执行校验。

主持人与成员上下文均包含按任务选用的专业协作方法：澄清关键未知、互补分工、检验替代解释、按证据调整及可追溯交付。研究、决策、创意和工程任务采用不同重点；不强制固定提问数、轮数、候选数、JSON 或通用评分表。这是提示词指引，不是效果保证或新的宿主验收闸。

团队负责人的公共协作合同要求派工包含子问题、必要上下文、读写范围、交付格式、成功及停止条件。独立只读调查可并行；共享目录写入须先划定互斥范围。返工通过原成员续接，提供失败条件与新证据；重复失败无新增信息时应报告阻塞。用户指定读取范围时，派工需保留原限制，不能弱化为仅限制引用来源。记忆、项目板、运行清单及历史不自动成为允许资料；资料不可访问时须报告限制，不自行扩展。以上属于模型行为指引，宿主仍负责身份、权限、依赖和验收约束。

严格验收按真实工具类型判断命令是否完成：即使成员将命令声明为 `observation`，后台命令或缺少零退出码的命令也不能通过；普通读取观察无需退出码。`job_output` 必须是 completed 且整数 exitCode=0；终端等待与归档作业回执不能充当命令完成证据。真实工具成功只建立证据关联，不证明检查描述与业务条件一致。

`wait_agent` 等待成员结果须传真实运行 ID；省略 ID 的语义是收件箱等待。`wait_agents(agent_ids, timeout?)` 在共享等待期限内观察显式指定的 1 至 32 个不同成员，按输入顺序返回有界结果／错误预览、实际状态和 `settled`，以及成功、失败／中断、尚未收尾计数；`timed_out` 包含仍执行或清理的成员。进入终态但尚在清理的成员不计为成功收尾，超时和取消观察都不停止成员。零秒只观察现状，不创建收尾；已经结束的收尾异常仍须传播，不能当成观察超时或成功。两种等待均先授权目标，只有目标查询的缺失或不可见错误转换为成员不可用；执行及收尾本身的 `KeyError` 等原始异常保留，不伪装成目标不存在。模型正文包含同一有界摘要，截断结果标记 `result_truncated`；等待结果不能充当目标验收证据。当前团队有尚未取回的成员结果且无待收消息时，省略 ID 的 `wait_agent` 返回这些 ID 要求修正调用，不阻塞消息读取；批量等待仅核销实际已收尾成员的取回标记。收尾失败反馈用于下一次纠正调用，执行工具后清除过期状态，下一次最终回答仍由宿主重新验收。

跨轮次可用历史成员运行 ID 调用 `followup_task`：仅原父对话已落定的成员可进入该路径，当前团队按配置签名复核上下文；身份、模型、权限或工作区不匹配时明确拒绝。

成员持久上下文索引须先通过校验，团队才向主对话绑定本轮回复与访问限制。格式损坏时保留原记录并明确失败，不把初始化失败的约束残留到普通对话；不自动修复或迁移上下文。

团队 lead 成员的 `access=read` 会将主对话协调者限制为读取和现有协作控制入口，同时应用工具可见性过滤与执行前复核，禁止直接文件写入、命令及未知副作用工具。结束后恢复此前限制；省略或 `inherit` 不新增限制。该声明仅限定团队负责人，各成员仍按自己的访问级别和授权执行，不能用派工绕过任务边界。

架构评审场景 `architecture-lab` 面向系统设计和跨模块演进，按任务选择质量场景、结构与状态语义、独立风险复核；团队负责人与成员均显式只读。评审区分受理、完成与持久提交，不自动执行代码修改、迁移或部署，不凭技术名称断言性能和数据保证。

故障诊断场景 `incident-lab` 将证据调查、恢复建议和独立复核分为可选角色，默认只读；按题目区分止损、服务恢复和根因确认，不自动执行重启、清理或生产变更。选择和安装方式与其他示例一致。

团队页提供可编辑的专业团队起点：工程交付、安全审查、产品探索、性能诊断和证据研究。选择“创建此团队”后，在现有编辑器检查并保存；也可使用编辑器的保存并使用入口。成员指令内联，无需先安装单独成员，全部使用当前对话模型；没有固定到特定提供方或调用外部 CLI。创建不会启动模型或自动发送消息。模板卡片和待选指令按当前界面语言解析；进入编辑器后成为用户草稿，语言切换不改写正文，保存后同样按原文使用。

模板副本按当前目录预选未占用的标识，智能体与团队共用名称空间：默认使用 `team-<类别>-custom`，已占用时从 `team-<类别>-2-custom` 逐个选择。保存后刷新目录，下一次创建使用更新后的名称集合；已有配置及其正文保持原样。预选不能代替服务端的同名冲突保护；目录过期或并发创建时仍明确拒绝，不覆盖配置，也不自动改名重发。用户仍可在高级设置中调整标识。

工程交付团队的规划、实现、复核按依赖推进，共享目录仅实现者有继承写权限；团队负责人、规划者和复核者只读。复核者可以检查源码和原始工具证据，不能声称自己执行了命令。其余四类团队所有角色只读。团队负责人按问题选择必要成员，花名册不代表每次都要启动全员。模板明确分工合同、来源范围、证据定位、停止及返工条件，但提示方法不保证输出正确，也不会自动建立严格验收合同；身份、依赖及只读限制仍由宿主执行。模板由 `web/src/lib/teamTemplates.ts` 的稳定身份与双语资源生成，保存沿用现有智能体创建协议、作用域和草稿机制。

这些起点参考了 [OpenAI Agents SDK 的团队负责人编排实现](https://github.com/openai/openai-agents-python/blob/main/docs/multi_agent.md)、[Anthropic 多智能体研究系统的任务边界与评估实践](https://www.anthropic.com/engineering/multi-agent-research-system)及 [Claude Code 团队的独立任务与文件冲突边界](https://code.claude.com/docs/en/agent-teams)。未引入另一套执行引擎；没有同输入的质量、成本和延迟对照，不据此作跨产品优劣结论。

`examples/teams` 另提供可选的独立智能体／团队目录示例。通过智能体／团队页的“浏览”选择包含 `AGENTS.md` 的目录安装；引用独立成员的团队需先安装成员，并选择相同使用范围。核心不自动安装或选择，使用方式见[团队示例](../examples/teams/README.md)。 自定义智能体头像从所属目录句柄读取，单文件上限5 MiB，读取前后核对普通文件身份与大小；Windows使用实际文件句柄路径确认目录边界。头像ETag绑定实际预览正文，不复用仅按路径、时间与大小标识的缓存。超限或读取期间变化返回明确错误，原文件保持。平台机制的受控回归不等于Windows实机竞态验收。

只读团队成员仅能发现和执行显式声明为 `read` 的工具；内置 `web_fetch` 与 `web_search` 已声明为读取能力。远程或未知工具不按名称推断只读，仍需可信副作用声明，并受现有授权约束。

### 编辑器与技能配置

智能体定义编辑器的保存回执、草稿存储提示及后续挂载/目录刷新提示保留资源身份，切换语言时重新解析；刷新错误中的第三方正文保持原文，多个原因按当前语言分隔。切换语言不会重新保存配置或草稿；人格目录仍按实际语言重新加载。

同一编辑器的创建、编辑保存及文件导入共用同步操作锁，同一事件内连续触发也只受理一次。保存锁持续到后续挂载及目录刷新结束；期间关闭、丢弃、新建和另存副本不能替换已提交草稿。明确拒绝后保留草稿并恢复操作入口；语言切换不释放在途锁。

外部选择或查看另一个定义时，编辑器建立新的草稿代次。旧保存、导入及目录刷新回执不能关闭、改写或向新草稿发布错误，也不能继续触发旧保存的后续挂载与呈现。已发出的请求仍正常结束；过期保存不自动清理其浏览器草稿，也不自动重发。新草稿在原在途操作结束后可显式保存。

创建及编辑回执先经过公共响应契约校验：`created`／`updated` 必须明确为 `true`，须包含已保存定义的名称和类型，编辑还须包含有效版本。编辑器再核对名称和类型与本次提交一致，确认前不清理草稿或继续挂载。空响应、损坏响应、身份错配、网络错误、408 和服务端错误保留未知结果；原草稿仍有效时，在同一次操作锁内尝试只读刷新目录，并以当前语言保留未确认提示及原诊断。回查失败同时保留两个阶段的原因。目录出现同名项不等于确认原保存成功，不自动重发保存；明确的其他 4xx 拒绝仍保留原错误和草稿。

智能体编辑器的“技能选择”与设置页共用当前项目技能目录，支持搜索、选中搜索结果、清空和继承技能。开启“继承技能”使用默认设置；再次关闭时恢复本次开启前的选择（包括未选择任何技能），不将继承结果复制为手动选择。保存继承时只保留 `skills: null` 的语义（声明文件省略该字段），不保存技能数量或目录快照；默认设置的新增技能和启停变更会在后续轮次生效。设置页启停是默认智能体的技能配置；指定智能体的显式列表独立生效，可以选择默认配置中停用的技能，且不回写默认开关。所属插件停用、技能文件不存在或技能系统关闭时，显式列表不能恢复这些技能。技能禁止隐式调用时，模型仍不能通过技能工具加载；用户显式入口与模型工具遵循各自的加载边界。独立 ACP 执行器使用自己的技能配置，编辑器不提供技能选择；保存外部执行器配置时不提交技能选择，解析器拒绝外部执行器与非空技能列表的组合。

团队及团队关联成员不提供技能选择入口，关联智能体沿用自身配置；已有技能配置在编辑保存时保留。智能体简介可选，留空时不从工作指令自动生成。智能体与团队的人格只保存完整的 `metadata.personality_prompt` 正文，不保存模板代号，也不在运行时根据代号生成正文。名称、职业、人格和执行器字段在编辑时实时同步到完整扩展配置 JSON；JSON 未完成或格式错误时保留原文并阻止保存。

内置沟通人格使用语义化标识（例如 `systems-planner`、`research-analyst`）；四项推荐偏好使用 `reflective`／`proactive`、`conceptual`／`concrete`、`analytical`／`empathetic`、`structured`／`adaptive`。推荐返回对应模板标识，保存与选择仍使用目录和版本检查。全局选中的内置人格按当前调用语言解析名称、说明和运行提示词，不改写保存原件或变更选择版本；用户人格及智能体配置正文仍保留原文。不接受旧字母代号，不自动改写用户已有存储。

## 技能

技能由 `harness/skills` 发现和解析，系统发现路径为仓库 `.harness/skills`，当前未附带预装技能；目录缺失时系统目录为空。用户与项目安装路径由 `skills/paths.py` 确定；技能正文按需加载，不把完整提示词放入浏览器语言包。`author_skill` 和 `author_plugin` 不依赖预装的创建辅助技能；`skill-creator`、`plugin-creator` 在当前技能目录中可用时才先加载，缺失时按创建工具的参数与校验要求操作。

当前发现入口 `build_default_registry` 与 `for_project` 从工作目录向最近 Git 边界逐级扫描 `.agents/skills` 和 `.harness/skills`，较近目录优先，同目录 `.agents` 优先。随后加入用户共享技能目录、运行根 `skills/`，最后加入存在的随包系统技能目录；插件技能由独立 provider 提供。显式 `extra_roots` 使用调用方给定的优先级。目录不存在不创建，也不搬移、删除或合并用户文件。

非 Git 目录只扫描当前目录；Git 项目从工作目录扫描到最近 Git 边界。项目中任一受支持技能目录即使为空，也会阻止 `fallback_root` 的主工作区回退；只有这些目录均不存在时，才加入显式回退根。安装目标与发现来源分别由 `skills/paths.py` 和 `skills/registry.py` 管理。

`AGENTS.md` 支持顶层 `skills` 和 `members[].skills`。省略或 `null` 表示继承，`[]` 表示不启用任何技能；名称允许独立技能名及 `plugin:skill` 限定名，禁止重复。团队的优先级是成员显式选择 → 引用智能体的显式选择 → 团队公共选择 → 默认设置，团队负责人也使用同一规则。示例：

```yaml
---
name: writing-team
description: 写作与审阅团队
agent_type: team
skills: [writing]
members:
  - name: coordinator
    role: lead
    prompt: 拆解并汇总任务
  - name: reviewer
    prompt: 审阅结果
    skills: [review]
---
团队协作指令。
```

示例技能名应替换成当前已安装技能。配置随创建、编辑、复制、导入及导出保留，未保存选择进入当前编辑草稿。运行中保存的选择在下一轮次生效，当前目录与技能工具使用同一份轮次选择。团队成员私有上下文按显式技能配置区分，避免改选后混用旧配置历史；继承默认时不改变原上下文标识。

技能只能指导使用宿主实际可用的工具。添加技能时核对工具注册表、依赖及分发内容，不将不存在的生成模型或工具描述为内置能力。

## 连接器

连接器是带生命周期的 MCP 声明，存放于版本化 `connectors.json`。安装、启用和授权是不同操作：启动时仅接入同时为 `enabled` 和 `bound` 的声明；手动启用保存启用状态并尝试连接、注册工具，返回连接状态与工具数量。绑定先探测连接并等待其关闭，成功后保存 `bound`；已启用的连接器随后正式接入。停用注销工具并关闭连接，旧声明不能覆盖更新后的注册状态。

环境变量引用采用 `${VAR}`，连接时解析；OAuth 凭据由凭据存储管理。默认在 Windows 优先使用凭据管理器；其他平台或系统后端不可用时使用运行根中的 `oauth-credentials.json`，文件权限为 `0600`，内容未加密。环境变量 PAT 不写入连接器声明，只保存引用。不要把密钥写入清单、普通设置或日志。预设位于 `harness/connectors/presets.py`，运行管理位于 `manager.py`。 SDK 的 `CredentialStore` 支持 `auto`、`wincred`、`file` 和 `memory`；`auto` 在可用的 Windows 凭据管理器之外，只有提供 `home` 才选择文件后端，否则保存在进程内存中。

连接器目录界面由 `EscPanel.tsx` 装配，连接器表单和授权展示由 `ConnectorsTab.tsx` 管理，共享目录控件与数据类型分别位于 `ExtensionCatalogControls.tsx` 和 `lib/extensionCatalog.ts`。OAuth 状态只在面板可见且没有正在提交的目录操作时轮询，同批请求全部结束后统一发布已确认状态，再安排下一轮；较快的结果不会取消并重读同批较慢的连接器。隐藏或卸载时取消读取。目录刷新结果是权威状态，不被旧轮询镜像持续覆盖。

连接器页面的推荐、添加入口和名称字段统一使用“连接器”。搜索匹配原始名称、显示名称、说明、命令和网址，显示匹配数量；没有匹配结果时提示换词或清除搜索，只有目录为空时才引导添加连接器。搜索、清除搜索及切换语言不修改连接器声明。

连接器本地鉴权拒绝保存完整资源键和原始变量名列表，目录重读按当前语言解析文案及列表分隔符；环境变量名和 MCP 名称保持原文。OAuth 登录任务绑定操作代次，注销或关闭后迟到的授权回执不能重新写凭据、绑定或发布成功；第三方诊断保留原文。授权后连接等待结束还会核对发起时的声明身份；声明被替换或删除时不发布授权成功，保留已发生的凭据写入事实，不重放授权。

连接器手动绑定的探测连接必须完成所属关闭后才提交绑定状态。连接失败与关闭失败同时发生时保留两者；取消和重复取消等待同一次关闭，不重复连接或关闭。关闭未确认时不标记绑定成功、不发布成功事件。

连接器管理器关闭共用一次所属任务；并发关闭与重复取消都等待已接收的 OAuth 任务收尾。正常取消不作为清理故障，其他任务异常保留并在再次关闭时返回同一失败，不重放清理。开始关闭后不能再发起授权，需重启服务。注销从活动登记移出的任务仍归管理器所有；关闭等待其清理，不再次投递取消，正常结束后释放引用，失败保留到关闭时报告。

OAuth 元数据发现、设备 HTTP 请求和令牌刷新在线程中执行；取消等待仍等待原请求及响应上下文关闭，不重放请求。网络超时是底层请求限制，不保证总墙钟截止时间，慢响应可能延长取消等待。浏览器回调授权使用同一所属等待，并通过取消信号停止尚未收到回调的等待，关闭监听服务后才返回；若令牌交换已开始，仍等待原交换收尾。打开浏览器同样等待原调用，不因取消重复打开。真实回归只使用本机临时回调端口和受控网络，不代表线上账号验收。

## 插件包与钩子

插件设置页只保留顶部一个刷新按钮，同时重读已安装插件与市场目录；两个读取均结束后再解除忙碌状态，各自错误保持可见。刷新不注册市场、不安装插件、不拉取远端更新；市场注册或移除期间不启动页面刷新，避免重叠读取覆盖写入结果。

插件包生命周期由 `harness/plugins/packages.py` 和 `service.py` 管理，聚合技能、连接器、钩子及应用引用。来源编辑、版本比较、启停、连接和信任授权均经过宿主 API。智能体／团队通过独立声明管理。智能体／团队示例见 `examples/teams/README.md`。

### 来源、预览与安装

插件清单中的包内相对路径统一使用正斜杠，宿主扫描也转换为同一表示后执行边界校验。本机文件系统根路径仍按平台表示。Git 插件的 `file:` 来源先按标准 URL 路径规则转换到本机路径再判断绝对路径，支持 Windows 盘符以及经过编码的中文和空格；不允许借此越过包目录或跟随符号链接。

本机管理入口可编辑显式选择的已有插件目录，不要求其先注册为项目；清单存在仅用于识别插件来源。读取、保存及删除的相对文件路径仍经包内边界与符号链接检查，托管安装目录只读，版本比较不能省略。这不是针对本机管理进程的文件系统沙箱。

包快照增量枚举普通文件与子目录，各自上限为 4096 项；达到各自上限后的下一项即拒绝，不先遍历完整目录再报错。枚举句柄在成功或失败时均关闭，限额内按原全路径排序计算摘要，既有包的审核摘要保持稳定。文件总字节上限及链接、特殊文件拒绝规则继续生效；目录限额控制空目录数量，不保证任意文件系统的固定响应时间，也不把线程超时当作底层扫描已撤销。

插件页的目录、市场和对话审核共用预览流程，审阅快照同时包含来源路径与包摘要；开始新预览即撤下旧快照，安装只提交当前已审阅的快照。关闭页面或切换对话后不采纳旧读取结果。写请求结果未知时回查已安装状态，不自动重放写请求。智能体／技能目录安装已落盘但刷新失败时返回 503 及`installed: true`、已安装路径，保留刷新原异常，不把它当作未安装或自动再次复制。

安装目标根不能位于源目录内部，拒绝递归复制自身。独立目录安装先在安装根同级的本次专属临时目录复制并复验清单，发布前核对根目录身份，完整后才发布最终名称；失败只清理本次临时目录。安装和卸载共享同名操作系统旁路锁，竞争时拒绝，不删除锁文件；现有同名目录或链接不得覆盖。支持目录句柄的平台卸载时核对已打开根目录身份，并通过该句柄删除原目录内条目，根改名或换链不将删除重定向到新目标。此锁约束遵守该入口的调用，支持目录句柄的平台发布也绑定原安装根，复制中根被替换时拒绝，发布后身份变化报告未确认且不沿新路径撤销；不代表无目录句柄平台具有同等原生路径保证；崩溃遗留目录不做隐式扫描清理。

扩展页面将未知结果说明和原因分别保存为资源身份，呈现时解析当前语言；外部诊断正文保持原样。技能选择器在语言实际变化时重新获取目录说明，并保留显式技能选择；语言切换不触发安装、信任或源码保存。

连接器metadata中的`app_ids`只接受文本列表；插件目录读取与应用绑定使用同一校验，不能用字符串子串匹配推断应用可用。损坏身份明确拒绝，保留原声明，不自动转换或改写。

支持目录句柄的平台删除插件源码时，从已确认父目录句柄有界读取正文并核对版本、文件身份，再按原目录句柄删除；父路径换链不将删除重定向到外部文件。外部编辑器不遵守服务锁时，末次身份核对与删除之间仍不是原子CAS；无目录句柄平台的原生路径边界须另行验收。

### JSON 读取

插件 JSON 通过普通文件句柄读取，读取前后核对文件身份、大小及时间；支持NOFOLLOW的平台拒绝末级符号链接，读取期间变化明确拒绝，包内清单、应用、钩子和MCP声明均传递包根，支持目录句柄的平台逐级NOFOLLOW打开，避免校验后的父链接替换。打开包根前后核对设备与inode，根在stat至open之间被替换时拒绝；无目录句柄平台的原生路径授权仍需独立验收。插件JSON读取上限为 1 MiB，任意嵌套对象拒绝重复字段；不接受非有限数字、孤立代理码点或超过 64 层的容器。拒绝保留源文件，错误按调用语言解析，不通过后值覆盖或自动修复猜测声明。MCP 服务的 `startup_timeout_sec` 与 `tool_timeout_sec` 必须是可表示为有限浮点数的正数；超出浮点范围的整数也明确拒绝，不泄漏数值转换异常。

### 钩子声明与信任

项目钩子从最近的 `.harness/hooks.json` 或 Git 边界定位，用户钩子使用运行根的 `hooks.json`；插件钩子由包存储提供。配置与执行入口为 `harness/app/hooks.py`。项目和用户文件最多 64 KiB，完整声明最多 32 个处理器；未知事件、字段和无效匹配器明确拒绝。

钩子设置的配置与运行记录使用同组页签，左右方向键和 Home/End 同步切换内容与焦点。页签和内容区互相关联，切换保留未保存配置，不触发保存或信任操作；输入法组合输入和带修饰键的按键不切换页签。

信任记录保存在运行根 `hook-trust.json`，绑定项目／用户文件的原始字节 SHA-256，或插件钩子声明的规范化摘要。保存信任时核对预期指纹，执行前再次检查当前信任与声明身份；文件或声明变化后须重新确认信任。钩子执行成功不替代业务验收。

当前执行 `command` 与 `mcp_tool` 处理器；`prompt` 和 `agent` 类型可读取，但执行时明确记录为 `skipped`，不调用模型。`SessionEnd` 不接受 `mcp_tool`。普通处理器超时范围为 0.05–3600 秒；`Interrupt` 和 `SessionEnd` 命令的实际超时限制为 1–3 秒。超出浮点范围的整数按非法声明拒绝，不泄漏数值转换异常。

长上下文由 `hook_output.py` 处理，默认约 2500 词元；命令可用 `additionalContextLimit` 配置，0 表示不做该层上下文预览裁剪。超过阈值时将已捕获正文保存到运行根 `hook_outputs/<对话摘要>/`，返回带文件位置的首尾预览；保存失败则返回明确的未保存提示。命令捕获仍有独立大小上限，不能将预览文件视作无限制的进程输出。

Windows 的 `bash` 工具及命令钩子统一通过 `cmd.exe /d /s /c` 执行，关闭注册表 AutoRun，并固定剥离命令正文外层的包装引号；关闭所属执行器时也遵循相同规则。含空格的命令名必须在正文中显式加双引号。依赖 conda 等 AutoRun 初始化的命令需显式激活环境。正文仍遵循 cmd 的变量展开、管道和重定向规则，包装不会自动转义不可信参数。

插件停用及卸载在断开所属MCP连接时逐项尝试，首项清理失败不会遗落其余连接；所有原异常在收尾后保留，失败不会继续提交插件状态或通知成功。单独停用连接器同样传播真实关闭异常，只有未登记或已经正常关闭的连接才按正常停用处理；未知进程清理不得被吞成“已断开”。

## 当前文件工具

智能体启用文件工具时统一开放 `read`、`write`、`edit`、`glob`、`grep`。局部替换使用 `old_string/new_string`，全部替换显式设置 `replace_all`；删除使用空字符串。按行插入使用 `insert_line/new_string`，0 表示文件开头，保留文件原有尾换行。新建文件使用 write；已有文件先 read 建立观察，版本改变需重新读取。

生成 SVG、图片、HTML、文档等最终文件时，运行提示要求默认使用本对话工作目录内的相对路径，生成、验证和交付引用指向同一实际文件；临时目录仅用于可丢弃的中间数据。纯对话演示、不写文件或用户明确指定其它位置时遵循用户要求。该指引不能保证模型始终选对路径：`write` 仍保留经权限判定的项目外绝对路径写入能力，但成功回执会明确说明项目外位置与当前目录，提醒不要重放已成功写入，也不会自动搬运原件。变更卡片保留项目外文件的绝对路径，不再将其拼成项目内链接。

`present` 只声明已存在且解析后位于本对话工作目录内的最终文件；项目外绝对路径、解析后越界的相对路径及指向项目外的链接返回 `PRESENT_OUTSIDE_WORKSPACE`，整批声明失败且不发布交付事件。相对路径以调用目录解析，不能沿用工具注册时的其它项目目录。它不复制、移动或生成文件；用户指定的项目外输出须如实说明实际位置，当前项目面板不提供该文件的下载。历史项目外交付记录保留原路径，不提供错误的预览、缩略图或下载入口。

`read` 默认保留行号展示；精确编辑前可传 `line_numbers=false`，例如 `{"path":"src/Level.js","offset":478,"limit":10,"line_numbers":false}`。原文保留缩进、空行和范围末尾真实换行，仅将 CRLF／CR 统一成 LF；提示与截断说明位于源码块外。Unicode 分隔符仍是原文字符。读取最多加载文件前 512 KiB，未指定范围时最多选择 2000 行；单次正文展示上限为 16000 字符，展示截断与字节截断分别标记。字节截断时 `total_lines_known` 为 `false`，`total_lines` 只统计已读取前缀，不能当作完整文件行数。

编辑使用独立的 8 MiB 完整读取上限，超过上限拒绝修改，不以已读取的前缀覆盖原文件。按行插入的位置基于实际完整内容，替换与插入均保留原有行尾格式；返回片段仍受展示限制。

默认观察保护启用时，`FS_EDIT_NOT_FOUND` 撤销本对话对该文件的观察：先按返回的候选参数 `read` 当前原文，再构造小而唯一的替换块；改用另一个 `old_string` 或整体覆盖已有文件不能绕过重读。错误详情通过结果 `display.code/details` 保留，`suggested_read` 可直接用作读取参数。`new_text_present` 仅是位置线索，不能证明修改已完成。成功替换和插入均回传有界的当前原文，省略范围需重新读取。

直接装配文件工具时使用 `harness.tools.builtin.fs_tools.build_fs_tools(cwd, observation_policy=True)`。默认启用先读和版本保护；宿主确需关闭时显式传入 `False`，仅影响返回的这组工具定义，不影响已有 Harness 或其他工具注册表。不要使用进程全局开关控制实例策略，也不要把该开关暴露为模型工具参数。

## 可信宿主工具范围

扩展通过 `Harness.add_tool`、`Harness.add_skill` 和注册表钩子接入。当前智能体调度器调用 `ToolRegistry.execute_call`，提示词通过 assemble/render 装配。

`search_tools` 在当前可见目录中搜索已加载与延迟工具，匹配名称、命名空间和当前语言说明。查询中包含完整工具名时，只返回这些点名工具，附加描述词不再将它过滤为空，例如 `present file preview` 可以找到 `present`，`todo_write todo_read` 可以同时找到两个已加载工具；没有明确工具名时仍要求各查询词均匹配。完整名称查询保持精确选择。只为匹配的延迟工具记录加载事件，已加载工具沿用当前定义；空查询分页浏览全部可见目录。搜索不会开放范围外工具或执行目标操作。

可信 SDK 宿主可用 `registry.restricted(["tool_name"])` 为专用 `AgentLoop` 创建工具范围视图。视图同时收窄模型目录与实际执行，空集合表示全部拒绝；嵌套视图与上级范围取交集，不能重新开放上级禁止的工具。名称集合在创建时固定，后续调用方修改原列表不改变范围。原注册表后续增加的工具只有在该范围已明确列名时才可见，移除或替换工具继续走原执行前复核。

工具范围视图有意共享原注册表的定义、钩子、服务、结果观察及写入协调，不复制权限判断和资源所有权。它只约束使用此视图的调用方，不自动给其他对话、外部执行器或子智能体设置权限，也不是文件／网络沙箱。创建视图不修改原注册表；智能体声明中的工具授权字段仍然禁止，不能通过声明或模型参数扩大宿主权限。输入最多 4096 项，每个名称为最多 256 字节的非空 UTF-8 文本，字符串不能冒充名称集合。回归见 `tests/test_tool_scope.py`。

Superagent 的 HarnessExecutorAdapter 通过可信宿主 Profile 和协调 Worker 记录绑定工作对话角色，并在 `Harness` 的运行及 AgentLoop 装配入口重新核实原资源和工具范围；关闭也由原宿主等待所属创建操作。它不把任意对话头元数据视为授权，缺少匹配创建器时拒绝执行。当前受管理 Worker 的子智能体与 Ralph 入口须关闭；配置、恢复与边界统一见 [Superagent 模式](superagent.md#授权工作与独立质量门)。

## 成员原始证据

团队负责人可用 `member_evidence` 读取自己直接委派且已落定的成员运行，包括先前轮次。先只传真实 `agent_id` 列工具清单（省略 `call_id`），再传清单中的 `call_id`，按需配合 `query`、`offset`、`limit` 分段核对原文。返回运行与上下文身份、结果序号和原文摘要；它不返回成员私有思考，也不把历史上下文的其他运行混为本轮。清单分页使用 `next_after`。 读取确切调用时还返回 `call`：原调用序号、名称、副作用及参数的规范 JSON 预览。`input_available` 标记原事件是否保存参数；`input_json` 最多 4096 字符，`input_total_chars`、`input_truncated` 明确完整性，`input_sha256` 对规范化完整参数 JSON 的 UTF-8 字节计算摘要。截断或缺失参数不能据此补猜目标。记忆／项目板结果不能代替工作区文件或网址读取证据，须核对实际参数与结果。这项能力不允许同伴、无关对话或运行中取证，不重放原工具；工具成功仍不能代替主张支持或业务完成判断。

成员上下文复用时，若工具调用 ID 在不同运行或多次调用中重复，`member_evidence` 会拒绝无法唯一归属的清单或该调用原文，并明确报告歧义；不把历史结果替换成本轮证据。未发生歧义的具体调用仍可按其真实 ID 单独读取。

跨轮次读取仅按原直接父对话关系授权，并要求运行已落定；返回原始 `parent_run_id` 和 `run_scope`，历史工具结果不能称为本轮重新观察。此入口不恢复旧模型运行，不授予跨作用域等待、投递、中断或续接权限；同伴和其他父对话仍不能读取。

成员证据清单保留已开始但没有持久结果的调用：`result_available=false`、`result_seq=null`、`is_error=null`。这只证明记录过调用尝试，不证明成功、失败、未执行或可安全重试。各项含原开始序号 `call_seq` 及用于分页的 `evidence_seq`；有结果时后者取结果序号，无结果时取开始序号。分页始终使用返回的 `next_after`。缺失结果的原文读取仍明确报错，不合成工具结果。

严格团队验收要求报告引用本轮次唯一的工具结果 ID。同轮次出现多份结果共用 `call_id` 时，引用该 ID 返回 `ambiguous_tool_evidence` 并保持未验证，不能用后一次成功覆盖先前失败；不引用的歧义结果不会阻止核对其他唯一证据。此规则不改变后台命令必须完成且零退出码、终端等待不等于命令退出的要求，也不将工具成功当作业务完成。

## 项目看板

项目看板由 `harness/project/board.py` 管理，固定保存在工作区 `docs/harness-task-board.json`，与对话的执行清单分别维护。读取返回原始文件字节的 SHA-256 `revision`；写入须使用读取时的修订，保存前再次比较，不匹配返回 `board/stale-revision`。通过校验后写入同目录临时文件，刷新到磁盘，再替换目标。

`project_board_read` 与 `GET /api/v1/project-board` 返回 `file_exists`。文件缺失时返回当前格式空板和 `false`，只读路径不会创建文件；合法的已存在空板返回 `true`。已有零字节文件、损坏 JSON 或无效格式明确报错并保留原文件，不能当作新板初始化。`tasks: []` 和空内容摘要均不能单独证明文件存在；`file_exists` 仅描述该次读取时的状态。该字段属于读取投影，不写入持久化任务板。持久化文件顶层仅接受整数 `schema: 2` 和 `tasks`，拒绝浮点版本、额外顶层字段以及任意层级的重复 JSON 字段；格式不符时保留原件，不丢弃未知内容后重写。

任务板读取和写入均限制为 2,000,000 字节；超限读取只读取上限加一个字节后拒绝，保留原文件。工具与 HTTP 的错误正文按当前语言提供中英文消息，`code` 和结构化 `git.reason` 保持机器码。项目规划、执行及独立审阅提示词遵循当前语言，用户目标、任务合同及路径保持原文。独立审阅在启动时封存 `language`（`en` 或 `zh-CN`），验收按封存语言重建提示词；缺失或无效的语言标记明确拒绝，不迁移既有记录。

成员近期团队背景仅供连续性，不自动属于本次许可来源。`fork_turns=none` 控制通用轮次继承，不证明没有团队背景或复用的私有历史；不能单凭该参数宣称完全独立判断。需要独立复核时，应明确资料、历史意见的使用边界，并以实际上下文与运行证据核验。当前读取范围的这些提示不构成工具级路径沙箱。

请求与工具日志的工具节点带 `run_id` 与 `run_attribution_ambiguous`：运行归属仅取唯一的原始开始事件，完成事件不能补猜。调用 ID 在同上下文重复时归属为 `null` 并标歧义；缺少开始身份也返回 `null`。不能把归属未知的调用算作某次运行的已核验行为。

## 发行资源验证

当前源码没有预装系统技能；构建允许系统资源目录缺失，仍检查存在资源时的符号链接和输出路径约束。`scripts/verify_skill_distribution.py` 是可手动执行的 wheel 验证入口：

```sh
python scripts/verify_skill_distribution.py dist/harness-1.0.0-py3-none-any.whl
```

验证器对照当前源码校验资源字节，在临时目录隔离导入发行包，并实际创建技能、调用 `author_skill`。默认直接展开 wheel，不需要 `uv`；可选 `--install` 使用当前 Python 的 `pip` 离线安装到临时目录，因此该模式要求当前解释器已安装 `pip`。

CI 的 `unittest` 作业在运行后端回归前通过 `python -m pip wheel --no-deps --wheel-dir .run/wheel .` 构建发行包，再自动调用 `verify_skill_distribution.py` 检查构建产物。验证失败会使该作业失败，不能仅用源码导入测试替代发行资源验证。

## 可选本地语义记忆候选

Python 嵌入方可以显式提供本地候选服务；未配置缓存也未提供服务时不加载模型、不注册额外候选工具。先用 `python -m pip install ".[memory]"` 安装可选依赖，再按 [开发与测试](development.md) 的显式模型缓存准备命令核对已有缓存，将实际目录传给服务。安装依赖本身不下载模型或启用工具：

```python
from harness import Harness, HarnessConfig
from harness.app.memory_semantic import LocalMemoryCandidates

candidates = LocalMemoryCandidates('/absolute/model-cache')
app = Harness(HarnessConfig(), memory_candidates=candidates)
# 调用者注入的候选服务由调用者拥有，结束时 await candidates.aclose()。
```

宿主增加一个只读工具 `memory_candidates`，必填 `scope=session|project|user`，仍使用可信对话绑定。模型不能选择其他对话或数据库路径；返回顶层及候选scope，续页保持同一scope、查询及snapshot。工具在auto模式按需发现，不为三层重复注册。`query`最多500字符，`limit`为1至10。服务只加载现有的多语言MiniLM缓存，`local_files_only=True`，不会为用户记忆下载模型或调用远程嵌入。缓存缺失或依赖未安装时工具报错，原关键词recall及自动注入不受影响。没有设置页面开关。

命令行可用 `HARNESS_MEMORY_MODEL_CACHE` 指定已有缓存目录；桌面开发启动同样继承该环境变量。例如PowerShell设置 `$env:HARNESS_MEMORY_MODEL_CACHE='C:\models\harness-memory'` 后运行 `python -m harness.cli --ui`。移除该环境变量并重启即关闭候选入口。它不会自动安装依赖或准备缓存。SDK也可使用 `HarnessConfig(memory_model_cache=...)`；`HarnessConfig.from_env(memory_model_cache=None)` 显式覆盖环境配置以关闭。直接注入的 `memory_candidates` 优先于配置目录，记忆功能整体关闭时不装配候选服务。缓存路径是宿主启动配置，不经HTTP设置接口暴露或写入运行时设置文件。

自然语言查询最多扫描按固定/更新时间排序的前200条记忆，以主题前50字符和正文前256字符生成向量；模型还可能按128 token截断。结果明确返回 `scanned`、`omitted`、`indexed_content_prefix_chars`、`embedding_may_truncate`。不建立持久向量库、不跨调用缓存正文，每次读取当前存储快照。宿主服务保留最多512条内存向量，缓存键绑定作用域存储位置、编号、修订及完整主题/正文摘要，任一变化重新编码；只保留向量和摘要，不保存查询或正文。结果中的 `encoded_records`、`reused_records` 说明此次编码和复用数量。缓存命中仍重新核验来源，已删除记录不通过缓存复活；服务重新启动后缓存为空。单个ASCII符号、编号和独立ASCII路径使用完整现有精确检索，不让相似向量冒充缺失身份。其他查询融合关键词和余弦分数至少0.3的语义候选；这个阈值尚未通过生产校准。

返回 `meaning=semantic-candidates-only` 和 `requires_answer_support_check=true`；相似度不是事实、授权或回答依据。原记录身份、版本、来源和派生状态随候选返回，可调用同作用域check工具核对摘录，再读取当前源码。无答案问题仍可能返回相关主题记录，不能据此猜测答案。首次加载和批量推理有CPU/内存成本；内置服务的同步search与异步search_async共享参数校验；空查询、非法limit/扫描游标在读取数据库或创建进程前拒绝，异步入口只接受limit/offset/snapshot，不能覆盖宿主存储路径或身份。异步search_async和智能体工具在所属进程中执行自然语言检索，同服务串行；进程间使用一次性认证、长度不超过1MiB的私有JSON通道，不提供HTTP接口。取消当前请求或工具超时会终止并回收整个所属进程，丢弃该进程模型与向量缓存；取消排队者不会终止其他对话正在执行的请求。取消、崩溃或通道损坏后，后续独立请求重新启动服务，不自动重放失败请求。身份匹配且完整接收的业务错误（例如memory/scan-changed）直接返回，保留仍可用的热进程和缓存；非法错误结构仍按通道失败回收。日志持续排空，仅保留末尾8192字节诊断；启动退出或响应通道提前关闭时，先等待所属进程与日志收尾，再构造memory/semantic-worker错误，保留已经输出的原始诊断。没有stderr时，错误详情仍包含executable、pid、停止前已确认的exit_code及exit_code_hex；尚未确认的退出码保持null，不能用主动终止后的状态追认崩溃原因。配置自动装配的服务由Harness.close回收；直接注入的服务由调用方await aclose负责。单ASCII精确查询沿用只读线程路径，不启动模型进程；同步SDK search仍在调用线程执行，不能用异步取消终止它。首次启动增加进程和模型加载成本，关闭或取消后须重新预热。默认自动提示注入没有使用此服务。

每条候选的 `retrieval.match` 为 `keyword`、`semantic`、`both` 或 `exact`，分别表示关键词、语义、共同或精确查询命中。`keyword_rank`、`semantic_rank` 给出各排序来源的名次，未命中来源为null；混合查询的 `fusion_score` 是各命中名次的 `1/(60+名次)` 之和。精确查询没有向量或融合分数。`retrieval_policy` 说明RRF常数、200条工作集和128 token模型限制，并标记 `score_meaning=similarity-not-confidence`。正文和主题的实际编码前缀字符数分别随记录返回，可能存在进一步token截断；不能把一次候选查询当成全库或全文搜索。

自然语言候选支持显式分段扫描：首次省略 `offset`、`snapshot`，从固定/更新时间排序的前200条开始。返回的 `next_offset` 非null时，可将它作为 `offset`，并原样传入 `snapshot` 读取下一段；`total_records` 为当前记录总数，`remaining` 为当前段之后的记录数，`omitted` 包含本次未扫描的前段和后段。每段只返回本段最多limit条候选，融合名次和得分不代表全库排名。偏移允许0至999，后续段必须携带快照；精确符号查询始终全库匹配，不接受非零偏移。

快照摘要绑定当前作用域的存储位置及完整有序记录，不是授权凭据，也不持久锁定数据库。扫描期间若有保存、删除、导入或重排等变化，旧快照返回 `memory/scan-changed`，调用方须从offset=0重读，不能把旧段与新段当作同一完整扫描。当前来源文件状态仍在各段召回时重新检查；数据库快照不冻结文件系统或保证事实不变。

## 扩展文案的新增规则

自有工具 schema、拒绝消息、钩子示例和运行提示词使用显式资源键，实际调用时解析当前语言，不在构造工具时冻结文本。钩子事件、状态和示例已在 `web/src/lib/projectHooks.ts` 使用读取时解析的资源；已加入配置的命令属于用户内容，切换语言不重写它。外部供应商、用户智能体定义及工具结果保持原文。

只以当前已注册和分发的能力编写示例。示例也必须保留真实退出码、参数边界和资源清理；尚未完成审查的示例不能被当作生产推荐实现。

## 业务工具示例

`examples/business_agent.py` 按配置语言注册审查人格、团队规则和工具说明，消费当前扁平流事件；工具名和用户正文保持原文。`git_log` 使用统一宿主 Git 入口和字面路径，`run_tests` 使用当前解释器与参数数组执行 pytest，不拼接 Shell；保留真实退出码，只显示末尾30行。测试属于 execute 且要求审批；超时和取消复用所属进程清理，宿主在成功或异常后均关闭。收到错误事件时示例返回非零。它会执行目标项目代码，仅用于显式选择的项目，不在默认回归中调用在线模型。

内置连接器预设通过显式资源键解析描述、鉴权提示和配套技能模板；摘要在读取时使用当前语言，安装记录使用独立可变参数副本。技能目录位置不代表翻译所有权：系统发现目录、用户及项目技能的描述、使用说明和正文均保持文件原文，宿主包装说明另用资源键。预设配套技能在首次安装时写入当时语言的文件；已有文件及用户编辑不因重装或语言切换被覆盖。

模型工具`agent`的mount操作只以空`name`退场。非空名称（包括`off`、`none`）一律按当前目录中的原始智能体名解析，不使用翻译后的退出文案或别名控制身份；未找到名称返回错误并保持当前选择。search操作的空名称仍只表示目录查询，不退场。

用户斜杠命令保留不带任务正文的`/agent off`退场；`/agent off <任务>`按名调用`off`智能体，不退场。`exit`、`end`及翻译后的退出文字不再作为隐式控制别名。

智能体与技能查找失败时，可用名称列表只包含当前启用过滤器允许的条目，按读取语言解析错误提示；错误仍保留本次请求名称及停用原因。`list_all()`保留管理目录，`has()`只检查原始注册是否存在，不用于判断当前可调用性；停用不会删除条目。

## 环境 MCP 声明

`HARNESS_MCP_SERVERS` 接受当前 `McpServerConfig` 对象数组，或 `@path` 指向 UTF-8 JSON 数组文件。例如：

```json
[
  {"server_name": "local", "transport": "stdio", "command": "node", "args": ["server.mjs"], "env": {}},
  {"server_name": "remote", "transport": "streamable-http", "url": "https://example.invalid/mcp", "headers": {}}
]
```

未设置、空环境值或显式 `[]` 表示无环境声明。服务名须唯一并完整匹配 `[A-Za-z0-9_-]{1,32}`；参数和工具过滤为字符串数组，环境和请求头为字符串映射，不把单字符串或其他类型转换为当前声明。超时为正整数毫秒，启动超时可省略或为 null；重连延迟和尝试数为非负整数，零延迟在运行时最少等待1毫秒。

`@path` 会展开用户目录；相对路径以启动进程的当前工作目录为基准。此路径规则独立于执行器 JSON 中按配置文件目录解析的路径。

不接受 `mcpServers`/`servers` 旧封装。文件读取、编码、JSON、任一条目或重复服务名出错时拒绝整份环境配置，错误不包含凭据正文，原文件保持不变。此处的声明校验不启动服务；已通过校验的服务仍按各自 `fail_on_startup_error` 和重连设置处理连接失败。环境声明和 `connectors.json` 的管理入口保持独立。

MCP 工具发现按完整分页更新目录：每页必须有 tools 数组，声明必须包含有效名称和 object 类型的 inputSchema；可选 description 为字符串、annotations 为对象。缺失 schema 不补造为空对象，非法声明不跳过。nextCursor 按不透明字符串原样传递（包含空字符串），只有字段省略才表示结束；类型错误或重复游标明确失败，不能发布已收到的半份目录。合法空 tools 数组仍可清空原目录。原有重连预算及失败策略继续生效。

MCP 重连预算耗尽时关闭原连接后再释放句柄；清理失败返回原错误并保留所属连接，不能继续发布替换配置。监督器关闭先撤下工具目录；显式再次关闭可重试同一清理。批量关闭尝试全部服务，再返回单项原异常或聚合全部异常，不将部分失败报告为成功。

## 联网读取与语言服务

### 网页搜索与抓取

`web_search` 与 `web_fetch` 均注册为只读工具。直接 SDK 与模型调用共用参数校验：查询或 URL 必须是非空文本，数量与大小必须是正整数，`raw` 必须是布尔值，超时必须是有限正数；错误在读取提供方设置与联网之前拒绝，不将字符串、布尔值或空值转换成有效参数。

已启用的提供方按能力依次尝试：DeepSeek 支持搜索与抓取，Brave 支持搜索，最后使用默认实现。各次尝试分享总等待预算，并为后续来源保留时间；空结果或已知请求失败可以回退，取消直接传播，不触发下一来源。默认抓取响应最多读取 5 MiB，正文默认展示 40000 字符；HTML 转为文本，JSON 和 `raw=true` 保留解码正文。内容按响应声明的 charset 解码，未声明时严格使用 UTF-8。

默认 HTTP 读取与图片读取共用地址校验，只允许 HTTP/HTTPS；拒绝本地主机名，以及 DNS 结果中任一受限地址，IPv6 隧道同时检查嵌入的 IPv4。地址分类与重定向校验不构成完整的 DNS 重绑定防护。第三方搜索或抓取 API 的远端执行不由本地地址校验代替。

网页读取按实际调用语言发送Accept-Language：英文使用en，中文优先zh-CN/zh并保留英文后备。默认HTML搜索同样按调用语言选择地域与Bing端点，英文使用us-en及www.bing.com，中文使用cn-zh及cn.bing.com；查询原文仅作URL编码。健康冷静期按实际端点主机隔离，切换语言不会把另一主机的失败状态当作当前故障；第三方查询、网页及错误原文不翻译。确定性回归使用受控网络，不代表线上引擎可用性验收。

`web_fetch` 仅在确认超时后，对当前工具实例中同一对话、同一来源（协议与网络地址）冷却 60 秒；其他对话和来源不受影响，取消或其他错误不触发冷却。这与默认 HTML 搜索按端点主机记录的 900 秒引擎健康冷却相互独立。

### LSP 查询

`lsp` 注册五种操作：`definition`、`references`、`hover`、`symbols` 和 `workspace_symbol`。前三种使用从 1 开始的行号及从 0 开始的字符位置；`symbols` 不要求行号，`workspace_symbol` 使用非空查询文本且不要求文件路径。工作目录优先使用工具调用上下文，其次使用装配目录。服务器按语言候选顺序从 PATH 查找；缺少服务器返回 `available=false` 和当前调用语言的安装提示，不自动安装。

每次查询创建独立的 stdio 服务器，初始化工作区后发送文件原文。源文件在启动服务器前读取，最多 8 MiB，要求普通文件和有效 UTF-8，保留原换行；拒绝时不修改文件。定义结果最多展示 50 个位置，引用与符号最多展示 200 项；位置的可选源码预览只读取前 256 KiB，每行最多展示 200 字符，不能将缺少预览解释为目标不存在。

每个 JSON-RPC 请求默认等待 30 秒，发送、通知处理和反向请求共享该请求的固定截止时间，不因进度消息续期；初始化和业务查询分别计时。查询结束、失败或取消均沿所属关闭任务回收服务器，并发关闭共享任务，重复取消仍等待原收尾；清理失败明确报错，显式再次关闭可重试。

LSP文件URI通过平台路径生成，保留Unicode、保留字符、Windows盘符及UNC主机；反向转换只在Windows去除盘符前导斜线，localhost表示本机。TypeScript、JavaScript和TSX使用typescript-language-server的stdio入口，不直接把独立tsserver协议当LSP。路径与候选发现回归使用平台路径对象和受控发现，不等于各服务器及Windows实机验收。

LSP客户端发送整数请求号，响应ID必须为整数，不能用布尔值、浮点数或数字字符串匹配请求。合法通知及其他整数请求的迟到响应仍按原规则处理，不重发查询。

## 进程启动与取消

团队运行关闭使用同一个所属收尾任务；并发关闭及调用方重复取消等待原成员与流回收，不重复执行。成员取消与其他失败逐项收集，状态发布失败也保留；再次关闭返回原收尾失败，不把失败改成成功。

### Ralph 轮次循环

`ralph` 由 `enable_ralph` 控制注册，每轮创建全新的智能体对话，不继承父对话或上一轮上下文；目标和上一份有效结构化报告按实际调用语言构造提示，共享工作区保留各轮成果。报告必须包含 `status`、`summary`、`evidence`、`nextSteps` 和 `blocker`：继续时必须有下一步且无阻塞，完成时必须有证据、无下一步和阻塞，阻塞时必须明确原因。超过交接长度上限直接拒绝，不截断为合法报告。

终态为 `complete`、`blocked` 或 `budget-limited`；成员失败或报告非法则报错，错误说明可附最后一份有效报告。完成状态来自成员报告，业务验收仍需核对实际证据。默认每轮等待 900 秒，模型选择的 `maxRounds` 必须是部署上限内的正整数，超出时明确拒绝。

Ralph原始成员报告（含围栏和说明文字）最多解析65536字符，超限在JSON解析及对象扫描前拒绝；嵌入对象扫描累计最多262144次字符检查，耗尽时作为无效报告拒绝，过深JSON不向调用方泄漏RecursionError；合法报告正文仍遵循原16384字符限制。调用方取消等待时只中断当前所属成员一次，等待回收后再传播取消。

Ralph工具注册前要求部署轮次上限为正整数，每轮超时和计算后的总等待上限均为有限正数。非法类型、布尔值和非有限值用当前语言明确拒绝，不进入工具注册或成员派工；默认64轮不限制部署方显式配置其他合法正整数上限。

### 本机命令启动

工具链选择指引仅在已注册 `load_workspace_dependencies` 时提供，要求先核对当前工作区、PATH 工具和项目依赖入口；Harness 的服务解释器或模型桥接运行时不等于项目 Shell 环境。`bash` 说明按实际作业表区分能力：提供作业表时，常驻服务使用 `run_in_background=true`，命令自身不加 `&` 或 `nohup`，另发有界请求确认地址并检查原作业；没有作业表时，不宣称支持后台参数。内置浏览器只接受不带凭证的 HTTP/HTTPS 地址，本地 HTML 通过受管理服务访问，不能直接导航到 `file://`。地址可访问、命令零退出和服务仍运行均不证明页面功能验收通过。

前台 `run_code` 和 `bash` 在启动请求已接受后被取消，仍等待迟到的进程句柄并完成所属清理，再传播取消；启动尚未被接受时不继续创建进程。临时脚本保留到启动收尾结束；若启动清理未确认，返回 `ProcessCleanupError` 和 `temporary_script` 路径并保留原脚本，不自动重跑或删除。该诊断路径不是原命令执行成功的证据。

### 外部智能体（ACP）

外部智能体使用 ACP v1 的独立 stdio 进程，按 UTF-8 JSON 行交换消息；解析遵循严格 JSON 数字语法，拒绝 NaN、Infinity 和 -Infinity 等非标准数值。预设为 OpenCode（`opencode acp`）、Codex（`codex-acp`）和 Claude Code（`claude-agent-acp`）。`list_external_agents` 只检查 PATH 中的适配器和底层 CLI，`available` 表示适配器可找到，登录状态为 `not_checked`；检测不启动进程、不读取登录凭据、不自动安装。

`delegate_agent` 仅在宿主同时开启文件与命令能力时注册，属于需要审批的执行工具，只能选择预设智能体；只读权限拒绝委派。每次委派创建独立外部对话，外部权限选择前后再次检查当前准入条件，只认可本次请求中的选项。只有 `stopReason=end_turn` 且没有拒绝权限才标记完成；正文流保留末尾 32768 字符并报告丢弃数量，外部正文与工具标题保持原文。

独立命令行使用 `--list-external-agents` 检测，或 `--external-agent <预设|custom>` 执行任务；`custom` 必须提供 `--agent-command`，重复 `--agent-arg` 构造参数数组，不拼接 Shell。此入口不要求 Harness 模型或 API key，外部智能体的安装和登录由其自身管理。终端权限请求要求交互选择，非交互输入取消权限请求。

客户端单帧默认上限为 4 MiB，可配置为 1 KiB 至 64 MiB；请求超时默认 600 秒。同一外部对话不允许重叠 prompt，不同对话可并发。客户端只声明实际支持的空能力集，不代管外部文件或终端操作；未支持的反向请求返回方法不存在。prompt 超时或取消先请求停止，再关闭所属连接和进程，不能把停止请求已发送当作回收完成。

ACP初始化只接受整数版本1，布尔值、浮点数和字符串不能通过版本协商；返回的agentCapabilities若存在必须为对象，省略时使用空对象。非法回执在标记就绪之前拒绝并沿所属关闭路径回收原进程，不修改第三方对象中的合法字段。

ACP客户端区分调用方取消与进程创建任务自身取消。创建任务已取消时直接传播取消，不重复等待同一终态任务；调用方取消或关闭发生在句柄交付前时，仍接管迟到句柄并完成进程清理，之后才结束等待。`test_acp_startup_ownership.py`覆盖重复取消、并发关闭、原启动错误及隔离真实Python子进程回收；真实进程组分支属于POSIX验收。

## 执行服务配置

MCP管理服务回收主进程和隧道时逐项尝试，首项异常不跳过后项。成功回收后释放对应引用；失败句柄保留供显式重试，单个错误保持原异常，多项错误聚合。停止失败不能报告已停止，临时地址在停止开始时撤下；这不等于已验收所有启动线程和原生平台收尾路径。

MCP管理服务复用执行器的当前配置解析器，先校验既有配置的完整快照，再准备依赖和隧道。验证命令只能使用参数数组，不能把字符串或映射转换为参数。损坏JSON、编码、字段或项目配置保留原件并返回资源型错误；全部项目模式保留经过校验的项目字段，显式切换所需备份使用同一读取快照的原始字节，不重读后拼接。

执行器JSON配置中的home必须为非空路径文本，省略时使用当前默认目录；workspace_registry省略或显式null表示不跟随注册表，其他值必须是非空路径文本，不把0、false或空字符串当作省略。SDK直接构造支持字符串与PathLike，错误路径类型和NUL使用双语ConfigError；解析不会自动创建这些路径。

### MCP 技能运行根

执行器的 `home` 保存执行对话、作业及验证数据；可选 `skill_home` 指定宿主技能运行根，技能发现、插件启用与技能启停均从该根读取。省略或 `null` 时沿用 `home`，保留独立执行器的数据隔离。JSON 中显式路径必须为非空文本，相对路径以配置文件目录解析。

设置页启动的托管 MCP 自动将 `skill_home` 指向 Harness 宿主运行根，而将执行数据保存在独立的 `mcp-service/state`。宿主根为 `~/.harness` 时共享技能来自 `~/.agents/skills`；自定义运行根仍遵守本页技能目录规则。`harness_context`、`harness_skill_list` 和 `harness_skill_load` 使用同一发现链路；项目覆盖、插件限定名和显式停用继续生效。修改代码后需在任务结束边界停止并重新启动托管 MCP，运行中的进程不会热替换 Python 模块。
