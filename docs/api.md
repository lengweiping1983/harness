# 接口与协议

Harness 提供 HTTP API、WebSocket 实时通道和独立 MCP 执行服务。HTTP 与实时通道共用对话运行状态；独立 MCP 服务按本机登记的项目权限执行工具，不调用模型。

## Web API

HTTP API 使用 `/api/v1`。本机管理入口具有添加任意已有目录为项目、在所选绝对目录下创建文件夹及编辑本地插件源的能力；项目注册约束文件浏览的选择范围，不是隔离本机管理调用方的文件系统沙箱。浏览器请求携带 Origin 时，来源必须唯一且为纯 Origin 值，主机和端口必须匹配请求 Host，不再特例放行其他开发端口；重复 Origin 或含路径、查询、片段、用户信息的来源均拒绝。响应始终携带 `Vary: Origin`，拒绝来源时关闭连接且不返回 CORS 许可头；Vite 代理保留 Host 并禁用自身 CORS 预处理，API OPTIONS 与响应许可头由后端统一决定，仍可使用同源开发入口。无 Origin 的原生客户端继续可用，但浏览器明确声明跨站或同站跨来源的 Fetch Metadata 时拒绝；本机管理入口检查全部 `Sec-Fetch-Site` 头及逗号分隔值，比较前统一大小写并移除首尾空白；即使同时提供同源 Origin，也拒绝其中的跨站／同站跨来源声明。OPTIONS 使用同一策略，拒绝的来源不获得 CORS 许可头；这些检查不认证本机进程。本机管理信任边界也包括模型连接、账号登录与服务启停，不仅是目录读取；当前没有所有管理动作共用的幂等键或审计账本保证，共享访问仍由独立权限合同约束。路由注册位于 `harness/web/api`，当前完整方法、参数和响应见 [生成的 OpenAPI](openapi-v1.json)。运行 `python scripts/generate_protocol.py` 重建契约，使用 `--check` 做同步校验。

插件 API 的通用文件 I/O 失败仍返回 `400 plugin-package/io-error`，用户提示使用服务端与浏览器共用的双语资源；响应 `details.copy` 保留资源身份、`details.errno` 保留机器原因，不回显原始路径。原异常及完整堆栈进入服务端日志，原 HTTP 状态和失败语义不因文案处理变化。

未实现的 HTTP 方法访问 `/api/` 路径时仍经统一请求解析、来源检查和路由错误出口处理，返回 JSON 错误；已匹配路径的方法不支持时为 `405 method-not-allowed`，路径不存在时为 `404 route/not-found`。裸 `/api` 和 `/api/` 前缀的未知 GET／HEAD 路径同样返回 JSON 404，不回退到 SPA 首页。它们不使用 HTTP 服务基类的 HTML 501 错误页。HEAD 按 GET 路由读取相同资源并保留响应头，仅省略正文；不执行仅注册 POST 的处理器。开发入口将裸 `/api` 和 `/api/` 命名空间整体代理到后端，不依赖 Accept 选择 SPA。Vite 的 Node HTTP 解析器仍先于产品路由工作，解析器拒绝的未知方法 token 或畸形报文可能直接返回无产品 JSON 的 400。`/ws/` 的未知子路径在握手前返回 JSON 404，拒绝来源仍为 403，不回退到首页。

Superagent 本机工作台使用 `/api/v1/superagents` 的连接、分页查询、固定请求命令与媒体读取端点，复用同一实例协调账本。仅允许回环客户端与本机 Host，拒绝共享主体；运行归主宿主持有，取消 HTTP 等待不撤销已受理写入。完整行为、原请求查回和媒体安全边界见[工作台产品页](superagent.md#统一工作台)，字段以生成 OpenAPI 为准。

Superagent Worker 网关独立监听 `/executor/v1`，不注册在本机管理 API 下。其 HMAC 帧、nonce、原操作号和回执结构由 `superagent_remote_protocol.worker_openapi()` 生成到 [Worker OpenAPI](openapi-worker-v1.json)；设备身份、TLS、执行约束与租约规则见[远程执行产品页](superagent.md#隔离与远程-worker)。同一生成器同步维护两个 OpenAPI，设备端不运行另一套协调器。

创建对话只接受契约列出的字段，未知字段在持久化前拒绝。显式创建和 PATCH 改名的标题最多 512 个 Unicode 码点，超限返回 `400 session/invalid-field`；不截断或改写已有标题。PATCH 同样拒绝未知字段及非法的标题、模型、思考强度类型。创建对话时，`cwd`、`title` 和 `model` 若提供非空值，必须为字符串；非字符串且非 `null` 的值在创建任何持久对话前返回 `400 session/invalid-field`，`details.field` 标识具体字段。省略字段或空请求体仍允许按当前配置创建默认对话。显式非空 `cwd` 还会展开用户目录并严格解析，必须是已存在目录；不存在、不是目录或无法解析时，在创建持久记录前返回 `400 session/invalid-cwd`，`details.field` 为 `cwd`。省略 `cwd`、`null` 和空字符串使用默认工作目录，不自动创建目录；创建后目录被移除仍由实际操作报告错误。

网页新建对话未指定标题时，头信息登记 `metadata.auto_title=awaiting`。首次人工任务提交后先保存不超过 50 个 Unicode 码点的临时标题，再在独立后台请求中使用当前对话的模型连接生成不超过 50 个码点的任务标题；输入只取用户原文的前 12000 个码点，不发送对话历史、系统上下文或附件正文，不提供工具。命名请求的超时预算为 30 秒，取消后仍等待底层清理，失败、无凭据或非法输出保留临时标题，不阻塞执行轮次。纯附件消息使用原附件文件名，不额外请求模型。

命名输出上限为 256 token，能力读取与模型请求共用上述超时预算。所选模型的能力明确列出 `off`，且未声明强制推理或不支持推理时，命名请求选择关闭推理，并移除本次请求继承的 `extra_body.reasoning`／`reasoning_effort` 覆盖，沿现有提供商映射发送；能力未知、不支持关闭或自定义适配器未提供能力读取时保留模型默认。不改动对话模型、全局思考设置或连接配置，也不通过重试弥补超时。

命名请求通过支持 `on_request` 的适配器接入现有传输追踪，`purpose=title`，请求与工具日志显示“对话命名”。仅在实际传输开始后产生追踪记录，不因有逻辑请求号就补造已发送证据；不支持观察回调的自定义适配器保留原调用签名。会话头的 `auto_title_reason` 区分无凭据、纯附件、空输出、多行、超长、工具调用、超时、取消和请求异常，成功时为 null；`auto_title_request_id` 关联命名的逻辑请求，`auto_title_error_type` 仅记录异常类型。历史记录不补写诊断，失败不自动重放命名。

标题保存到对话头，侧栏、顶部标题及完成通知共用该值；目录修订通知使网页重新读取列表。后续消息、自动目标续跑和内部控制消息不改名。显式创建标题或手动改名优先，即使手动保存与临时标题相同，迟到的生成结果也不能覆盖。新流程仅作用于网页新建且未指定标题的对话；SDK 创建保持显式标题语义，已有对话不自动重命名或迁移。后台请求在服务关闭时取消并等待所属收尾，重启不自动重放未完成的命名。

### 对话创建与结果确认

`GET /api/v1/sessions/{session_id}/turns/{turn}/completion` 返回已提交轮次的回复定位、反馈、钩子汇总及 `delivery`。重复开始边界拒绝，缺少本轮结束不能借用后续轮次。`delivery` 聚合唯一轮次中的执行次数、失败、结果未知及成功 `present` 回执中的交付物引用；交付物最多返回 32 个，并保留完整去重数量。它不创建新的运行状态，也不推断业务验收。

交付物引用保留原 `present` 的 `workspace_root`、文件名称及说明（原回执提供时），不使用当前对话目录补齐历史声明。界面仅对原目录内可定位的文件提供预览入口；缺少目录或路径越界时保留原路径供核对。预览读取当前磁盘内容，不证明历史声明后的文件仍存在或未变更；超过返回上限时显示数量限制及原始执行入口。

`delivery.verification` 为 `unverified`、`passed`、`failed`、`stale` 或 `unknown`，`checks` 关联原检查、结果序号及声明输入路径。普通运行没有宿主登记回执时保持未验证。可选可信宿主接口 `VerificationCapture.begin/complete` 在前台 `bash/pwsh` 调用前捕获输入，完成时核对原调用参数及真实退出结果；模型工具参数不能登记通过。冻结会话及持久化重开共用原日志，不重放命令。重复、冲突或损坏回执明确拒绝。

读取 completion 时在工作线程核对文件指纹，每次至多 32 个检查和 32 个不同文件，单文件 8 MiB、总读取 16 MiB；超出读取预算或文件不可读保持结果未知，不标通过。只读查询拒绝越界、研究目录、特殊文件及链接入口，并核对句柄归属与读取前后身份；这不是文件系统事务或操作系统沙箱。摘要显示读取时快照，不持续监测后续改动；用户可重新检查，声明输入变化后原通过显示过期。未声明的环境和依赖不属于该回执的验证范围。

重新检查期间及读取失败后，当前验证状态分别显示检查中、结果未确认；先前检查只能在明确标识的历史证据中查看。只读重试不执行原工具，切换语言不重查，跨对话迟到回包不能归还到新结果。

权限问题可携带 `operation`，包含工具、工作目录及声明副作用。宿主新生成的审批还提供 `approval`：实际生效的策略、触发审批的有界原因列表，以及自动审阅转人工时的具体情形（要求确认、输入超限、预算不可用或无法取得有效决定）。这些字段来自实际权限判定，不从工具名称、译文或审阅原文在界面反推；工具声明不证明真实副作用或系统隔离。没有说明的既有问题保持原状，不补造原因。完整原问题仍可展开，用户与第三方正文保持原文。

审批依据纳入原问题的 `revision`，实时广播和待答查询保留相同内容；切换界面语言只重新呈现，不重新审批。问题本身不跨服务重启恢复；新人工决定的审计记录保留当次结构化依据，旧记录不改写。模型提问工具不能自行填入宿主专用的 `operation.approval`。外部 ACP 智能体的独立审批仍沿原协议处理，不推断其工具副作用。

临时授权按权限作用域、工具、参数及目录绑定，15 分钟后失效并可撤回；同一宿主委派链中的子智能体沿既有作用域复用，普通历史分叉保持独立。上述展示不改变准入、审批答案、授权指纹或权限边界。

`POST /api/v1/sessions` 接受可选 `X-Request-ID`。提供时，创建的首个持久对话头保存 `metadata.creation_request_id` 和 `creation_completed: false`；模型和智能体选择初始化完成后才将完成标志写为 `true`。缺少请求号的 SDK／HTTP 创建仍可执行，但不能依赖该身份回查。

浏览器点击“新对话”先进入草稿：已选项目时继承该项目，工作树对话继承来源项目；未选项目或项目目录已失效时打开项目选择器，不能隐式使用宿主启动目录。选择器可选择已添加项目、浏览目录或就地创建文件夹，保留未发送的文字与附件；取消不创建对话。选择器面板按视口限制高度，目录、检出设置和辅助说明放在可滚动正文中，确认操作独立放在底部。输入区随时可重新选择项目。开始前检查与创建请求共用所选项目目录；已有对话先使用其 `resolved_cwd`，其次使用 `cwd`。模型检查读取 `/api/v1/status.has_model_credentials`，与执行和自动标题共用配置密钥、已配置连接及已登录订阅账号的判定；未知、未配置和已配置分别表达，不探测远端连通性。`config.has_api_key` 仅表示主配置中的密钥，不代表其他连接不可用。关闭设置后重新读取状态；重读期间或失败时显示未知，不保留旧凭据结论，迟到的旧回包不能覆盖后一次关闭后的状态。项目选择器打开时重读项目目录，`exists=false` 的项目保留记录、显示“目录不存在”并禁选；侧栏保留其历史对话和项目移除入口。

`GET /api/v1/workspace-options?path=<绝对目录>` 在创建对话和登记项目之前只读探测目录，返回普通文件夹或 Git 仓库、当前分支、HEAD、本地分支、全部引用与未提交状态。损坏的 Git 元数据报错，不当作普通文件夹初始化。宿主关闭 Git／工作树功能时，`is_git` 与 `dirty` 为 `null`，明确表示未探测，仍允许选择本地目录。隐藏页面暂停项目只读检查并明确说明原因，返回后自动检查当前目录；可见页面等待检查期间提供重新检查入口，该操作只取消并重读目录，不创建对话或执行 Git 写入。添加项目页面与新对话输入区使用同一组选项：普通文件夹使用本地目录；Git 项目可选本地分支或启用 Worktree 后选择起始引用。没有首个提交时禁用 Worktree；读取失败先重读，选项和语言变化不执行 Git 写入。

新对话输入框下方将项目、分支、Worktree 和刷新入口排列在同一设置栏，宽度不足时换行。目录模式说明在 Worktree 开关悬停或聚焦时呈现，未提交修改、首次提交限制及读取错误仍在设置栏中可见。推荐任务位于设置栏下方，以按内容宽度排列的纵向列表显示；仅在空白、无附件、无待处理提交且未运行或排队时呈现。点击推荐只填入当前草稿并将光标放到末尾，不创建或发送对话；已有输入、附件和切换前的草稿不会被迟到的选择覆盖。低高度窗口隐藏推荐列表以优先保留输入空间。

`POST /api/v1/sessions` 的可选 `project` 包含已登记的 `workspace_id`、`mode=local|worktree`、可选 `ref` 及所见 `expected_head`／`expected_branch`。所选项目与显式 `cwd` 必须一致。默认首次发送才准备目录；打开目标等需要持久对话的显式操作也沿同一准入完成准备。准备前复核所见分支和提交，变化时拒绝旧选择。本地模式切换其他分支先在浏览器确认，后端只接受本地分支，存在未提交内容则拒绝切换，不执行暂存、stash 或提交。保留当前分支允许继续使用原目录。Worktree 模式从所选提交建立独立目录和新分支，不复制原目录的未提交内容；项目位于仓库子目录时，在新检出中使用相同子目录。工作树创建或后续对话创建未确认时返回 `session/workspace-uncertain`，保留可检查资源，不回退原目录、不自动重放。进程内服务锁串行准备与既有 Git 操作，不保证与外部 Git 进程之间的跨进程事务。

请求号是恢复查询的关联身份，不是这个创建接口的幂等去重保证。响应丢失后不要自动重发 POST：浏览器从真实本地草稿存储恢复原请求号，查询对话目录，要求恰好一个已完成的匹配条目，再读取详情核对头部身份及所需智能体挂载。没有、重复、不完整或错配结果都保持待确认；相同标题或工作目录不能用于确认。若旧请求已经确认完成，而用户已更换项目、检出或智能体，则保留旧记录，本次发送使用当前选择创建新的对话并只向新对话提交；回查期间再次切换则不创建或提交。空白且等待首次任务的持久对话显示“草稿对话”，不自动清理用户数据。

智能体挂载失败时，当前路由尝试删除本次创建的对话；使用项目检出选项时保留已准备目录并返回未确认错误，其他创建传播原错误。其他初始化或最终头部写入失败可能保留带原请求号的未完成对话。浏览器恢复不能把“已经存在记录”当作初始化成功，也不自动删除、补造完成标志或重放创建。此恢复合同与共享成员提交需求的 `Idempotency-Key` 去重合同不同。

### 请求大小与传输

HTTP 请求体在读取前按 `Content-Length` 校验，并拒绝任何 `Transfer-Encoding` 请求头（包括空值）：普通请求（包括运行提交）最多 4 MiB；仅 `POST /api/v1/attachments` 最多 129 MiB，容纳 96 MiB 原始附件的 base64 内容及 1 MiB JSON 元数据。超限返回 `413 request/body-too-large` 并关闭连接，不读取请求体。附件仍执行领域层的文件数、类型和原始字节限额。开发代理在收到请求头后立即转发，并对有长度的正文与后端协商 `Expect: 100-continue`，取得临时回执后才转发正文，避免早期拒绝与代理仍在上传的写入竞争。后端将 100 临时回执延后至长度校验完成，超限或畸形长度直接返回最终拒绝；正常请求读取原正文，下一次请求不继承继续上传标记。后端关闭响应显式携带 `Connection: close`。客户端若同步发送完整正文，可能在发送阶段收到连接关闭，仍须按其 HTTP 传输能力读取响应，不能据此重放写入。

OpenAPI 请求体覆盖实际读取 JSON 的管理接口；无参动作不要求请求体。协议源复用 `input_schemas.py` 的写入边界，并由 `request_contracts.py` 补充管理字段声明。OpenAPI 与提供商目录响应按 Accept-Encoding 协商 gzip，解压后的 JSON 及 no-store 策略保持一致。OpenAPI、提供商和工具目录不提供 ETag／304 条件请求契约；If-None-Match 不使这些目录返回 304。内容寻址附件和生产静态资源的条件请求沿各自已有规则处理。

主要路由分组包括对话及对话正文、运行与队列、引导与停止、目标与计划、权限、模型设置、项目及工作树、文件与终端、浏览器、技能与智能体、插件与连接器、记忆、钩子及自动化。新增公共字段必须同时更新协议源、调用方和测试。

目标控制`POST /api/v1/sessions/{id}/goal`的主状态保存与消息、广播、调度不是单个原子事务。主状态保存后任一步失败返回`503 goal/control-incomplete`，附原对话和动作身份；已保存目标保留。读回目标状态只更新界面，不确认整次控制成功，不重发原请求。取消不回滚已经提交的状态。

`WebContext.call` 负责 HTTP 线程到事件循环的调度。HTTP 与 WebSocket 的任务提交都进入 `RunController`。实时帧是持久业务事实的投影，不能作为唯一恢复来源。原生页面能力另受桌面来源检查和对话访问校验约束。

主轮次失败的 `turn/end` 保留字符串 `reason: error` 和原始 `error` 诊断，同时发送与运行错误相同的结构化 `code`、`message` 及存在时的 `details` 等错误字段。已提交结束还携带 `committed`、`source_seq` 和 `time`；提交失败明确为 `committed: false`，不补造持久位置。浏览器使用结构化错误生成卡片，同轮同码且完整诊断一致的轮次结束与运行错误合并为一张，保留持久位置与资源身份；不同轮次、错误码、正文或已提供详情不同的错误独立显示。模型错误的操作说明与技术详情分层展示，结构化详情默认收起，访客不显示私有诊断。历史读取只呈现原有持久证据，不改写记录或重放执行。

`GET /api/v1/sessions` 的摘要取当前消息表面最后一条非空人工任务或普通引导；自动目标续跑、计划模式控制及目标控制文案不覆盖任务摘要。运行中目标控制随后作为引导应用时，按已提交受理记录的请求标识和轮次识别，不能按正文猜测。已保存的对话标题（包括首次任务生成的自动标题）优先于摘要；后续任务可以更新摘要，但不因此改名。原控制消息和引导回执继续保留在对话中。

前端 HTTP 请求集中使用 `web/src/lib` 的共享传输。保留操作专用超时，结果未知的写请求只能先回查，不自动重放。访问检查见 `harness/web/server.py`、`api/access.py` 与共享访问实现。

`GET /api/v1/runtime` 的成员列表在历史分页之外保留执行或收尾尚未结束的句柄，且遵守请求的对话范围。成员运行已进入终态而交付未结束时，仍拒绝覆盖其工作区的环境文件复制，返回 `409 git/running`，不生成复制回执或写入目标文件；其他工作区可以继续操作，收尾全部结束后可显式重新提交。

运行总览仅接受可选查询字段 `session_id`；终端输出 `/api/v1/runtime/terminals/{terminal_id}/output` 还接受 `offset`、`count` 和 `tail`。每个字段只接受单值，未知字段、重复字段、空白对话标识及无效窗口返回 `400 request/invalid-query`。HTTP 层保留显式空值供业务校验，只有省略 `session_id` 才进入全局总览或唯一终端拥有者选择；多个终端拥有者时省略对话仍返回 `missing-session`。偏移为 0 至 JavaScript 安全整数上限，行数为 1–2000，默认分别为 0 和 500；`tail` 只接受 `true`／`false`，默认 `false`。参数校验与 OpenAPI 共用 `harness/web/query.py` 的声明。

轮次关联运行的查询只接受日志中明确保存的运行身份；缺失关联返回 `run/turn-not-found`，重复轮次开始返回 `run/ambiguous-turn`。运行恢复报告在无法确定唯一范围时返回 `scope_known: false` 和 `verification_required: true`，不会扫描旧结果猜测轮次。文件审阅与恢复共用轮次事件范围，排除结束之后及显式属于其他轮次或运行的证据。

“查看执行”的轮次查询及按运行标识读取共用生成的 `RunRecord` 响应校验，并核对对话与明确的运行身份。预览及展开详情在面板或页面隐藏时取消在途读取，显示后读取当前选择；目标替换、切换对话及关闭后的迟到结果不替换新记录。错误保留产品资源身份，切换语言只重新呈现，外部诊断保持原文。“重试读取执行”仅执行 GET，不提交继续运行，也不重放未知副作用；恢复观察不会再次抢占编辑器焦点。

恢复报告的 `tools` 每项对应一次执行，`call_id` 可跨步骤复用；展示条目使用 `source_seq` 与 `call_id` 的组合身份。`total_tools` 和 `uncertain_operations` 针对完整范围计算，分页不减少待核实数量。只有宿主的明确未执行证据可产生 `not_executed`，缺少真正开始记录的孤立结果保持未知。

恢复页面在检查和继续两种方式下均先展示整个运行的待核实事项及已载入工具数量；范围未知时明确提示无法确定完整范围，不将零条记录解释为没有待核实操作。待核实数量包括结果未知或报告错误的非只读操作，工具报告成功不代表任务完成或验证通过。同一版本的分页必须保留完整范围、待核实总数和核实要求；分页读取失败或证据变化时保留已载入内容与编辑草稿，撤销核实确认。重新读取后仍需核实的事项不自动恢复确认。

冻结团队路由 `TeamRoute` 必须同时提供 `team`、`revision`、`recipients`、`selection_revision` 和 `recipient_identities`，不接受额外字段。浏览器的生成响应契约也执行此限制，字段查询只接受 schema 自身声明；`constructor` 等原型同名字段不能绕过限制。执行前重新核对选择版本及成员身份；路由结构必须完整。

`SteeringReceipt` 必须包含 `team_delivered` 和可空的 `delivery_seq`，以及当前接受时间、应用序号、原因和文本截断标记。送达证据必须绑定接受序号。引导回执的 `text` 是用户原始正文，摘要截断也按原文计算；内部模型正文和附件内容独立保留，不要求浏览器解析中英文附件标记。共享 HTTP 传输校验运行引导接口与直接 `/steer`、`/steering` 接口，缺少必需字段视为无效响应。

Python SDK 的 `Harness.steer(..., before_accept=check)` 允许可信宿主在引导锁内、首次接受事件提交前再次核验授权和原运行。检查必须同步返回 `None`，异常阻止本次接受，异步检查或其他返回值明确拒绝；既有稳定回执直接回查，不再次调用检查。这不是 HTTP 参数，也不能由模型正文提供；Superagent 节点指令借此复核来源与确切轮次，完整边界见 [节点执行指令](superagent.md#持续协作指令与控制)。

队列列表、对话范围运行读取和编辑响应中的 `text` 为用户原文，附件由 `attachment_refs` 单独提供。编辑仅提交 `text` 和 `expected_version`，后端保留原有附件并重新装配模型提示；版本仍核对完整运行快照。存在附件引用时允许空正文，无附件的空正文由业务层拒绝；版本冲突中的 `current.text` 也使用原文。丢失保存或撤回响应时只回查原运行，不重发写请求。

### 项目目录读取与恢复

`GET /api/v1/workspaces` 的成功响应必须包含 `workspaces` 数组与文本 `default`；每条项目记录包含文本 `id`、`path`、`name`、`color`，可附带时间戳和布尔 `exists`。浏览器从公共协议生成的契约校验这些字段，空对象、非法数组或错误字段类型不作为空项目列表接受。

启动时的项目、对话、模型、状态、工具、技能、文件目录和界面设置，以及显式项目刷新，对网络连接失败、408 和 500／502／503／504 使用有界 GET 重试：最多读取五次，退避为 250、750、1500、3000 毫秒，全部尝试共用 20 秒截止时间。取消、协议损坏、其他明确拒绝不自动重试；普通写入结果回查仍沿原来的单次查询，写请求不自动重发。启动项目读取最终失败时保留此前确认的项目和错误身份，不把失败改成已确认的空目录。

没有已确认项目可供分组时，读取中或读取失败的对话暂按全部对话展示，不能误标成“未匹配项目”；原有分组偏好保持。服务端 `ready`、网络恢复、页面重新可见或重新聚焦后，失败的项目目录会自动补读；隐藏页面、启动中、已有读取或没有失败状态时不额外读取。恢复会清除错误并恢复分组，当前对话缺失的项目选择按已确认目录补齐，读取期间用户另选的项目不会被覆盖。达到重试边界后仍保留手动重读入口；真正成功返回的空数组继续表示没有登记项目。

### 对话删除与项目移除的浏览器确认

`DELETE /api/v1/sessions/{id}` 与 `DELETE /api/v1/workspaces/{id}` 的成功回执包含匹配请求ID的 `deleted`。浏览器只对匹配回执直接确认；成功结构身份失配、损坏回执或未知传输结果会只读查询一次对应目录。目标仍存在或读取失败时保留本地状态及对话草稿，显示结果未确认，不自动重发DELETE。读回确认原目标已不存在后才按已完成操作清理本地状态。明确4xx拒绝（408除外）仍显示拒绝原因，不启动缺席确认。

`GET /api/v1/sessions` 接受可选单值整数 `limit`，范围为 1–1000。省略时返回完整可见列表；显式合法值在权限过滤及活动时间降序排序后截取。`0`、负数、非整数、超上限、空值、重复参数及未知查询字段返回 `400 request/invalid-query`，不再静默忽略。参数与 OpenAPI 共用 `harness/web/query.py` 声明。此限制控制响应条数，列表仍沿现有路径派生摘要及排序，不代表减少磁盘扫描。

`GET /api/v1/sessions/activity` 返回 `running`、`catalog_revision`、`server_id`、`completion_cursor`、`completions_lost` 和 `completions`。首次省略查询参数建立基线，不补发已有完成通知；之后以该响应的 `server_id`（服务与权限范围身份）和非负安全整数 `after=completion_cursor` 续读。完成条目包含 `seq`、`session_id`、`run_id` 和 `status`，只来自已经启动运行的 `completed`／`failed`／`interrupted` 终态；上下文整理、排队取消与重复终态不新增通知。独立有界记录覆盖两次活动读取之间已经开始并结束的短任务，不依赖正文事件重放。

共享读取对运行列表、完成条目及游标序号一起按授权对话集合投影。服务重启、授权集合变化或游标超过当前水位时重新建立基线；同一服务与权限范围的补发缺口以 `completions_lost=true` 明确报告，客户端提示检查对话，不补造丢失通知。删除对话释放其通知记录。查询与生成响应契约共用当前协议定义，未知、重复或非法查询参数返回 `400 request/invalid-query`。

## 实时通道与续传

轮次开始事件的`run_id`同时用于实时与历史恢复的运行归属。运行终态`run/state.id`及由它派生的`done.run_id`若明确属于另一运行，不结算当前轮次草稿或关闭当前运行状态；服务端Hub同样保留当前临时生成投影。旧事件仍进入重放序列，不通过丢弃游标制造缺口。缺少明确运行身份的事件不补造身份。

对话 WebSocket `/ws?session=...&since=N` 发送 `ready` 快照和按 `seq` 排序的事件；前端只把 JSON 对象帧交给业务事件层，非法 JSON 与非对象帧丢弃；`pong` 仅由传输层消费，不作为业务事件分发。`resume` 使用同一游标，缓冲区无法覆盖缺口时返回需要重置的快照。前端检测事件序号缺口后请求 `force_snapshot`，不会继续应用残缺流。`GET /api/v1/sessions/{session_id}/live-events?since=N` 是按相同序号增量读取的 HTTP 通道，返回 `since`、`last_seq` 和事件列表；共享访问可能过滤不可见事件，因此列表数量不等于序号差值。

首次连接、`resume` 和增量 HTTP 的 `since` 必须为 0 至 JavaScript 安全整数上限的整数，省略为 0。空值、非法格式、负数和越界值返回 `request/invalid-query`，不回退为全量补发。HTTP 和 WebSocket URL 的重复 `since` 也会被拒绝。HTTP 在查询会话存在性之前校验游标，拒绝为 400；WebSocket 首次请求在升级前拒绝；已经连接的 `resume` 返回错误帧，保留连接。跨来源的 WebSocket 请求仍为 403，升级前使用 JSON 错误响应。

终端 `/stream` 使用终端输出的 `cursor` 和 `wait_ms` 长轮询，与对话事件序号互不通用；重连沿用该终端的输出游标，不用对话 `seq` 替代。

前端连接使用 20 秒应用层 ping，服务端响应 pong；发出 ping 后 10 秒仍未收到 pong 时关闭该连接并重新进入退避重连，旧连接的迟到回调不影响新连接。连接关闭后从 0.5 秒开始指数退避、最大基础间隔 15 秒并加抖动，连续最多重试 40 次；连接打开后重置次数。停止自动重连时横幅提供手动重新连接入口，此操作只重建连接，不重放任务写入。

Web事件中枢关闭时同时释放房间、草稿、生成遥测、成员预览及关闭运行标记。同一连接替换订阅时取消旧发送协程；旧协程收尾只移除自己仍拥有的订阅，不能删除替换后的订阅。重放缓冲及批量发送仍保持顺序，慢客户端断开不清除房间重放。

## 无模型 MCP 服务

ChatGPT 普通聊天的流水线、生图交接、请求回查和可选浏览器扩展接续见 [ChatGPT 网页开发与自动接续](chatgpt-development.md)。工具目录以实际服务发现结果为准；扩展回环桥独立于公网 MCP 入口。

入口为 `harness-mcp`，配置由 `harness/execution/config.py` 校验，不接受模型设置。项目必须已存在；权限默认为只读。示例中的路径需改为本机实际路径：

```json
{
  "home": "/path/to/private-executor",
  "projects": {
    "app": {
      "root": "/path/to/project",
      "principals": ["local"],
      "writable": false,
      "commands": false,
      "commits": false
    }
  }
}
```

配置中的相对路径以配置文件所在目录为基准；省略 `home` 时使用该目录下的 `.harness-executor`。项目的 `root` 必须是已存在目录，`writable`、`commands` 和 `commits` 只接受布尔值；启用 `commits` 同时要求 `writable`。未知配置字段和模型设置会被拒绝。

本机受信任 stdio 客户端：

```sh
harness-mcp serve --config /path/to/executor.json --transport stdio
```

本机 HTTP 服务：

```sh
harness-mcp serve --config /path/to/executor.json --transport http --port 8876
```

启用公网 OAuth 使用 `--public-url https://your-host.example`；HTTP 进程仍监听本机，由用户配置 HTTPS 入口。本机授权管理使用相同配置和 URL：

```sh
harness-mcp init-login --config /path/to/executor.json --public-url https://your-host.example
harness-mcp approvals --config /path/to/executor.json --public-url https://your-host.example
harness-mcp approve --config /path/to/executor.json --public-url https://your-host.example --ticket TICKET
```

执行器批量文件修改在写入前检查版本并保存原始备份。后续步骤失败时，仅回滚仍匹配本次写入版本的文件；并发修改或回滚失败会保留当前文件和备份，报告 `execution/rollback-incomplete`，不会覆盖新内容或自动重放整批修改。版本核对与文件替换不是跨进程原子事务。

stdio 不接受 `--public-url`。服务按本机登记的 principal 和项目权限执行。工具目录见 `harness/execution/catalog.py`，执行及授权见 `execution/runtime.py`、`policy.py` 和 `mcp_server/auth.py`。初始化及 `harness_context` 指引使用公开工具全名：长任务查询为 `harness_job_poll`，验证与验收分别为 `harness_verify`、`harness_finalize`，不能用内部方法名代替。

执行器在同一项目资源域内允许经过核对的内置只读工具并发，写入、命令提交及未核准的扩展工具独占执行。等待中的独占调用阻止新读取插队；`harness_job_poll` 保留独立查询路径。动态项目注册表仍共用资源域。幂等提交、事件持久化和最终验收保持原有约束；客户端取消不会撤销已接受调用，关闭等待所有已接受工作结束。Git 查询禁用可选索引刷新。该调度不隔离外部进程或已启动的后台作业，文件版本检查和项目忙碌检查继续生效；同步文件读取与搜索仍在事件循环上执行，不能据此声称磁盘读取并行或普遍提速。

工具副作用采用 `unknown`、`read`、`workspace_write`、`external_write`、`execute`。远程工具未声明时保持未知，不能按工具名称推断只读。

### 工作区能力发现

`load_workspace_dependencies` 通过 MCP 的工具目录公开，stdio 与 HTTP 共用同一执行入口；OAuth 调用要求 `project.read`。它不需要模型凭据，也不要求项目具有写入或命令权限。可在创建对话前调用：

```json
{"project_id": "app", "include_packages": true}
```

已有对话时可改传 `session_id`，不能同时传入两个选择参数。两者均省略时，仅自动选择当前身份唯一可访问的项目；无可访问项目或存在多个项目时返回 `execution/workspace-selection-required`，先用 `harness_context` 查看可访问目录。不能用工具参数指定任意 `cwd`，也不沿用上一次调用选择。对话选择继续核对所属身份、项目授权及原项目根。

结果沿执行器统一回执放在 `data` 中，MCP 同时返回 JSON 正文及等价的 `structuredContent`：

| 字段 | 含义 |
|---|---|
| `cwd` / `process_cwd` | 所选项目根／Harness 服务进程目录，二者分别报告，不修改进程工作目录 |
| `python` | 服务解释器的路径、版本、实现、搜索路径；`source` 为 `harness_process` |
| `node` / `executables` | 服务 PATH 中 Node 侧运行时的路径与版本／其他工具链、文档和媒体工具的已发现可执行文件路径 |
| `workspace` | 项目根中已存在的常见依赖目录和依赖清单路径；链接以 `linked` 标记，不跟随链接或读取清单正文 |
| `project` | 当前项目身份、名称、根、写入／命令／提交权限、验证项名称及已启用技能目录，与 `harness_context` 使用同一能力来源 |
| `tools` / `execution_environment` | 当前注册的工具名／宿主执行环境声明；目录可见不代表获准执行所有操作 |
| `runtime_scope` | 按服务语言说明探测来源和使用边界 |

`include_packages` 只接受布尔值，默认 `true`，枚举服务解释器安装的 Python 包，稳定排序并有数量上限；`package_count` 表示总数，`packages_truncated` 表示清单是否截断。传入 `false` 不枚举包。项目中的 `.venv`、`venv`、`node_modules` 和依赖清单仅报告存在性，不自动激活环境、安装依赖、执行项目脚本，也不将服务包清单冒称项目环境的包清单。目录或可执行文件存在不能证明依赖可用，宿主执行环境声明不代替平台验收。

运行时及包枚举复用短期缓存，每次返回隔离快照；PATH 或 Python 搜索路径变化后使用对应的新探测结果。工作区入口每次重新检查，不共享另一项目的目录结果。版本命令在所属临时目录中运行，并禁用 Corepack 下载和自动固定项目版本；原进程树回收后才释放该目录。探测在线程中执行；客户端中断不撤销已接受的探测，服务关闭仍等待原线程完成，不重新探测。读取失败返回明确错误，不把部分清单当作完整成功。

### 服务语言

独立 MCP 执行器的 `language` 配置决定服务初始化及工具请求使用的语言，支持 auto、zh-CN、en；auto 按本机系统地区解析。该设置由本机配置提供，不能用模型工具参数改变。修改配置后需重新创建服务。授权、执行文案及托管入口使用同一配置语言；用户输入和第三方诊断保持原文。

独立执行器的 HTTP 授权路由按服务 `language` 配置绑定语言，包含 OAuth 拒绝、密码表单、无效票据和等待批准页面；不根据浏览器请求改变服务语言。页面原始回调地址、未知权限名与外部错误保留原文并 HTML 转义。

从设置页面启动托管 MCP 服务时，将本次启动上下文的有效语言写入独立执行器配置；后台线程和子进程沿用该次语言快照。运行期间切换界面语言不会修改已启动服务，停止后重新启动才使用新的语言。托管入口在初始化登录、构建 HTTP 服务及运行服务期间绑定配置语言；缺失已初始化的密码文件时明确失败，不自动重建凭据。

### 持久记录与图片交付

执行器的幂等调用按 principal、作用域、工具名和请求号隔离，并核对完整参数的指纹；同一身份的不同参数返回 `execution/request-conflict`。重启后尚为 `running` 的调用改为 `outcome_unknown`，后续请求返回 `execution/outcome-unknown`，不自动重放。

执行器读取对话记录时校验当前正文结构，拒绝正文覆盖数据库中的对话、项目和版本身份；证据正文也不能覆盖证据ID、种类或对话身份。损坏记录保留原件并返回`execution/store-invalid`，不自动修复或迁移。

图片请求读取核对数据库 ID、`pending`／`delivery_unconfirmed`／`delivered` 状态及当前正文结构，交付前执行同一校验。只有 `pending` 接受交付；`delivery_unconfirmed` 返回 `execution/image-delivery-unconfirmed`，已交付返回 `execution/image-already-delivered`，均不重新下载或写入。损坏记录返回 `execution/store-invalid`，保留原件；提示词保持用户原文。交付意图及回执的持久顺序见 [存储与恢复](storage.md#恢复和副作用)。

执行器重读已完成幂等回执时拒绝非法JSON、非对象及身份或终态错配。JSON null不代表新请求；损坏回执返回`execution/store-invalid`并保留原记录，不追加工具事件或重新执行。合法成功与拒绝回执按原样返回。

执行器持久化的验证命令在读取时复用登记协议，校验验证标识及非空字符串参数数组。非法JSON、字符串/映射伪装的参数数组或越界字段返回`execution/store-invalid`，保留原记录且不启动作业。

独立执行器的 OAuth 刷新轮换在同一事务内核对旧 refresh token 的一次性消费结果，再撤销原凭据家族并签发新凭据。跨数据库连接同时使用同一旧凭据时只能一个成功；失败请求不能撤销已签发的新凭据，签发持久化失败则整体回滚。数据库事务原样传播 SDK 的 TokenError，已消费授权码或刷新凭据继续返回 invalid_grant。

## 对话邀请与成员

主持人从本机完整入口使用对话标题旁常驻的“邀请协作”打开管理面板。尚未创建对话时，点击后沿现有项目与检出确认流程创建对话，再打开属于该对话的面板；仅呈现入口不创建记录，创建失败、原实例关闭或切换后不打开旧面板。首次启用后创建有期限的单人邀请。启用接口仅对完整宿主入口开放；共享入口不能匿名认领主持人身份。完整宿主入口仍具有本机管理权限，不能暴露到公网。

| 方法及路径（均以 `/api/v1` 开头） | 用途 |
|---|---|
| `POST /sessions/{id}/collaboration/enable` | 本机启用访问合同 |
| `GET /sessions/{id}/collaboration` | 成员、显示名和管理者可见的邀请清单 |
| `POST /sessions/{id}/invitations` | 创建邀请；原始邀请秘密只返回一次 |
| `POST /sessions/{id}/invitations/{invite}/approve` | 按 `expected_revision` 批准待加入成员 |
| `POST /sessions/{id}/invitations/{invite}/revoke` | 撤销尚未加入的邀请 |
| `POST /sessions/{id}/members/{subject}` | 按版本修改角色或移除成员 |
| `POST /access/invitations/claim` | 邀请秘密、显示名和随机领取秘密提交申请 |
| `POST /access/invitations/status` | 用两个秘密回查申请；批准后返回稳定主体 |
| `POST /access/invitations/enter` | 批准后兑换独立浏览器 Cookie |

共享协作错误正文按当前语言提供中英文消息；`code` 与原有 HTTP 状态保持稳定。 服务与浏览器使用同一组公开错误资源；访客按本地语言呈现错误，切换语言会更新已保存的错误反馈，不修改宿主配置或模型提示词的语言。未知第三方错误正文在完整宿主界面保持原文；共享实时错误只根据公开错误码生成消息，不转发宿主异常正文或私有详情。邀请摘要及申请摘要只接受当前格式的十六进制字符串，损坏记录明确拒绝并保留原日志。

角色映射：观察者为 `read`，协作者为 `read/contribute`，管理员为 `read/contribute/control/manage`。共享页面根据当前能力显示任务输入；协作者可提交普通文本需求，原任务队列负责执行。宿主斜杠命令、插件安装、队列控制和终端不因此开放；管理员审批仅使用下述对话范围接口。完整字段和响应以生成协议为准。

公开领取、回查和兑换必须来自配置的精确浏览器 Origin、Host，使用 JSON 请求，不能附带 Authorization。HTTPS 来源签发 Secure、HttpOnly、SameSite=Strict Cookie；显式配置的回环及私有 IP 可用于局域网 HTTP 测试，此时 Cookie 保留 HttpOnly 和 SameSite=Strict，传输不加密。邀请及领取秘密只保存 SHA-256 摘要，不返回到成员清单或公共历史；显示名不参与身份验证。

批准用一条访问事件同时记录授权和邀请消费；重复批准不再次添加成员。成员修改使用完整授权版本比较。普通角色修改保留当前浏览器登录，移除再添加会产生新成员周期，旧 Cookie 和原邀请领取证明不恢复。写请求结果未知时读取当前状态，不自动重放。兑换结果未知时同时核对已批准主体和实际 Cookie 主体。

嵌入时，共享入口由宿主通过 `serve(..., shared_authenticator=app.session_credentials.authenticate, shared_browser_origin='https://host.example')` 显式开启，复用同一 Harness 实例；不要将默认完整入口作为隧道目标。未启动共享监听的实例创建邀请返回 `409 invitation/sharing-not-running`，避免生成指向其他实例的无效链接。共享地址由当前实例声明，界面只读，不允许手工替换到另一个实例。CLI 的 `--ui --share http://私有IPv4:端口` 同时提供本机管理与局域网共享监听，并向邀请面板提供已绑定地址；完整管理入口必须保持回环监听。没有公网隧道或自动 HTTPS 启动器。

### 真人任务提交与回执

共享浏览器使用现有 `POST /api/v1/sessions/{id}/runs`，只接受 `{"text":"需求正文"}`。必须提供 16–128 位字母、数字、下划线或连字符组成的 `Idempotency-Key`；服务端按已验证真人主体隔离键空间，正文不能声明作者、路由或权限。普通发送排队；不将其解释成引导或停止。重复键不同正文返回冲突；同键同内容返回原运行。不同真人使用相同键分别归属各自任务。

`GET /api/v1/sessions/{id}/submissions/{key}` 查询当前真人原请求，不创建运行；未知写结果及页面恢复只自动调用此接口。回执未找到时，用户可显式重试同一请求；继续使用原请求键与原正文，不创建新的幂等键。浏览器待确认请求与草稿复用原草稿存储，并按对话和真人主体隔离。`GET /api/v1/sessions/{id}/queue` 提供公共待执行列表，裁掉附件落盘路径及内部调度元数据。

运行记录保存服务端确定的 `requester`（`subject`、`display_name`）及内部成员加入周期。实际启动前重新核验 `contribute` 和加入周期；降权或移除再添加均不能让旧请求启动。已运行任务不因角色变化自动重放；其他控制仍通过原宿主流程。公共用户消息记录 `run_id`、`request_id` 和作者，持久消息序号由原日志提供，执行时只追加一次。

HTTP 历史、导出及 WS 初始快照、实时帧、重放使用服务端公开投影，排除推理、内部 note、系统提示词、工具参数和宿主路径。非公开实时事件保留无正文的 `shared/omitted` 序号标记，保持原推流序号连续；不另造持久事件序号。消息搜索继续只查询用户及助手的正文。

### 管理自己的未执行需求

共享成员可使用对话限定的 `GET/PATCH/DELETE /api/v1/sessions/{id}/runs/{run_id}` 查询、修改和移除自己的需求。PATCH 仅接受 `text` 与 `expected_version`，DELETE 使用 `expected_version` 查询参数；版本来自原队列快照。读回仅返回自己的公共运行信息，裁掉内部附件和调度元数据。其他真人的运行不能通过这一入口读取或修改；完整宿主原有管理行为保持不变。

修改和移除均在原 RunController 中检查作者、当前贡献权限、成员加入周期、未执行状态和文本版本。已启动任务不能修改；过期版本返回冲突。编辑同样禁止将真人普通需求改成宿主斜杠命令。结果未知时先回查原运行及完整队列，不自动重放 PATCH 或 DELETE；界面保留独立的编辑内容，不覆盖底部草稿。

共享输入区的权限和队列读取绑定刷新代次，定时轮询等待当前读取结束，避免慢响应不断被下一轮取代；后发读取、效果重建、隐藏或关闭使旧读取失效并取消其传输。迟到结果即使忽略取消也不能恢复已撤销的编辑权限。重新显示只恢复读取，不重放提交，已受理写入仍按原请求号收尾。

## 对话范围审批

共享入口提供 `GET /api/v1/sessions/{session_id}/questions`，返回公开路由问题及内容指纹 `revision`。只读成员可查看，提交需要当前 `control` 权限及精确 Origin。

`POST /api/v1/sessions/{session_id}/questions/{question_id}/answer` 接收 `request_id`（16–128 位字母数字、下划线或连字符）、`expected_revision` 和 `answers`。问题范围、版本、当前权限和成员加入代次均在提交时核对；同一问题串行接受决定，落盘成功后才唤醒原问答调用。既有宿主工具政策继续生效。

`GET /api/v1/sessions/{session_id}/decisions/{request_id}` 只返回当前管理员自身、同一成员加入代次的回执；未找到返回 `{"receipt":null}`。写入超时先查原回执，不自动重答。同一请求号的相同内容可查回记录，修改内容返回冲突。`status: recorded` 仅说明决定已持久记录；`resolved` 仅在当前提交响应中报告是否唤醒问题，不持久推断工具执行结果。问题取消、超时或宿主拒绝均不能从决定日志推断为执行成功。进程重启不会重放决定或恢复旧 Future。

共享页面的管理员使用原问题卡片提交审批，协作者和观察者仅查看。未确认请求按对话、真人和问题隔离保存在当前标签页；刷新不重放，原回执不存在时须再次显式点击，复用原请求号、版本和答案。

### 临时工具授权

`GET /api/v1/sessions/{session_id}/permissions/grants` 返回当前范围的授权快照，`GET .../permissions/grants/{grant_id}` 读取单条授权详情，`DELETE .../permissions/grants/{grant_id}` 撤回所选授权。撤回响应的 `revoked` 必须匹配请求的授权ID；浏览器不使用其他ID的回执删除本地条目或声明成功。结果未知时刷新列表核对，不自动重发DELETE。授权已不存在时显示范围变化提示；撤回授权不等于停止已启动操作。读取/控制错误与决定提示保留资源身份，第三方诊断及工具名保持原文。

`PATCH /api/v1/sessions/{id}/permissions` 必须同时提供 `permission_policy` 和 `expected_version`。缺失或多余字段返回 `400 permissions/invalid`：文案指出首个问题字段，`details.missing` 与 `details.unexpected` 列出完整字段集合。版本类型不符或长度不是64返回 `400 permissions/invalid-version`，`details.field` 为 `expected_version`。格式合法但与当前版本不匹配时仍返回 `409 permissions/changed`；调用方先读取当前权限及版本，再决定后续操作，不自动重放写入。

## 浏览器资源与关闭

浏览器操作取消后等待原操作收尾，重复取消不再次打断清理。停止加载的取消表示结果未确认，连接释放和历史记录完成后才返回；不能据此重发停止或导航。对话关闭逐项尝试上下文、观察句柄与画面收尾，失败保留所属句柄供显式重试；已确认关闭的上下文不重复关闭。全局关闭继续尝试其他对话、引擎和标题资源，最后保留原始异常报告失败。

页面观察在异步捕获、标题读取及旧句柄释放后，重新核对对话控制版本、页面和文档身份；迟到观察释放而不注册控件引用。模态响应后对原操作失败进行只读观察时，结果的`origin_operation_error`保留原操作错误，观察成功不表示原操作成功，也不重放原动作。

`GET /api/v1/screenshot/capabilities` 返回 native、hideWindow 和 reason；可用时 reason 为 null，不可用时为显式浏览器资源对象 `{key: "ui.screenshot.nativeUnavailable"}`。能力只读探测不执行截图；前端保存资源身份，菜单和已发出的提示随当前语言解析，切换语言不重复探测或捕获。

本机 macOS 的 `POST /api/v1/screenshot` 在捕获前申请屏幕录制权限，隐藏窗口另核对辅助功能权限。权限不足时打开对应系统设置，并分别返回 `403 screenshot/permission-required` 或 `403 screenshot/accessibility-required`，尚未执行捕获或隐藏窗口；打开设置失败返回 `503 screenshot/permission-settings-failed`，保留原始异常原因。错误码对应公开双语资源，切换界面语言不重发请求；交互规则见 [系统权限与再次授权](../desktop/README.md#系统权限与再次授权)。

## 设置页管理 MCP 执行服务

设置页的 MCP 服务面板通过本机管理接口启动和停止独立执行服务，显示本机地址、公网地址及运行状态，并可显式查看或复制登录密码。启动提示与公网地址标签按实际隧道模式区分临时地址和固定地址。管理接口只允许本机入口访问；共享入口不能启停服务或读取密码。

- `GET /api/v1/mcp-service`：读取状态、已登记项目列表及不含完整令牌的隧道摘要（含 `token_mask`）；`password_mask` 仅在运行且已有密码文件时提供遮罩，其他状态为空。
- `POST /api/v1/mcp-service/start`：默认使用全部已登记项目；传入 `scope: "selected"` 与 `workspace_id` 可限定为一个已登记项目。不能提交任意项目路径。
- `POST /api/v1/mcp-service/stop`：停止服务及其隧道。
- `POST /api/v1/mcp-service/password`：显式读取已保存的登录密码；服务不可用时返回错误。

面板同时支持临时隧道和固定隧道，Windows 和 macOS 使用相同启动、取消、健康检查与停止生命周期。公网入口使用 OAuth，连接密码用于授权登录；固定域名保持不变时不因重启隧道而更换 OAuth 地址。Cloudflare 账号、DNS 和隧道配置由用户管理，Harness 不代为创建或修改外部账号。

`start` 可附带 `tunnel` 对象，包含 `mode`（`quick` 或 `named`）、`public_url`、`origin_port`（1024–65535 的整数）和可选的 `token`。省略整个对象复用当前配置；首次缺少配置使用临时隧道。点击启动前，浏览器检查端口整数范围、固定隧道 HTTPS 根地址和令牌（留空可复用已保存令牌）；非法输入保留在面板中并提示，不发送启动请求。停止操作不受草稿校验阻挡。点击启动时自动保存配置，无需单独保存；下次打开设置或重启 Harness 后回填模式、固定地址与端口，令牌显示遮罩，留空复用。登录密码首次启动生成，后续启动继续使用同一份私密文件。配置保存到本机私有目录，采用唯一临时文件、同步与原子替换；准备期间原件发生变化时拒绝覆盖。损坏或重复字段的配置保留原件并拒绝启动，不自动修复。令牌通过子进程环境传递，不写入命令行参数、不通过状态接口返回；日志尾部移除本次令牌。

固定隧道适合长期连接：在 Cloudflare 控制台创建远程管理隧道、公开域名及连接令牌，在面板选择“固定隧道”并填写 HTTPS 根地址、本机源站端口和令牌。macOS 和 Windows 的新配置默认源站端口均为 `12345`，与 Codex 桌面网关的默认端口 `18765` 分开；已保存的端口继续按原配置读取，不自动改写。将该域名的服务地址设为 `http://127.0.0.1:<origin_port>`；使用默认端口时即为 `http://127.0.0.1:12345`。每台电脑使用独立隧道及域名，避免不同电脑的 MCP 数据混合。令牌已保存时留空可复用，修改配置前先停止服务。该模式使用 `cloudflared tunnel run`，不申请临时域名；端口预检查在准备隧道程序前进行，真实占用明确拒绝启动，不停止占用端口的服务。POSIX 探测与实际服务器一样启用地址复用并核对可监听，避免已关闭连接的 `TIME_WAIT` 被误报为占用；Windows 不启用地址复用，保留对其他服务的占用检测。Harness 检查本机执行器及连接器就绪，但不能据此证明用户的 DNS、远端路由或访问策略配置正确，需要用户完成真实客户端连接验收。配置参考 [Cloudflare Tunnel 设置](https://developers.cloudflare.com/tunnel/get-started/)。

临时隧道无需账号，但不保证可用性，重启会申请新域名。收到申请阶段的 429/1015 时显示专门的限流提示，本次 Harness 进程暂停新的临时申请五分钟；这只是本地保护时间，不承诺 Cloudflare 在五分钟后解除限制。不会自动重试申请，也不会切换出口以绕过限制；固定隧道不受此本地保护影响。

两种模式先检查连接器回环 `/ready`，再检查本机执行器健康状态。连接器存活但暂时断开时保留原地址，面板显示正在重连，由 cloudflared 继续连接原隧道，不新建域名；连接器或执行器进程退出时显示失败并收回地址，用户可显式重启。启动中可点击停止，等待已接受操作及所属进程、代理监听和输出线程收尾；清理未完成时不启动第二个实例。

图形入口将 Windows/macOS 系统 HTTP/HTTPS 代理及绕过列表补入隧道子进程环境；已有大小写代理环境变量优先（含显式空值），不修改系统设置或父进程环境。临时域名申请通过本次实例拥有的回环申请服务使用已配置的 HTTPS 代理，Windows 和 macOS 一致；随机路径只接受一次空正文 POST，不重定向或重放申请，限制响应大小及等待时间。此处理只覆盖域名申请，不代理到 Cloudflare 边缘的隧道数据连接。失败保留最多 8 KiB 的输出尾部供展开诊断，第三方原文不翻译，切换语言不重新启动。服务生命周期由 `harness/app/mcp_service.py` 管理；此入口与局域网共享对话入口独立，不能用共享对话权限替代 MCP 项目授权。

隧道程序优先从 PATH 查找。私有自动安装固定使用 2026.9.1：x64 Windows 与 macOS 优先使用 AgentDock 的 HTTPS 组件镜像，镜像失败或摘要不符则切换官方直链及资产 API；x86 Windows 直接使用官方通道。每个来源均按源码固定的官方 SHA-256 校验，不从远程目录接收新的信任摘要。已有 PATH 程序仍由用户管理，不强制替换版本。macOS 另检查常用安装位置，并可准备经过固定摘要校验的版本；官方下载遇到网络错误时自动有限重试，仍失败则尝试系统 curl；Windows 另回退到使用系统证书与代理的 PowerShell/.NET 流式下载，均限制大小、时长并响应取消。直链传输失败后切换固定资产 ID 的 GitHub 官方 API 通道，全部失败时返回有界的具体诊断，成功后继续校验并安装到 Harness 私有缓存，无需手动运行 brew；Windows 缺少 PATH 程序时自动下载固定版本的官方可执行文件，校验 SHA-256 后原子保存到 Harness 私有缓存；每次复用前重新校验缓存，失败时重新下载，取消时不发布下载文件。支持 x64、x86，Windows ARM64 使用系统 x64 仿真运行官方 x64 版本。无需管理员权限或修改 PATH，不探测旧产品目录，也不注册系统服务。其他平台找不到程序时明确报错。

服务状态为 stopped、starting、running、stopping 或 failed。状态回执保留错误诊断 `error`，自有错误同时提供 `error_copy`，无自有资源身份时该字段为 null；多项失败通过可选的 `error_details` 按顺序保留资源身份及外部诊断。面板按当前界面语言解析自有文案，本机与公网地址保持原值，语言切换不触发启停或密码读取。

MCP 服务设置面板在页面隐藏或面板关闭时暂停状态轮询，并取消未完成的状态读取；恢复可见后重新读取。启停前发出的旧状态响应不能覆盖当前动作返回的状态。

MCP服务状态的组合失败通过`error_details`提供按顺序的资源错误或外部原文；浏览器呈现时翻译各资源并组合，不通过错误正文反向匹配。`error`仍提供完整可读诊断，启动与清理失败不会因后台线程退出而丢失其中一项。

## 记忆管理

设置中的“三层记忆”可切换用户偏好、项目知识和对话笔记。现有 `/api/v1/sessions/{session_id}/memory` 及其更新、删除、导入、导出路由统一接受可选查询参数 `scope=user|project|session`，缺省为 `project`。服务端从已存在的对话解析项目根；不接受 `root` 覆盖。查询 `q` 仍为关键词搜索。

三种 scope 均使用现有内容、主题、固定状态、来源证据和版本控制。更新及删除版本冲突返回 409；格式和作用域错误返回 400。导入文件的 format 必须与所选层匹配。共享访问模式继续由原授权白名单拒绝记忆接口；本次不扩大远程访问能力。写请求结果未知时客户端回查列表并保留错误，不自动重放。

### 召回预览

`GET /api/v1/sessions/{session_id}/memory/preview` 返回三层当前召回的只读解释。输入来自服务端对话的最新用户消息，响应的 `source_seq` 指向该消息；客户端的 `q` 或 `scope` 不替换这份上下文。预览返回 `budget`、`used_chars` 和每层状态，包含选中条目的 ID、revision、`pinned|query` 原因、预算跳过条目、候选上限跳过数量和未命中数量。正文、查询文本、证据正文及数据库路径不进入预览响应。

预览与正式注入共用选择器，但反映读取当时的数据库、消息和语言状态；它不是先前模型请求的消费回执，也不是数据库跨层事务快照。核对历史实际请求应使用既有请求诊断。`ready` 表示层可读取，`unavailable` 表示读取失败，`unbound` 表示缺少对应作用域；不会因一层失败隐藏其他健康层的解释。公共类型为生成的 `MemoryPreview`，共享 HTTP 传输校验其响应结构。

预览条目引用新增 `source_status`：`untracked|unchanged|changed|missing|unavailable|unsafe|unchecked|invalid`。该状态仅比较记忆记录中的文件指纹；来源路径、当前指纹和文件正文不进入预览。说明见存储文档“文件来源与重新核实”。

各层 `recall.suppressed` 列出因已选中有效摘要而跳过的候选身份，字段为 `id`、`revision`、`summary_id`、`summary_revision`。摘要未选中、失效或来源需要重新核实时不抑制原文。该列表不包含正文和证据。

预览条目引用的 `derivation_status` 为 `none|current|changed|missing|invalid|unchecked`，表示整理摘要与输入版本之间的关系，不代表事实正确性。智能体工具新增同作用域的 `*_consolidate` 操作；当前没有额外HTTP整理写接口。记忆导入的当前格式保留有效编号和版本，身份冲突不覆盖，完整引用无法保留时回滚；调用方无需改写导出的JSON。

### 附件拒绝的资源身份

上传请求只接受 `files`，每项只接受 `name`、`mediaType` 和 `data`；文件名及声明类型最多 255 个码点，批次最多 20 个文件，结构和长度在解码、准入与落盘前校验。展示名仍由领域层清洗并限制长度。统计读取失败不返回部分结果；上传落盘后统计失败返回 `503 attachment/stats-unavailable`，`details.attachments` 保留已写入引用，不能当作上传未发生或自动重放。无单项删除接口，内容寻址附件可能被多个对话引用，不通过清理单个测试对象引入隐式删除。

附件准入、请求校验和不存在错误在原有 `error`、`code`、HTTP状态基础上，通过 `details.copy` 携带 `key` 及平面 `params`。例如拒绝 `.exe` 的错误码仍为 `attachment/type-denied`，资源为 `ui.attachments.server.extensionDenied`，参数为 `{"p0":".exe"}`。已有数值细节（如 `bytes`、`maxBytes`）保留；`error` 仍是产生时的诊断文本。

上传客户端只接受错误码对应的已登记资源键、完整参数名及有限数值/字符串值；已登记错误缺少或损坏资源信息时按无效响应呈现，不按正文反推，不重发上传。未登记错误保留原始诊断，不把“未登记”等同于“第三方”；附件存储异常及其他公共错误另按各自协议处理。

## 错误提示的语言

HTTP 语言沿用实例当前设置，不通过 Accept-Language 或 X-Language 覆盖。HTTP 错误保留原有 `code`、状态码与 `details`。畸形 UTF-8／JSON 使用完整双语提示，解析位置保存在结构化 details，不将解析器英文原句拼入提示；路由不存在错误只回显路径的前 200 个码点。当消息仅为已登记的机器错误码时，响应出口按当前语言显示操作提示；业务已提供的具体消息与未知错误码保持原样。共享 WebSocket 的只读拒绝使用同一文案。共享问题读取中的已知 `session/not-found` 使用已登记的双语资源，机器码保留在 code 字段；该入口原有 403 及未启用共享的 409 保持不变。真正未知的共享错误码仍由兜底消息保留诊断身份。共享 HTTP 传输按错误码与资源键核对 JSON 格式、标题超限、未知字段及语音准备的自有诊断；保存资源身份后，英中英切换仅重新呈现，未知资源或非法参数保留原诊断，不自动重发请求。该投影不改变鉴权、请求重试或执行状态。

## 恢复指令与回执

`POST /api/v1/sessions/{session_id}/continue` 的审核恢复请求提供 `run_id`、`mode`、`text`、`recovery_version` 和 `verification_note`。回执的 `recovery.instruction_text` 保存完整指令原文，与装配后供模型使用的 `text` 分开；核实说明按现有规则去除首尾空白。浏览器按结构化身份核对回执，不根据中英文提示词的前后缀识别请求。

相同幂等键、原运行及完整恢复字段只复用已接受回执，不因语言变化重新提交运行。修改指令、模式、来源版本或核实说明返回 `run/idempotency-conflict`；未知写结果仍先读取原回执，不自动重发。未携带恢复草稿的普通继续请求沿用自身提交合同，不能将这项核对用于猜测其他请求。

## 问答与账号消息语言

宿主产生的问题选项可携带唯一、非空且不超过 200 个字符的字符串 `id`；它用于动作身份，不替换答案中的标签。计划审批使用 `approve` 和 `keep-planning` 身份，标签按运行语言产生；浏览器切换语言只改变显示，提交仍使用该问题提供的原始标签。权限审批采用 `allow-once`、`allow-temporarily`、`deny` 身份，分别表示本次、相同操作 15 分钟及拒绝；身份本身不授予权限，答复、版本和实际工具准入仍由原调用链校验。

问答答案中的 `selected` 必须显式提供字符串数组，包括自由文本答案的空数组；不接受旧的单个字符串或省略该字段。未提交的问题仍按既有部分回答语义补为空选择。无效答案不会提交决定或唤醒等待中的工具。

ChatGPT 账号内建错误按当前读取语言展示；OAuth 回调使用发起该次登录时的语言，正文通过 UTF-8 返回。模型目录中的供应商名称、描述和用户内容保持原文，不翻译第三方内容。

附件读取与提交要求仓库内容和完整元数据一致。附件不存在返回 `attachment/not-found`；损坏或不完整的仓库记录明确返回 `attachment/invalid-storage`，不补造旧格式元数据。提交引用不可用附件时返回 `attachment/unavailable`，不创建运行；WebSocket 失败保留 `submitted: false` 及原 `request_id`。物化写入失败返回 `attachment/materialize-failed`，已有工作区文件不被覆盖。

## 人格与语言快照

对话人格及推荐协议使用 `harness/agents/personality.py` 的当前语义代号和四组偏好；可空选择表示清空，不接受旧字母代号，也不自动迁移；无效配置提示从当前人格目录重新选择或使用默认配置。`harness/web/protocol.py` 按调用语言构造独立说明快照，不修改共享 schema 常量。`GET /api/v1/openapi.json` 在当前路由实例内按语言及路由模板快照缓存不可变响应字节，最多保留四项；每次返回独立响应对象并禁止客户端缓存。语言或路由快照变化使用独立条目。生成文件同步与真实人格、队列请求体、共享回答必填字段由 `tests/test_protocol_current_boundaries.py` 核对。

人格目录读取与保存、删除、推荐、全局应用使用独立生命周期。语言切换保留编辑器、偏好和正在进行的操作锁；若写入未结束，目录刷新延后至所属操作收尾，再读取当前语言目录，不重复写入。浏览器人格草稿校验当前语义代号，旧字母代号不恢复。

## 输入与队列草稿

浏览器输入草稿只合并当前完整快照：格式、选择、附件、待确认提交及资源提示须通过读取校验。损坏的输入草稿快照先在 localStorage 另存原始字节并读回确认，再移除活动无效记录，以当前格式恢复保存。隔离失败时保留活动原件和当前页内存输入，错误提示按当前语言呈现。不自动迁移旧版本，也不重放待确认提交。

队列编辑与撤回草稿使用同一持久快照校验及损坏原件保护。队列条目检查当前操作字段、版本指纹与可用的对话身份，未确认编辑须关联同一条目；服务端附带的RunRecord元信息保留。损坏sessionStorage数据不合并、不覆盖或删除，当前页的新编辑保留在内存，提示按实际语言解析。

队列编辑保存或只读核实成功后，仅清理仍与发起快照相同的编辑草稿；等待期间被替换的新草稿保留，旧操作的焦点恢复不得抢占新编辑。成功通知保存资源身份，分页和读取错误使用完整双语模板；切换语言不重新提交或核实。

## 模型连接与设置提交

连接设置使用供应商→接口→模型与认证结构。`GET /api/v1/connection` 返回版本 2 的配置投影与 `revision`；`PATCH` 只接受 `providers` 和读取时的 `revision`，允许空列表。并发版本冲突返回错误，原配置保持不变。每个接口包含协议、地址、认证、共享 Key 列表与模型列表。模型身份为 `harness/{供应商ID}/{接口ID}/{模型ID}`，同名远端模型可以属于不同接口。保存响应包含 `routing` 和当前配置。认证类型包括 `api_key`、`oauth`、`environment`、`opencode_local` 和 `anonymous`；`anonymous` 仅用于 Kilo Free，要求固定的公共网关地址、Chat Completions 协议及空 Key／认证环境字段。保存和读回的公开契约均保留该类型。

`GET /api/v1/connection/providers` 返回初始供应商模板。`POST /api/v1/connection/discover` 接收 `provider` 和 `connection` 草稿，不提交配置写入。动态目录使用供应商自己的刷新逻辑；通用 OpenAI／Anthropic 列表协议读取当前接口的完整模型列表。响应 `fallback: false` 表示成功目录，其成员以远端为准，只补充同名元数据，不复活已下架模型。`fallback: true` 表示保留现有缓存：接口读取失败、分页结果尚不完整或缺少可用列表协议；没有缓存的读取失败仍报错。接口留空地址时沿用模板地址，缓存存在时优先保留该接口缓存而不是重新展示安装包模板。

公开接口可包含 `model_catalog` 能力元数据。获取成功后界面将新目录写入草稿，移除不再存在的选中模型；保存时沿同一个 `PATCH /connection`、`revision` 比较与原子文件发布路径提交缓存和选择。重新打开的目录、模型能力、子智能体目录及模型桥接读取同一份缓存；保留模型的稳定身份及手工选项。缓存支持明确的思考映射与档位、输入类型、容量、兼容参数及分段计费元数据，不包含认证凭据。未能确认的新模型能力不猜测；同版本日期快照可以补充该系列已知思考能力，显式模型级映射可用于目录外手工模型。Kilo Free 新增时自动获取明确免费的候选模型，初始选择为空，后续刷新保留已保存的勾选；其他供应商仍由用户显式选择目录项或添加各用途系列最新版。

授权通过 `/connection/authorization` 创建操作，按操作 ID 查询、回答或取消；OAuth 令牌不返回浏览器。登录先暂存草稿凭据，保存配置时按授权操作和接口身份提交。

`PATCH /connection/status` 接收 `connection_id`、`key_id`、`enabled`；`POST /connection/reset` 接收 `connection_id`，显式恢复该接口失败 Key。Key 只在所选接口轮换，不切换模型或供应商。已输出文本、思考、签名或工具调用后失败不自动重放。

已保存模型 Key 共用 `mask_api_key`：超过四位显示六个星号加末四位，短 Key 只显示星号。省略 Key 新值按稳定身份保留；环境值与自定义请求头在公开投影中为空，按字段身份保留。OAuth 只返回已授权状态。配置格式不符时明确报错，不自动迁移或清理。配置操作和发行运行时见 [模型供应商](model-providers.md)。

模型菜单在尚未创建对话时也可选择思考强度，通过 `PATCH /api/v1/ui-settings` 保存默认 `reasoning_effort`；选择本身不创建对话。具体档位和 `null`（模型默认）同步持久设置与请求默认模板，重启恢复后同样生效。有对话时仍保存该对话的显式覆盖，取消覆盖则继承全局默认。全局变更由未设置覆盖的对话在后续运行中采用，已开始的运行保留请求快照。

模型菜单直接显示当前所选模型名称。未手选模型的对话显示设置中的默认模型，目录勾选该模型；默认设置改变后同步更新。手选其他模型沿 `PATCH /api/v1/sessions/{id}` 保存当前对话的具体模型，不修改全局默认。重复选择当前模型不写入；菜单不提供另一种模型配置模式。保存失败保留已确认配置，结果不确定先读取原对话确认，不自动重发；原对话的保存继续收尾，但迟到结果不关闭或污染切换后新开的菜单。API 仍允许 `model: null` 清空对话覆盖，该协议行为不由模型菜单发起。

输入区模型按钮标明所选模型及保存中的选择；多连接配置标明路由候选。它们不证明某次请求已经采用该模型。生成状态行显示当前阶段与经过时间，悬停提示及展开详情呈现所属对话请求事件报告的模型，重试时随同一请求更新；断线时提示最近报告值，缺失时显示尚未报告，不从全局选择、挂载快照或路由候选推断。触屏及键盘用户可展开详情读取完整模型名。请求结束后清除生成状态。

默认强度连点按顺序保存。首次发送等待已有保存结束，未确认或失败时保留草稿并提示核对；保存期间切换到其他新对话或项目不会继续创建旧提交。已有的继承对话在默认保存中或尚未确认时也拒绝发送，显式覆盖的对话保持独立。未知写入只读回一次设置，不自动重放；失败菜单始终提供“使用模型默认”恢复入口，即使当前模型没有可选档位。

`PATCH /api/v1/ui-settings` 混合更新账号模型和普通设置时，两者分别使用账号文件与设置文件。若模型选择已提交、后续普通设置保存失败，返回 `503 settings/partially-applied`，`details.applied.default_model` 标明已提交模型；先通过设置 GET 核对状态，再决定后续操作。接口不声称两个文件构成整体事务，不自动回滚或重放已提交的选择。重复选择当前账号模型不再重复写账号文件。

宿主中的 `list_subagent_models` 读取同一已配置供应商目录及 ChatGPT 账号模型，不另发 OpenRouter 目录请求。独立构造工具、未提供宿主目录回调时，仍使用显式传入的单接口目录读取。默认选择、对话覆盖、团队／智能体及压缩都使用稳定模型身份。

问题输入和计划修改意见的浏览器草稿只恢复当前有效格式。损坏正文、结构或问题schema不匹配时保留sessionStorage原件，当前页的新输入留在内存，界面提供双语说明；已回答问题的自动收尾同样不得删除损坏原件。不自动过滤、截断或迁移无效选择。

浏览器原位编辑沿用当前对话连接：运行中使用引导，空闲时普通发送。回执成功仅清理发起时未变化的原位草稿；旧错误不能写入替换后的草稿或另一对话。消息行编辑实例按对话、消息ID和来源序号隔离，产品错误保存资源身份，不因语言切换重复发送。

运行时设置、启动语言设置和项目注册表均将非法JSON或UTF-8解码失败作为当前格式错误，按调用语言返回明确提示并保留原始字节。读取失败后，更新、项目播种和建立注册表文件同样拒绝，不能借这些入口覆盖损坏数据；文件缺失与合法空记录仍按当前初始化语义处理。

订阅账号状态和账号模型解析均返回独立模型快照，包含嵌套推理档位列表；SDK 调用方修改结果不得改变账号内部目录、当前模型选择或持久文件。

终端创建请求支持可选 `output_encoding`，默认 `utf-8`；未知编码在启动前拒绝，创建后固定。`TerminalView`、`JobView` 和 `CommandOutput` 可携带 `encoding_errors`（通道、实际编码、字节偏移及原始原因），与真实进程状态分开。工具 `bash`、`pwsh`、`run_code` 和独立执行器 `harness_exec` 使用同名参数。Windows ConPTY 只接受 UTF-8；详细边界见 [文本编码](text-encoding.md)。

`PATCH /api/v1/ui-settings` 的非空请求若全部字段无效，返回 `400 settings/invalid-fields`，`details.rejected` 列出拒绝字段，且不写入设置或账号选择。语言仅接受 `auto`、`zh-CN`、`en`；主题由浏览器本地偏好管理，`theme` 不是该接口支持的字段。混合请求继续保存合法字段，并在成功响应的 `rejected` 中列出拒绝字段；空对象保持无操作语义。

## 上下文管理

上下文管理只在对话的“上下文 → 管理设置”中提供，设置导航、搜索和命令目录不再重复注册该页面。三档预算按当前对话所选模型的窗口计算：精简 40%、均衡 60%、深入分析 80%；手工窗口上限更小时使用该上限。容量未知时分别使用 128,000、256,000、384,000 token。每次显示均有一档选中，预算显示在对应卡片内，不再单列独立预算输入。上述比例是目标；实际预算取目标与现有安全阈值的较小值，即 `max(1, floor(窗口 × 0.85) - min(输出预留, floor(窗口 / 4)))`。目标受限时卡片直接说明目标比例及实际预算，不把 80% 当作可突破输出预留的许可。

面板通过 `GET /api/v1/settings` 读取本机共用策略，优先使用当前对话模型目录中的容量，不以其他默认模型或旧请求的容量代替。选择档位或改变模型容量只更新草稿，保存沿 `PATCH /api/v1/settings` 发布计算后的预算数值，仍由现有自动管理与安全余量确定实际整理阈值。重新打开时按当前容量匹配已保存预算；不匹配的数值先预选均衡并标为待保存，不自动改写原配置。高级选项保留自动选择工具的方式、工具结果长度、摘要长度、输出预留和手工窗口上限。

设置由本机所有对话共用，后续安全边界采用，已发出的请求保留原快照。未知写入先读取核实，不自动重发；同窗通知和保存读回不能覆盖后续编辑。预设计算和面板选择分别由 `contextPresets.test.ts`、`context-presets-model-smoke.mjs` 验证，写入隔离继续由 context-save 系列回归核对。

## 自动化日程

自动化列表的状态筛选与任务卡片共用判断：启用与运行中的任务归入“已启用”；停用的一次性任务只有在最近一次记录成功且结束时间已达到计划时刻时，才显示并归入“已完成”，提前手动执行不把尚未到期的任务标为完成。其他停用任务归入“已暂停”。名称搜索忽略首尾空格和大小写；无匹配结果可一次重置搜索与状态筛选。

调度器每 2 秒检查到期任务；数据库租约有效期为 30 秒，同一所有者在剩余有效期不超过 20 秒时续租。每次检查和手动运行仍在同一 `BEGIN IMMEDIATE` 事务内重新核对数据库所有权，不能凭本地缓存认领任务；其他所有者的未到期租约阻止认领，到期后允许接管。没有任务到期且尚未到续租时刻的检查不更新租约行；关闭仍仅释放自己的租约。此调整不改变数据库结构或 SQLite 日志模式。

自动化保存与预览均要求显式的 `schedule` 对象，支持 once、interval、daily、weekly、monthly、yearly；monthly 需要 `time` 与 `monthdays`（1 至 31 日），yearly 另需 `months`（1 至 12 月），当月不存在的日期直接跳过（例如 2 月 31 日进入 3 月 31 日）。不再从旧的 `due` 或 `interval_seconds` 请求字段推导日程，也不在缺少日程时默认立即执行。列表中的 `due` 是调度结果，不能替代创建请求的日程。 新建必须提供32位小写十六进制`creation_id`，持久ID为`auto_`加该标识；更新必须提供现有`id`，两种身份不能同时出现。重复创建标识返回`automation/create-exists`，不覆盖已保存配置、调度时刻或运行状态。浏览器发送前持久保存原创建身份与正文，未知响应只从目录回查原ID和字段；换页或刷新后仍不重发。原创建已确认而用户输入已变化时，保留新草稿并提示再次明确提交。浏览器存储不可写时不发送新建请求。

模型在对话中收到明确的定时或重复提醒请求时，可调用 `schedule_automation`；工具自动绑定当前会话并把 `prompt` 保存为到期时发送的新用户消息。例如“每30分钟发送继续”会创建 interval 任务，任务到期后由同一调度器调用当前对话，不另起一套计时机制。普通对话不匹配定时意图时不会自动创建任务。

对话工具 `list_automations` 只返回当前对话的任务；用户要求修改名称、内容、时间或暂停、恢复定时器时，先查询，再用准确任务ID调用 `update_automation`，只提供需要变更的字段，未提供的字段保持原值；用户要求取消或删除定时器时，用准确任务ID调用 `delete_automation`。多个任务可能匹配时需明确目标。修改与删除在同一数据库事务中核对对话归属及运行状态，不能操作其他对话或正在运行的任务；删除成功后停止未来调度，既有运行记录保留。修改或删除失败不报告成功，也不自动重放未确认的写入。
该工具的创建身份由会话和工具调用 ID 稳定生成；同一调用被重放时回查原任务，内容一致才返回原记录，不重复创建或计作新进展。读取或写入失败不自动重放。提示词与工具参数说明均在真实对话请求中解析，回归覆盖提示词装配、双语目录和隔离对话的到期发送。
