# 存储与恢复

本页描述产品存储及显式恢复行为。新增或修改存储先遵循 [代码生成与防回归](code-generation.md)。

会话事件的 `source_event_seqs` 是可选的整数序号数组：省略或 `null` 表示没有来源，数组成员须为非负整数，布尔值不作为整数接受。加载、分页读取和导入遇到错误形状时明确拒绝，并保留原始日志；不会把损坏来源静默转换为没有来源。

会话头、附件原件及侧车元数据、连接器声明、扩展启停和 UI 设置共用 `core/fsatomic.py` 的同目录原子发布：独占临时文件，写入后 flush/fsync，再替换目标；Windows 的特定短暂共享冲突只重试替换，最多四次，不重写或重新采集内容。失败清理本次临时文件，原目标不因失败被删除。JSON 声明先序列化为固定 UTF-8/LF 字节再发布，各存储仍独立负责字段校验、锁和内存提交。附件原件与侧车仍分别发布，不是跨文件事务；已有损坏附件继续明确拒绝，不自动补齐。

会话提交、人格目录、插件安装、Key 池、仓库执行、网关租约及独立执行器共用 `core/file_lock.py` 的原生写锁适配。Windows 直接锁定首字节区域，空锁文件同样有效，不在取得锁之前写占位字节；POSIX 使用文件锁。各业务保留原有的阻塞或非阻塞策略，人格写入仍显式限制等待时间。释放后保留锁文件，避免等待者与新调用锁住不同身份。Key 池首次加载与后续读改写都在同一旁路锁中完成，避免构造中的读取句柄和另一实例的原子发布竞争；锁失败不允许无锁发布。

## 数据归属

`HARNESS_HOME` 默认指向 `~/.harness`，保存运行状态和用户设置。项目根与运行根不是同一概念。系统技能发现入口为仓库 `.harness/skills`，当前检出未附带该目录或预装技能；用户项目中的 `.harness` 内容属于项目数据，不得随代码清理删除。

| 数据 | 源码入口与存储 |
|---|---|
| 对话 | `session/store.py`：`sessions/<id>/header.json`、`events.jsonl` |
| 独立 MCP 执行器 | `execution/store.py`：执行器配置的 `home/executor.sqlite3`，同目录 `executor.owner` 文件持有进程所有权锁 |
| 普通聊天接续 | `mcp_server/companion.py`：执行器运行根的 `companion.sqlite3` 保存浏览器绑定与单次发送意图，`companion-key.json` 保存回环桥专用配对码；执行器数据库只读 |
| 请求诊断 | `session/request_traces.py`：运行根 `request-traces.sqlite3`，包含实际命名传输的 `purpose=title` |
| 文件证据 | `session/file_evidence.py`：运行根 `file-evidence` |
| 项目看板 | `project/board.py`：工作区 `docs/harness-task-board.json`，当前任务合同与内容修订 |
| 项目记忆 | `app/memory.py`：项目 `.harness/memory.sqlite3` |
| 用户记忆 | `app/layered_memory.py`：运行根 `memory/user.sqlite3` |
| 对话记忆 | `app/layered_memory.py`：运行根 `memory/sessions/<对话ID的SHA-256>.sqlite3` |
| 自动化 | `app/automations.py`：启用自动化时使用运行根 `automations.sqlite3`，保存调度声明、执行登记和调度租约 |
| Superagent | `app/superagent_*.py`：显式配置的接收、投递、协调、创建、关联及结果账本，保存事件、订阅、批次、游标、决策及原运行／资源引用；已有 Worker 的新 Thread 关联独立记录意图与回执，未知结果不重新订阅。CLI 另维护启动身份、接收回执、回复候选与状态投影。可选 `github.sqlite3`／`feishu.sqlite3` 各自保存信道身份、核验身份的原事件、原目标、消费游标、发送意图及远端回执，不保存密钥值或租户访问令牌；未知发送保留原件并只回查。复用原宿主工作树和对话存储，不复制执行状态，详见 [Superagent 模式](superagent.md) |
| 用户人格目录 | `agents/personality_library.py`：运行根 `personalities.json`，写入使用同目录 `personalities.lock` |
| 插件安装状态与版本包 | `plugins/packages.py`：运行根 `plugins/state.json` 与 `plugins/cache/<名称>/<摘要>` |
| 插件市场来源 | `plugins/marketplaces.py`：运行根 `plugins/marketplaces.json`；Git 市场指针位于 `plugin-sources/markets/<来源SHA-256>.json` |
| 连接器 | `connectors/store.py`：运行根 `connectors.json`，版本化声明 |
| 技能与智能体启停 | `plugins/state.py`：运行根 `esc-state.json` |
| 用户技能 | `skills/paths.py`：运行根名为 `.harness` 时使用其同级 `.agents/skills`；其他运行根使用其内部 `.agents/skills` |
| 项目安装扩展 | `skills/paths.py`：技能 `.agents/skills`，智能体 `.harness/agents` |

技能的安装、创建和卸载以 `.agents/skills` 为目标；当前发现器还读取项目 `.harness/skills`、运行根 `skills/` 和随包系统目录。安装目标与只读发现来源不是同一集合，具体优先级见扩展文档。不自动迁移其他目录中的文件。设置页仅在目录说明中展示路径，空态说明添加方式。 SDK 安装与卸载只接受 `skill`／`agent` 类型及 `user`／`project` 作用域；非法值在文件操作前拒绝，不回退为用户目录。

技能目录规则按传入运行根的名称判断；例如 `~/.harness` 对应 `~/.agents/skills`，`/data/custom/.harness` 对应 `/data/custom/.agents/skills`，`/data/runtime` 对应 `/data/runtime/.agents/skills`。不因目录位置不同自动搬移已有技能。

其他状态文件的实际位置由 `Harness` 装配和各存储类确定；不要将凭据复制到普通设置或文档中。

## 用户人格与插件状态

用户人格目录保存用户副本，内置人格不写入该目录。更新与删除要求当前 `revision`；写入先持有进程内锁与固定旁路文件锁，再读取最新目录，使用同目录临时文件完整写入、flush、fsync 后原子替换。目录损坏时保留原件并报错，不当作空目录覆盖。删除目录条目不改变已经复制到对话或智能体的独立文本。

插件安装状态与启停状态分开存储：`plugins/state.json` 记录安装版本，`esc-state.json` 保存能力启停。安装包目录由合法名称和摘要推导，拒绝路径中的符号链接，不接受状态文件指定任意绝对目录。市场来源清单不复制插件能力；已缓存 Git 市场的读取只使用登记指针，不因页面刷新启动网络获取。

## 对话列表扫描缓存

列表快速扫描以事件日志路径、mtime_ns和大小作为缓存键，条目上限512。缓存命中与最近使用顺序更新、插入淘汰及清空共用线程锁，避免并发清空后再移动已删除键；磁盘扫描在锁外执行，不串行化不同对话的文件读取。缓存不写入用户数据，也不替代日志校验及精确投影回退。日志路径入口直接读取元数据并只将文件不存在作为缺失处理，权限及其他读取错误保留原异常；正文读取失败同样传播，不用零统计或内存快照掩盖磁盘失败。缺少事件文件的新建对话由存储层确认。快速扫描遇损坏JSON、非对象记录或异常序号时交给存储层处理，不缓存自行推断的有效结果；损坏尾行仍保留原件及已确认前缀的写入保护。

## Academy 学习数据

独立课程项目、检查点、进度、代码与模型实验的证据、制课记录、点评快照和请求回执保存在 <Harness home>/academy/，不写主对话日志或用户当前项目。模型实验保留实际系统指令、用户提示和回答，后续实验不改写已提交的点评快照。课程包更新不会自动迁移学习项目；未知操作不重放。文件恢复先保存当前代码，再应用经指纹确认的目标快照；部分失败保留检查点与未知回执。完整归属和限制见 [Academy 的回执与数据](academy.md#回执与数据)。

## 写入纪律

无模型执行流水线使用既有执行器事件表中的 `pipeline/state` 保存完整修订；步骤输入、技能版本和项目根在后续修订中不可改变。每个命令使用固定原请求身份，先保存受理意图再提交，恢复时只核对原回执及作业。接续桥使用独立数据库，发送前保存唯一意图编号；编号不进入聊天正文，发送结果未知时保留记录，不自动重发。执行器启动事件记录本次实例身份，用于区分旧进程留下的作业事实；不重放命令或迁移已有结构。具体恢复和用户可见边界见 [ChatGPT 网页开发与自动接续](chatgpt-development.md)。

`ExecutionRuntime` 取得 `ExecutionStore` 后，设置加载、工具注册或启动事件登记仍可能失败；构造入口在传播原异常前显式关闭已取得的数据库和所有权锁，不依赖失败对象被垃圾回收。装配失败和存储回收失败同时发生时，沿共享清理入口保留两个原始异常。`test_file_lock_resources.py` 分别注入设置加载与末端事件失败，核对关闭后的数据库拒绝读取、所有权立即可重新取得，以及双重异常不被覆盖。

对话先持久化，再向订阅方广播。写失败会阻断对话继续执行，不能发布未落盘的成功状态。JSON 声明使用临时文件和原子替换；SQLite 的初始化与结构校验由 `harness/core/sqlite.py` 负责。

对话表面替换的起止序号必须存在于当前表面，且按表面位置正向排列；替换后序号的数值大小不代表位置顺序。追加先纯校验区间，提交成功后才修改内存表面。恢复重放采用同一校验，不把无效替换降级为追加，不改写原日志。

计划与智能体选择读取只对明确不存在的对话返回缺省状态；损坏对话及注册表错误继续向调用方报错，不能静默解除限制。

当前格式不自动迁移。已有文件损坏或结构不符时保留文件并报告错误，新建存储正常初始化。格式版本见各存储实现；不要仅因对话头版本一致就跳过业务事件的结构校验。

运行正文的 `id`、委派摘要的 `agent_id` 都必须与 `runs` 表中实际读取的主键一致。单条读取、历史分页及启动恢复共用存储层的身份校验；不按正文声明重定向缓存或恢复写入。身份不符返回 `run/identity-mismatch`，原文件保留。正文及摘要在任意嵌套层拒绝重复 JSON 字段，返回 `run/duplicate-field`，不按最后一个值覆盖；启动恢复遇到此类损坏时整笔事务回滚，保留已存记录。委派摘要分页仍只解析有界摘要；主运行终态历史仍按需加载，不为启动校验全量物化。

成员自有恢复和中断错误在结构化 `error.copy` 中保留资源身份；多项执行、关闭或交付失败按顺序保存 `error.parts`，原始原因继续保留。对外成员视图提供 `error_copy` 或 `error_parts`，归档写入警告提供 `archive_error_copy`。正文按读取语言呈现，浏览器按当前界面语言呈现；外部诊断及用户中断原因保持原文。摘要中的错误原因至多20项，外部诊断和文本参数共用2000字符预算，完整原因仍由单条详情读取。

主运行的自有中断、未完成、恢复和队列结算错误保留 `error.copy`；来自 `HarnessError` 的资源身份可以位于 `error.details.copy`。历史摘要保留明确资源及参数，恢复预览通过 `error_copy` 提供给浏览器；原诊断字符串继续保留。切换语言不改写运行记录，也不改变恢复版本。

恢复、轮次结果与验证回执共用工具结果身份检查：开始早于唯一结果，工具名、调用身份及布尔结果标记一致才采纳为配对执行。错名、乱序、重复或冲突身份保持未知，涉及副作用的恢复继续要求核实；缺少开始的明确未执行回执仍可表达未执行，不据此推断执行成功。只读恢复预览不重放工具或改写原日志。

运行正文和成员摘要都必须明确包含当前合法的 `status`；允许值来自 `core/runs.py` 的活动态和终态集合。缺少、未知或类型错误的状态返回 `run/invalid-status`，不使用新运行的默认值补齐，也不改写原始记录。

`runs.sqlite3` 的 `queue_orders.data` 必须是非空字符串组成的数组，身份不可重复；空数组合法。启动时先校验全部排序记录，再进行运行恢复。格式错误直接返回错误，不能据此改写其他运行状态。排序中保留已完成或已移出队列的历史身份是合法的，恢复时仅据此排列当前明确暂停的排队项，不重放历史运行。

HTTP新建对话的`X-Request-ID`随首个头写入`metadata.creation_request_id`，此时`creation_completed=false`；模型选择和智能体初始化完成并成功写回头信息后才标记true。最后一次写入失败时保留原请求身份及未完成状态，不能根据对话存在就认定初始化完成。浏览器在发送前将该身份存入未保存对话草稿；存储不能保留身份时拒绝创建。丢失响应后按身份查找唯一且已完成的对话，并核对详情头后恢复；找不到、不完整、重复匹配或身份错误时保留待确认状态，再次发送只回查，不重放POST。刷新仍沿草稿保存的身份回查；项目、检出或智能体已变更时，先确认原创建完成并保留原记录，再由本次发送创建当前对话，当前草稿只归新对话。旧结果仍未知或回查期间再次切换时不创建、不提交。

新对话创建草稿同时冻结可选 `project` 检出参数，刷新后继续回查原请求，不用当前分支选项重新创建工作树。Git 项目对话头保存 `project_cwd`、`workspace_id`、`checkout_mode`、`base_ref`，隔离检出另带 `worktree_id`；项目分组与下一次新对话使用来源项目，模型执行、文件与媒体仍使用实际 `cwd`。普通文件夹不伪造 Git 元信息。已有记录不迁移。分支、目录准备及失败处理见 [新对话接口](api.md#web-api)。

排队运行的 `prompt_input` 保存用户原文、物化后的附件 parts 和附件引用。编辑通过新字典与重装配后的模型正文一起提交，持久化成功后才替换内存记录；不从正文尾部推断或删除附件。对外队列视图提供原文，运行正文仍保留供模型使用的完整提示。

## 工作树交付失败

WorktreeService的交付冻结与环境复制公开入口共用实例RLock，读取工作树记录到发布索引保持串行；内部list/get重入同一锁，后续发布保留前一操作的字段。该保证属于同一宿主服务实例，不代表与外部进程或用户编辑之间的跨进程事务。

环境复制复用既有回执前严格核对当前字段、回执/工作树身份、指纹、状态、列表及相对路径和文件身份字段。损坏JSON、UTF-8或正文结构在复制规划前返回git/environment-invalid，保留原回执，不补空列表、不迁移或重放复制；合法空回执仍按当前终态复用规则处理。

工作树的源快照导入、交付整合和环境文件复制在失败后尝试保存失败记录；该记录若也无法写入，原领域错误的 `details.recording_error` 保留次级错误的代码、诊断及可用类型。原始异常仍为异常链原因，不自动重放写入或删除失败现场。没有 `recording_error` 仅表示本次记录调用未抛错，不等同整个操作已回滚或恢复完成。

交付冻结保存失败后的引用撤回只作用于本次创建的引用，并比较预期提交。撤回本身失败时，以交付结果不确定错误保留工作树ID、引用及`cleanup_error`，原保存异常仍作为异常链原因；不自动重放冻结或强制删除现场。

## 待办快照

`core/todo_initialization.py` 区分普通开发的建单建议与已批准计划的实施约束。普通开发连续三个成功写入批次后发送建议，整轮最多两次；即使清单提交失败，未建单也不拦截实施工具或最终回答，不因额度耗尽报 `todo/list-required`。已批准计划仍在实施前要求非空真实清单，保留有限纠正和明确未执行的门禁结果；已有工作不自动重放。提醒不生成或修改清单，实际提交仍走下述校验。

`todo/write` 的当前数据包含 `list_id` 和完整 `todos`。 SDK读取与工具快照读取共用当前格式校验：任务ID唯一、正文和状态有效、计划绑定一致，证据核对原调用身份及早于清单提交的事件序号。损坏记录明确报错并保留原件，不投影为空清单，也不从旧字段补造身份。读取不得为缺少身份的日志补造清单标识。快照令牌绑定对话、清单、计划和事件序号；更新时用 `snapshot_token` 或 `expected_seq` 做版本比较。冲突返回当前快照及恢复入口，不重置历史。浏览器对明确 updated=false 的已知待办错误直接显示当前界面语言的原因、原清单保留说明和修正指引；原始回执收在技术详情中，不在卡片中重试写入。未知错误仍保留通用原文呈现。

执行清单写工具可用且当前不是计划探索或只读任务时，每次模型请求将清单上下文与工具定义绑定到同一已确认快照。初次选择当前活动清单，后续成功的 `todo_read` 或写入可以选择另一清单或新版本；读取空计划不会继承另一清单的版本。上下文携带版本元数据、`update_arguments/write_arguments` 及任务 ID、状态，不复制任务正文或证据到开发者指令。空清单与以前轮次已全部勾选的清单不附带这段上下文；本轮更新过或尚未完成的所选清单继续提供。模型请求中的 `todo_update` 将 `snapshot_token` 标为必填，并用枚举约束本次快照、清单身份、序号及真实任务 ID；注册原件、SDK 和执行器的 `snapshot_token`／`expected_seq` 协议保持不变。并发变更或冲突不会把已发出的定义、参数自动换成最新版本；必须显式重读后才推进所选版本。压缩继续引用原持久快照，不自动补齐模型参数、修改清单或重放工具。

`todo_write` 的整体替换与 `todo_update` 的局部更新共用提交路径。首次创建无需版本参数，宿主在对话写锁内确认所选清单尚无提交记录后创建；显式提供 `expected_seq=-1` 或快照时仍严格核对。已有清单的更新和计划重新关联必须携带 `snapshot_token` 或 `expected_seq`，省略版本返回 `VERSION_REQUIRED`。已保存的空清单仍属于已有清单，不能绕过校验；并发首次创建只允许一个成功，不覆盖先提交的内容。

尚无任何清单记录、调用也没有显式指定清单、计划或快照时，宿主按本轮有效的计划批准选择首次建单作用域；读取与写入使用同一规则。已有活动清单和显式作用域不被自动更换。快照及证据必须归属于当前作用域，未关联计划的快照不能与另一计划混用；表面压缩不改变任务身份。

`todo_update` 使用任务粒度的安全合并：版本已变化时，先从当前对话日志恢复调用引用的确切基线，核对清单和计划归属；同时提供的令牌与序号必须对应同一快照。只有所有目标任务仍完整等于基线（包括正文、状态、计划和证据）才在写锁内合并到最新清单，保留其他任务与未指定字段。成功结果通过 `display.merged_from_seq` 及文本说明合并来源。任一目标变化则整个更新拒绝，删除的任务不会重建。整表 `todo_write`、`todo_bind` 和分页读取仍严格校验版本，不使用此合并规则，也不通过重试重放未知副作用。

读取、成功提交与冲突的 `current` 均返回 `write_arguments` 与 `update_arguments`，两者仅包含 `snapshot_token`。首次建单或整体替换使用 `todo_write` 加 `todos`；局部更新使用 `todo_update` 加 `updates`。宿主从快照恢复清单和计划，仍检查已保存的计划批准状态；不需要重复抄写 `list_id`、`plan_id` 或 `expected_seq`。未使用令牌时仍可用同一 `list_id` 与 `expected_seq`。轮次进度提醒使用同一 `TodoSnapshot` 生成上述参数，不单独推导快照或手工拼写计划 ID；这些返回字段不写入历史 `todo/write` 数据。

待办证据可使用 `evidence_seqs` 引用当前对话已记录的确切 `tool/result` 序号，或使用 `evidence_call_ids` 引用唯一调用 ID；两种方式互斥。数字序号可区分跨步骤复用的调用 ID，调用 ID 单独引用有歧义时仍拒绝。失败、裁剪、缺失或结果身份不一致的证据均拒绝，且整个清单提交保持原子性；空证据数组显式清除旧证据，省略证据字段保留原记录。持久化后的证据结构不变，不自动改写旧对话。

`todo_read` 返回最多 20 项最近成功结果的 `evidence_candidates`，含 `source_seq`、工具名与短预览；`next_evidence_before` 可原样传入 `evidence_before` 翻页。候选不自动证明某个任务已完成。无效或失败证据返回结构化 `INVALID_EVIDENCE`／`FAILED_EVIDENCE`、`updated=false`、固定所选清单的恢复入口与候选；`source_seq=-1` 的恢复指引明确使用 `todo_write` 建单，已有清单继续使用局部更新指引。提供的错误计划 ID 不被忽略或猜测修正，即使同时给出了有效快照也仍拒绝。

计划不存在或属于其他对话时返回 `UNKNOWN_PLAN`；写入或改绑目标尚未批准时返回 `PLAN_NOT_APPROVED`，附请求计划身份与当前状态。两者均为 `updated=false` 的结构化结果，携带所选清单的 `current` 和绑定确切快照的只读恢复参数。非活动清单的关联错误不能把恢复入口切换到活动清单；显式参数矛盾仍拒绝写入，不按相似 ID 猜测或自动更换关联。未批准计划的恢复指示不自动重试写入（`max_retries=0`）；普通冲突核对并合并后最多重试一次。

## 目标快照与用量归属

GoalStore的SDK读取及写入返回值与内部缓存隔离，调用方修改blocked_reason、completion深层证据或budget_reservations不会更新目标、推进修订或写盘。有效状态变更仍通过原CAS和持久提交入口完成。运行中的用量登记按对话ID、目标ID及请求ID共同归属；其他目标相同请求号的结算或清除不会将当前预留误标为未知。重开存储后的未结算用量仍按原规则显示未知，不自动重放请求。

目标从会话头恢复时还核对生命周期不变量：`complete` 必须覆盖全部成功标准，不能带阻塞、停止或待重试状态；`blocked` 必须有阻塞原因；预算预留不能超过目标预算。完成回执中的每条证据会按 `sourceSeq` 回到同一会话的真实成功工具事件，并逐字段比对保存的调用身份、输入摘要和结果预览。事件缺失、被裁剪或回执被篡改时拒绝恢复并保留原文件，不能把损坏状态投影为已完成，也不重放原工具。

读取投影另提供由现有字段推导的 `status`：`active`、`paused`、`blocked`、`usage_limited`、`budget_limited` 或 `complete`。`status` 不写回旧格式，也不替代持久的 `phase`；预算/用量刹车通过明确的 `stopReason` 映射，未知刹车保持 `paused`，不能从任意错误文本猜成限制类型。

## 恢复和副作用

进程重启后恢复对话与队列的权威记录；未完成运行按恢复策略标记中断。工具结果未知时不得重放命令、文件写入或外部写请求。前端遇到写请求超时先读回提交、队列或运行状态。

独立 MCP 执行器的图片交付在修改目标文件前持久保存`delivery_unconfirmed`及内容摘要、大小、尺寸、类型和文件标识，完整写入及最终回执保存后才变为`delivered`。中途失败保留未知状态和原异常，不因文件缺失重试交付；`harness_image_get`提供原交付信息供人工核实，不保存临时下载URL。交付回执核对原请求路径、内容版本与备份身份。

恢复范围只由已提交且唯一的 `turn/start.run_id` 确定，不通过运行结果反推身份。轮次结束之后的迟到事件和显式属于其他轮次或运行的事件不改变该轮次的恢复版本，也不进入文件审阅。缺少身份或开始记录重复时，恢复报告保留未知状态并要求核实，不迁移或改写日志。

每次工具执行独立保留证据，复用调用标识不覆盖前次执行。恢复成功状态要求精确配对的唯一原始结果；重复、缺失或格式不符的结果保持未知。宿主明确证明未执行的调用可排除副作用核实，但模型表面投影不能提供这种证明。工具报告成功也不能替代业务验收。

修复损坏数据之前先定位具体文件和错误，不自动清空运行目录，不使用数据库自动升级掩盖不匹配。

## 对话邀请与浏览器身份

邀请记录使用当前对话 `note` 事件 `collaboration/invitation`，只存邀请及领取秘密的摘要。批准是一条扩展的 `collaboration/access` 事件，包含邀请编号、稳定主体、显示名与能力；授权投影同时恢复已消费邀请。成员角色版本与加入周期分别记录：角色变更不使同一人的登录凭据失效，移除后重新加入不能恢复旧凭据或原邀请证明。分叉对话不继承原对话的访问授权及邀请。

访客申请的领取证明保存在当前标签页对话存储中，最长 24 小时；刷新后只回查审批，不重新申请。关闭标签页或存储不可用时不保证恢复。已兑换的 Cookie 可以按现有共享入口恢复阅读。

真人提交仍存储在原 `runs.sqlite3` 运行记录与幂等键事务中。`requester` 是提交时的服务端作者快照，`access_epoch` 绑定当时成员加入周期；恢复暂停队列时保留它们，执行前重新核权。公开消息来源从运行派生，原对话日志只记录实际执行产生的一条用户输入。浏览器复用已有草稿存储，按对话及真人主体隔离待确认请求；结果未知和刷新恢复只回查请求，不自动派工。

### 对话审批回执

`note` 中的 `collaboration/decision` 与原对话共存，记录对话、问题及其版本、可信审批者、成员加入代次、请求号、请求摘要和规范化答案。`recorded` 表示决定已落盘，不是工具成功、业务完成或重启重放指令。分叉中原对话的决定不会成为新对话的回执；移除后重新加入不能读取上一次加入的个人回执。

## 文件观察与恢复证据

文件观察的工具级回归见 `tests/test_file_write_boundaries.py`：读取后的外部改动、观察不存在后的外部创建、未观察已有文件及跨对话编辑均验证拒绝覆盖并保留磁盘字节；不据此保证全部外部写入竞态已被消除。

精确编辑在统一换行的文本上匹配，再按原始位置拼接。未编辑区间保留原始字符；替换内已有 LF／CRLF／CR 依次复用，新增行尾采用局部风格，插入优先采用前一行、文件开头采用后一行。编辑接缝不会把两个独立换行意外合并成一个 CRLF。回归覆盖混合行尾、逐处全量替换、等值编辑不写入、空文件、各插入位置和末尾换行。

运行恢复回归见 `tests/test_run_recovery.py`，覆盖暂停队列、已接受引导、非法排序不写回及主／成员归属隔离。恢复控制器构造期间不启动执行；未暂停的未完成运行持久标为中断，不能以恢复为由自动重放。

启用或关闭文件观察保护只影响对应宿主构造的文件工具，不会清空其他实例的内存观察，也不会修改持久日志。工具通过装配时的策略决定是否读取／生成观察及实施写入准入；策略不是工具调用参数。

通过 `build_fs_tools` 构造的每组文件工具独有无 Session 的 SDK 观察缓存，组内再按对话身份隔离。另一组的同名对话读取、写入或编辑失败不会授予、刷新或撤销本组的观察。携带 Session 的调用只更新该对象的观察记录，不写入 SDK 缓存；删除持久对话也不会清除同名 SDK 调用的记录。显式文件还原仍使所有存活对话及工具组对此目标的观察失效。回归见 `tests/test_file_observation_isolation.py` 和 `tests/test_file_policy_isolation.py`。

精确编辑原文失配时，工具结果的私有 `file_observation` 记录 `kind=invalidated`、当前目标路径和空版本；运行时与对话重放都只删除该目标的已有观察，不授予写入能力。失败结果只接受 `absent` 或 `invalidated` 证据，不能通过失败的 `present` 刷新观察。后续成功读取建立新的当前版本。恢复不根据错误正文、候选片段或当前磁盘推断历史观察，也不改写此前事件。回归见 `tests/test_edit_recovery.py`。

无模型执行器退出时，所有关闭调用等待同一清理任务；已接受任务收敛后才释放数据库和所有者锁。关闭等待者被取消不改变此顺序。清理失败仍返回错误，不能以关闭准入标记判断存储已经释放。

`RepositoryLease` 的锁文件与 `ExecutionStore` 的 `executor.owner` 文件在锁有效期间保持打开；关闭句柄释放锁，不删除锁文件。两者支持 `with` 和显式 `close()`，重复关闭安全。仓库任务由执行服务在任务完成或准备失败时释放租约；执行器在已接受工作收敛后关闭存储。数据库连接创建或初始化失败时，也会关闭已取得的所有者文件，避免失败实例继续占用存储。

## 三层记忆

`app/layered_memory.py` 在现有项目记忆之上绑定三种本地作用域。启用 `enable_project_memory` 时同时注册作用域工具和每轮次的动态注入；关闭时均不注册。

| 层 | 存储 | 工具 |
|---|---|---|
| 用户偏好 | 运行根 `memory/user.sqlite3` | `memory_recall(scopes=["user"])`；`user_memory_save/forget` |
| 项目知识 | 项目 `.harness/memory.sqlite3`，同仓库工作树共享 | `memory_recall(scopes=["project"])`；`memory_save/forget(scope="project")` |
| 对话笔记 | 运行根 `memory/sessions/<对话编号 SHA-256>.sqlite3` | `memory_recall(scopes=["session"])`；`memory_save/forget(scope="session")` |

工具共14个：共享只读 `memory_recall/check/archives/archive_search`，项目／对话写入 `memory_save/forget/consolidate/archive/restore`，以及独立用户写入 `user_memory_save/forget/consolidate/archive/restore`。启用可选语义候选时增加一个 `memory_candidates`，共15个。常用的recall及两类save/forget共5个直接提供；其余维护工具在auto模式通过 `search_tools` 按需加载，即使目录较小也不预先发送完整定义。显式all模式或没有可用发现工具时直接提供全部当前可见定义，发现不改变执行权限。没有旧工具别名或存储迁移。

`memory_recall` 的可选 `scopes` 是非空且不重复的作用域列表，默认查询当前已绑定的session/project/user；显式选择未绑定层时报错，不自动切到其他项目。每层读取一次，最多取得100个候选；在合计最多300个候选中统一关键词排序或多查询排名融合，再应用合计 `limit`（默认20，最大100）。结果逐条带 `scope/id/revision`，相同ID在不同层分别保留；并非三层跨库事务快照，显式检索某层失败会返回错误，不伪装为完整结果。单层维护和写入使用必填 `scope`；用户写工具不接受scope覆盖。其他回执顶层带scope，核验及语义候选也逐条标记scope。翻页保持相同scope、查询和筛选，不能将一个作用域的游标用于另一个作用域。

用户层代表当前运行根的本地用户，不是多租户账户隔离。用户层写入标记为 `external_write`；项目和对话写入为 `workspace_write`。写工具声明真实数据库路径，受工作树范围限制的成员不能借记忆工具写入范围之外。对话编号由工具上下文绑定，模型不能选择另一对话或存储路径。

自动注入默认共 8000 字符，用户、项目、对话分别保留四分之一、二分之一、四分之一的初始份额；完整包装、分隔符和转义计入预算。空层、未绑定层和没有当前候选的层把份额按1:2:1权重分给有候选的层；读取失败的层保留自己的提示份额。候选指固定条目或匹配当前查询的条目。各层只读取一次，分配与选择复用同一份记录。已有候选但条目过大的层仍保留份额，不逐条拆分正文；这仍可能留有空余。固定条目优先，按当前用户消息召回至多五条其他相关记录。未固定且不匹配当前任务的资料仍可通过对应 recall 工具检索。容量以字符计，不宣称等价于 token；目前是本地关键词匹配，没有向量模型依赖。

历史资料不提供新授权、执行回执或完成证据。单层损坏保留原文件并显示该层未召回，健康层继续可用。空读取不创建数据库，不自动把对话全文蒸馏为长期事实。记录支持来源、证据和 revision；更新及删除要求当前版本。三层导出分别使用 `harness-user-memory-v1`、`harness-project-memory-v1`、`harness-session-memory-v1`，跨层导入拒绝，防止误扩大资料共享范围。此改动不迁移或重写现有项目库。

召回选择由 `app/memory_context.py` 集中实现。`ProjectMemory.preview()` 与 `LayeredMemory.preview()` 生成带文本的内部结果及不含正文的 `explain()`；原 `context()` 只返回同一计算路径的文本。解释保存条目 ID 与 revision，便于区分后续修订；它不是事实真实性或业务完成的证明。默认不持久化预览，不生成额外记忆库或日志正文。

### 文件来源与重新核实

`memory_save(scope="project"或"session")` 的可选 `source_files` 接受最多3个当前项目文件。调用前必须由同一对话成功读取来源；宿主从对话的文件观察账本取得版本，不接受模型自填哈希，不使用其他对话或 SDK 工具缓存补证。`evidence` 的说明与来源封装为当前 `harness:file-sources:v1` 数据，仍写入原 evidence 字段，合计不超过1000字符；不迁移数据库。

普通文字 evidence 保持文字资料。具有文件来源的记录在自动召回及 recall 工具中增加 `source_check`；预览引用的 `source_status` 只返回状态，不返回路径或正文。`unchanged` 表示与记录的 SHA-256 前16位版本一致，`changed`/`missing` 提醒重新读取；`unsafe`/`unavailable`/`unchecked`/`invalid` 表示未能建立匹配，不能当作正确或错误结论。记录本身仍是历史主张，导入文件和人工编辑不能因为填写了指纹就成为可信事实。

来源以当前工作树根下的相对路径定位，避免共享记忆库误读主工作树版本；路径穿越及逃逸链接不核验。每层每次计算最多检查8个不同文件、每文件512KiB、总读取2MiB，结果只缓存到本次计算。大文件或超预算标为 unchecked。核验不改写记忆、不自动删除旧结论、不刷新文件观察或授予写入权限。这里是应用层的有界检查，不是对恶意本地文件系统竞态的操作系统沙箱保证。用户偏好层不捕获或核验项目来源。

### 受控整理

智能体可调用 `memory_consolidate(scope="project"或"session")` 或 `user_memory_consolidate`，提交2至6条同一作用域记忆的 `id`、当前 `revision` 以及整理后的 `content`。用户偏好整理要求明确的用户请求。服务在一个 SQLite 事务内校验全部输入，创建默认固定的摘要，取消原输入的固定状态；原输入正文、主题和来源保留。被取消固定的条目 revision 增加1。工具声明与对应 save 相同的真实写路径及副作用类别。

摘要 evidence 使用 `harness:consolidation:v1` 记录确定性请求身份、说明及整理前后的版本引用。相同输入版本和内容的重试返回 `replayed=true`，不重复取消固定或创建摘要；摘要已经被修改时拒绝覆盖。版本冲突、容量不足、重复内容或证据超限均整批回滚。整理回执只说明该操作及其引用状态，不证明摘要事实正确。

正式召回和预览返回 `derivation_status`：`none|current|changed|missing|invalid|unchecked`。`current` 只表示引用的版本仍匹配。父条目被修改或删除时，摘要保留并提示重新核实；来源文件核验会穿透当前有效引用，文件变化也使摘要要求核实。展开限制为8层、32个叶来源，循环或超限标记invalid。不会按正文相似度补找缺失身份。

当前导出包含条目身份与版本；显式导入会保留提供的有效 `id`/`revision`（编号为 `mem_` 加32位小写十六进制字符），未提供编号的条目正常生成新编号。同编号不同内容不覆盖；原本完整的整理引用若因身份冲突不能保持完整，则整批导入拒绝。重复导入保持幂等，现有数据库不迁移。导入的是记录中的主张，不是新的授权或已核验事实。

自动注入只在摘要实际选中、输入版本有效且来源检查未要求重新核实时，抑制它覆盖的未固定输入。摘要超预算、失效或来源未核实均保留原条目；后遇到的摘要只有在最终完整包装可放入预算时才替换先前输入。被覆盖的查询条目不消耗五条查询名额。用户重新固定的输入及当前显式查询的完整编号不被抑制。此选择不删除资料，recall 工具仍可检索原文。

召回解释的 `suppressed` 列表仅返回输入的 `id`、`revision` 及实际选中摘要的 `summary_id`、`summary_revision`，不携带正文。未匹配查询的输入仍计入 `unmatched`；各项计数与已选、预算跳过、查询限额跳过合计等于当前总记录数。

显式输入完整 `mem_` 编号时，关键词召回只解析对应条目；不会把正文或证据中提到该编号的摘要当作来源。可用现有 recall 工具或界面搜索直接回查整理输入。

英文关键词与标识符按完整词匹配，避免把 `API` 匹配为 `rapid` 或把 `port` 匹配为 `export`。单独输入相对文件路径时按整体路径匹配，不使用公共目录或扩展名替代缺失路径；普通混合问句仍按关键词排序。中文保留连续短语与双字片段召回。当前不提供标识符前缀补全、同义词或跨语种语义保证。

当前结构化依据只以人类说明和文件来源路径参与关键词排序，整理请求身份、输入编号、版本数字及指纹不作为相关性依据；完整记忆编号仍按对应条目身份查询。已知格式损坏时不索引原始机器字段，正文与主题仍可检索，原始证据保持存储不变并由来源核验报告错误。普通文本证据继续参与搜索。

统一的 `memory_recall` 工具支持 `queries`：1至4个非空查询，每个最多500字符，与 `query` 互斥。智能体可提供同义、跨语种或源码术语改写；服务不额外调用模型或发送资料到外部索引。每层的各查询复用一次数据库快照，分别取前100条，以 `1/(60+排名)` 相加融合形成该层最多100条候选；跨层合并后再按各查询排名融合，稳定排序并应用最终合计limit。重复改写按去空白和大小写归一去重，不增加权重。多查询结果中的 `query_matches` 返回命中的零基查询序号；原文、版本及来源核验保持原有规则。改写词的生成和质量由调用智能体决定，不保证语义召回率。自动提示注入及HTTP搜索仍使用当前单查询选择。

智能体可用 `memory_check(scope="session"或"project"或"user")` 回查候选引用。`references` 包含1至6条不同编号，每条须提供 `id`、当前 `revision` 和不超过1000字符的非空逐字正文 `excerpt`。服务只读一次作用域快照：记录缺失返回 `missing`，版本不同返回 `changed` 和当前修订，指定版本没有摘录返回 `excerpt_missing`；这些情况不返回替代正文。版本与摘录均匹配时返回 `matched`、原文摘录、Unicode字符位置 `start/end`（左闭右开），以及当前来源和派生检查。一次核对后的并发变更仍需按版本重新核查。

核对回执的 `meaning=record-excerpt-only` 表示记录摘录核验，不能证明事实正确、摘录支持某个推断或当前问题已有答案。例如“数据库损坏时保留文件”即使匹配，也不能回答备份保留期。工具不推断蕴含关系，不授予权限，不更新事实可信度，不自动修改存储；实际工具回执沿用对话事件持久化。

设置中的三层记忆面板可按需展开“自动召回解释”：显示三层预算、使用字符、选中/超预算/摘要覆盖/查询限额/未匹配数量，以及最新用户消息的查询序号。记录身份、来源和派生状态、覆盖关系默认折叠；解释不复制记忆正文、查询文本或来源路径。它是读取当时的快照，不是先前模型请求的消费回执，记忆或消息变化后应手动刷新。展开与刷新才读取；关闭解释、切换记忆作用域或离开面板取消请求并丢弃迟到响应，不在隐藏状态轮询。

设置中的三层记忆面板将当前格式的文件依据和整理依据显示为说明及版本列表，原始依据默认折叠，支持键盘展开。编辑来源说明时保留文件指纹、整理请求身份和输入版本引用；未改说明时保留原始依据字符串。说明与引用合计超过1000字符时暂停保存，缩短说明即可继续。未知或损坏格式保持原文显示及编辑，不擅自转换。 当前文件来源JSON的任意对象拒绝重复字段，路径或版本身份有歧义时标为invalid，不读取候选文件、不以最后一个值覆盖原证据。列表显示的是记录中的版本，当前文件状态仍由实际召回时的来源核验确定。

### 活动记忆的显式导入合同

`ProjectMemory.import_data` 与当前记忆HTTP导入入口接受当前层的 `format` 和 `memories` 列表；每条正文 `content` 必填，省略 `topic`、`pinned`、`evidence`、`source` 时分别使用 `project`、`false`、空字符串和 `import`。省略身份时创建新记忆ID，省略修订号时使用1；显式提供的类型、身份和修订仍严格校验。这是当前显式批量创建合同，不能仅凭默认值认定为旧格式兼容并删除。带身份的导出/导入继续核对ID的正文与主题冲突，并保留传入的有效修订号，批次写入在一个事务内，容量或冲突失败不留下较早条目；这与下文只合并归档、不激活活动记忆的 JSONL 归档入口不同。

## 显式记忆归档存储服务

`harness.app.memory_archive.MemoryArchive`提供活动记忆与历史归档的存储级移动和恢复，智能体也可通过同作用域工具显式调用；当前尚无HTTP和管理界面入口，不会自动归档、清理或迁移已有记录。SDK可在明确的用户操作中使用：

```python
from harness.app.memory_archive import MemoryArchive

archive = MemoryArchive(app.layered_memory.store('project', session_id=session.id))
receipt = archive.archive(project_root, [{'id': memory_id, 'revision': current_revision}])
page = archive.list(project_root, limit=20)
restored = archive.restore(project_root, memory_id, current_revision)
```

同一服务可绑定用户或对话存储，归档文件由可信存储位置派生：`memory.sqlite3`对应`memory.archive.sqlite3`，`user.sqlite3`对应`user.archive.sqlite3`，对话摘要文件同理。每个归档库是独立当前格式，不改活动库schema。空读取不创建库，归档和恢复才初始化所需新库；已有格式不符或损坏时拒绝并保留文件。

一次归档接收1至6条不同id及当前revision，在单个附加数据库事务内将完整原文、主题、固定状态、来源、证据、时间与版本保存到归档后移出活动库，释放活动容量。两库均须使用DELETE/TRUNCATE/PERSIST回滚日志模式；连接使用FULL同步。不接受WAL/OFF/MEMORY，也不隐式改日志模式。事务的跨文件原子性依赖SQLite支持条件和底层存储正确实现同步，不代表已做断电硬件验收。取消固定不是归档，已归档记录不进入现有自动注入、recall或语义候选。

活动摘要若引用拟归档条目，必须在同批包含相关摘要；损坏的活动整理引用也阻止未经核查的移动。版本冲突整批回滚。重复同一归档请求不会重复保存历史快照；重新恢复后的版本会提高，旧归档请求不能移动它。归档保留历史版本，列表按稳定seq倒序，可用next_before显式翻页，不自动合并到当前事实。

恢复只接受该id最新归档版本，不覆盖当前冲突记录，也不绕过活动容量限制；相同正文/主题由其他id占用时拒绝。恢复保留原文与证据、提高revision并更新时间，历史归档继续保留。重复恢复在活动记录仍为恢复版本且内容未变时返回replayed；更新后不重新覆盖。恢复摘要可能因输入已提高版本而要求重新核实，不会替换历史引用来伪造当前有效关系。历史资料、恢复成功和归档回执均不证明事实或授权。

智能体通过 `memory_archive` / `memory_restore` 的必填 `scope=session|project` 选择写入范围；用户写入保留独立 `user_memory_archive` / `user_memory_restore`。统一只读工具 `memory_archives` 用必填 `scope=session|project|user` 选择历史。archive提交 `inputs=[{id, revision}]`；archives可传 `before` 与 `limit`，也可用 `memory_id` 精确筛选同一记忆的历史版本（翻页保持相同身份；正文提及该身份不会匹配）；restore提交 `memory_id` 与 `archived_revision`。模型不能选择数据库路径或另一个对话身份。归档和恢复声明活动库与归档库两个实际写入路径，沿用已有审批、执行前复核和路径协调；用户偏好属于external_write，项目/对话属于workspace_write。任务只读模式拒绝写操作，历史读取属于read。写结果未知时先读取对应recall及archives，不自动重放归档或恢复；已提交工具结果沿用对话日志，不把历史快照当作当前事实。

归档内容检索使用 SDK `archive.search(project_root, query, before=None)`，以及统一只读工具 `memory_archive_search(scope="session"或"project"或"user")`。query 为1–500字符的非空关键词，沿用活动记忆的中英文词边界、完整ID和路径匹配；不调用嵌入模型。每次按归档序号倒序扫描最多100条，在当前页内按相关性排序，保留同一身份的不同版本。`scanned` 是扫描数量；即使 `archives` 为空，`next_before` 非空仍表示需要继续扫描，翻页保持相同query。游标只向更早序号推进，新追加历史需要从首页重新查询。结果含历史原文与版本，`meaning=historical-keyword-candidates-only`；不会自动恢复、注入上下文、核实当前文件或赋予历史内容执行权限。

归档备份可调用 `archive.export_jsonl(project_root, stream)`：stream 为调用者提供的 UTF-8 文本写入流，SDK不选择路径、不覆盖文件、不清理失败产物。显式文件备份示例（destination由调用者确定）：

```python
import os

with open(destination, 'x', encoding='utf-8', newline='') as stream:
    receipt = archive.export_jsonl(project_root, stream)
    stream.flush()
    os.fsync(stream.fileno())
with open(destination, encoding='utf-8', newline='') as stream:
    verified = archive.verify_jsonl(stream)
assert verified == receipt
```

独占模式`x`拒绝覆盖已有文件；失败保留产物供检查，不把它当作成功备份。导出是单一SQLite读快照，按seq递增流式读取，不将整个归档加载内存。头记录绑定当前用户/项目/对话格式，逐条保留seq、archived_at及完整记忆版本；尾记录包含count及此前所有UTF-8行（含换行）的SHA-256。verify_jsonl逐行最多读取65536字符，校验帧结构、作用域格式、记录字段、递增seq、计数、校验和及无尾随数据，返回相同回执。它不证明来源真实性，也不保证重复id/revision的全库唯一性；SHA-256不提供签名认证。缺少尾记录、内容改变或格式错误会明确拒绝；底层流I/O错误直接传播。空归档导出不创建数据库。当前提供SDK导出、验证与显式导入（见下文），未提供智能体文件写入工具，不替代活动记忆备份。

归档导入使用 `archive.import_jsonl(project_root, stream)`，只接受上述当前作用域格式。它逐帧校验并暂存到本次操作专用的临时SQLite库，检查完整尾记录、重复JSON字段、重复身份/版本、整数范围及有序序号后才打开目标归档库；校验失败不创建目标文件。临时库在操作结束后关闭并移除，不触及输入文件。空备份不初始化目标。目标使用现有归档日志模式约束（DELETE/TRUNCATE/PERSIST），不自动转换WAL等模式。

```python
with open(backup_path, encoding='utf-8', newline='') as stream:
    receipt = archive.import_jsonl(project_root, stream)
# receipt含count、sha256、imported、replayed；导入不会自动恢复活动记忆。
```

所有合并在一个目标库写事务中完成：相同id/revision的原文和archived_at必须完全一致，才计入replayed；否则整批回滚，包含本批较早插入的新记录。新增记录保留原文、版本与归档时间，seq重新分配为目标库本地分页游标，因此重新导出后的字节校验和可能不同。输入文件的校验和只证明内容完整，不证明来源真实性，调用者须明确选择可信来源和目标项目/对话。不同项目或不同对话共享对应层的格式标识，不提供来源身份认证。导入不写活动记忆、不改历史来源引用、不绕过显式restore的最新版本与冲突检查，不自动迁移或清理既有数据。已有目标库损坏时保留原文件并报错；当前提供SDK和本地CLI入口，无HTTP或智能体导入工具。

本地命令行无需API key或模型宿主即可使用相同能力：

```sh
python -m harness.cli --cwd /path/to/project --memory-export archive.jsonl
python -m harness.cli --memory-verify archive.jsonl
python -m harness.cli --cwd /path/to/project --memory-import archive.jsonl
python -m harness.cli --memory-export user-archive.jsonl --memory-scope user
python -m harness.cli --memory-export session-archive.jsonl --memory-scope session --memory-session SESSION_ID
```

作用域默认project，用户与对话存储沿用`HARNESS_HOME`（未设置时为`~/.harness`）；对话层必须显式给出非空对话身份，其他层禁止携带该参数。导出独占创建文件并flush/fsync，已有文件或父目录不存在时报错，不覆盖或自动创建父目录。校验/导入也须选择对应的memory-scope，导入不会激活历史。命令成功只输出JSON回执（operation/scope/file/count/sha256及导入计数），失败退出2并保留输入或失败产物。文件动作与提示词、UI、状态、ACP代理和运行配置选项互斥，避免操作被忽略或意外启动智能体；`--cwd`与`--language`可同时使用。CLI为本地操作者显式入口，智能体工具的审批与作用域控制保持原样，未增加HTTP入口。

可用隔离的合成规模评估复核归档SDK，命令不读取用户数据库：

```sh
python scripts/evaluate_memory_archive.py --sizes 100 10000 --content-chars 1024 --output archive-scale.json
```

输出文件必须不存在。fixture使用固定身份/版本/时间及指定长度正文，记录fixture与源码SHA-256、Python/SQLite/平台信息、备份字节数；逐项测量导出、校验、新库导入、重复导入和重导出，并核对完整产物字节一致及未创建活动库。耗时含tracemalloc探针；python_peak_bytes仅为Python受追踪分配，不含SQLite/系统原生分配。Windows另通过GetProcessMemoryInfo记录process_before/process_after快照，包括当前工作集、私有提交量和进程生命周期峰值；其他平台明确返回unavailable。进程指标包括解释器、原生分配及已加载模块；生命周期峰值包含fixture创建、先前操作和先前规模，不能当作单个操作的新增峰值。当前工作集快照不是操作期间的采样峰值。单样本不提供延迟分位数，不含fsync、断电或真实项目负载验收。输入规模与输出校验不能替代完整生产压测。

### 记忆删除的确认边界

设置中的记忆删除先显示内联确认，取消不写入；确认绑定当前对话、记忆层、记录编号和修订号。切换作用域或记录修订变化后，旧确认不能用于删除当前记录。面板限制同一作用域的一次操作在途，旧作用域的迟到结果不能清空新作用域的操作锁或编辑内容。删除仍使用服务端修订比较，结果不确定时只读回查，不自动重发。

## 格式校验的维护边界

新增当前格式读取要检查真实生产者、全部读取入口与公开协议，区分不存在和损坏；拒绝时保持原字节。不得为通过回归而把损坏数据自动初始化、字段缺失补默认值或未知状态改成成功。学习窗口缓存 `context-windows.json` 只接受整数版本1及完整有效的端点/模型窗口表；仅缺失文件返回空表，损坏、非法编码和读取失败明确报错，保留原件。保存前校验现有文件和整表，使用独立临时文件原子替换，写入失败向调用方报告。文件系统和多文件事务保证仍以对应实现及平台证据为限。

模型能力缓存 `model-capabilities.json` 保存当前版本的 models 与 learned 映射，完整校验容量、时间和能力字段；时间戳必须在零到当前时间之间且为有限数值，超出浮点范围的整数按损坏缓存拒绝。损坏或读取失败明确报错并保留原件；学习和目录刷新均先保存再发布内存，保存失败不标记刷新成功，下一次显式请求仍可尝试。远端目录发现失败保留已有能力，不等同于本地格式错误。

## 模型供应商配置

`HARNESS_HOME/model-providers.json`（默认 `~/.harness/model-providers.json`）保存版本 2 的供应商、接口、模型与凭据。缺失时为空列表；损坏或版本不符时保留原文件并明确报错，不转换历史文件。保存使用独立临时文件、原子替换、旁路文件锁和完整内容的 SHA-256 修订比较。请求使用深复制快照，运行中的 Key 租约独立于编辑草稿。账号池在该运行目录下的 `codex-gateway` 保存当前账号及自动切换设置，显式 `HARNESS_CODEX_GATEWAY_HOME` 仍可覆盖账号目录。

## 浏览器本地偏好

浏览器偏好使用 `harness.` 命名空间；自动化创建的待确认记录使用 `harness:automation-creation:<编码后的对话ID>`，由 `web/src/lib/automationCreation.ts` 管理。主题、字号、侧栏分组和折叠状态分别使用 `harness.ui-theme`、`harness.ui-font-size`、`harness.sidebar.group-by` 和 `harness.sidebar.collapsed`；已有带 `.v1` 后缀的键保持原名。首屏脚本、应用状态和未构建提示页使用同一主题键。不读取或自动迁移旧前缀下的偏好，也不清理用户浏览器中的旧数据；新键没有值时使用对应默认设置。

浏览器输入草稿以 `harness.drafts.v1` 存入 localStorage，保存正文、结构化附件引用，以及当前编辑来源、智能体/团队选择、执行模式、目标创建参数和待确认提交身份等状态；不保存附件原始文件。队列编辑与撤回草稿以 `harness.queue-edits.v1` 存入当前窗口的 sessionStorage；撤回队列后按原引用恢复可单独移除的附件。旧的隐藏附件上下文字段不属于当前草稿格式，格式拒绝时不自动迁移旧字段。队列编辑草稿的操作字段及运行元数据名称以当前生成协议为准，不通过接受任意附加字段容纳退役格式。

草稿读取、写入与删除都会检查现有持久化格式。输入草稿格式无效时，先将原始字节隔离到同一浏览器的 `harness.drafts.v1.invalid.<随机身份>`，读回确认后清除活动无效记录，恢复当前格式保存；隔离失败不清除原件，新编辑仍保存在当前页面内存。该过程不恢复旧字段或重发待确认请求。写入失败后的读取也优先保留未保存编辑或删除意图，不用旧磁盘值覆盖。服务重启本身不处理浏览器数据；隔离发生在当前页面的草稿存储读取边界。新建对话必须先可靠保存创建请求身份，无法保存时阻止发送，避免丢失响应后重复创建。

## 浏览器恢复草稿的提交收尾

恢复预览的检查与继续指令按对话、原运行和浏览器窗口保存，核实决定不恢复。提交成功只删除与提交时快照一致的该模式指令；比较指令、来源版本，并在继续模式比较核实说明。用户重新打开后修改的草稿、另一种恢复指令及其说明保留。取消只读分页会阻止旧预览覆盖新预览；已接受的恢复提交继续完成，关闭页面后不回调旧界面。

## 删除等待期间的本地内容

对话删除开始时捕获该对话的输入草稿、待恢复提交、队列编辑/撤回及Git提交说明。确认删除后，仅当这些内容仍属于同一快照时执行原本地清理；等待期间发生变化则保留整份相关本地内容，不转移到其他对话、不自动重发。其他对话的编辑不阻止原快照清理。

发生保留时，当前窗口显示需手动关闭的通知，提供下载当前保留快照的操作。下载包含原对话ID、草稿/队列/提交说明，以及附件的当前引用和元数据；不是附件原始文件的独立备份，也不自动创建或恢复对话。下载和关闭通知均不删除保留数据，既有浏览器存储归属不变。

Git提交草稿存储含损坏JSON、非对象或非法/超长说明时，页面报告损坏并保留原始存储，不把过滤后的对象写回。新编辑仍保留在当前页面内存；关闭或刷新前应复制文本。该状态不提供会覆盖原件的保存重试；普通存储写入失败仍可重试。没有自动修复、清理或迁移。
