# 语音输入与全局听写

Harness 将 Hex 作为内部语音识别引擎；录音、输入框草稿、全局听写设置与浮窗由 Harness 自己管理。桌面安装包必须包含本机引擎，不要求用户另行安装或打开 Hex。官方预编译引擎与其许可证随版本库分发于 `harness/resources/hex/<平台>-<架构>/`，仓库内不含引擎源码，打包时也不编译；运行时不隐式编译、安装独立应用或修改已有 Hex 配置。

## 输入框与模型

麦克风位于发送按钮左侧，点击开始录音，再次点击结束并转写；输入框聚焦时也可用 `Ctrl+Shift+Space`。按键自动重复、输入法组合事件及键码 229 不触发操作。声波使用真实麦克风音量，静音回落，不播放循环动画，也不改变转写音频。录音最多 60 秒，达到上限自动结束。

浏览器在内存中生成单声道、16 kHz、PCM16 WAV，再交给本机后端。文字追加到当前草稿，不清空原文或自动发送。切换对话、切走再切回、重建草稿、隐藏页面、禁用入口及卸载都会释放所属录音资源；已受理的转写继续收尾，迟到结果不进入替换对话。浏览器需支持 AudioWorklet，并允许麦克风及安全来源访问。

`POST /api/v1/voice/preparations` 是显式模型预热入口，接受空正文或空 JSON 对象；合法请求等待实际准备，不能直接以 ready=true 短路。浏览器和 API 等待预算均为 630 秒，包含服务启动及模型准备；引擎服务启动等待为 15 秒，准备请求的 HTTP I/O 超时为 600 秒。首次下载／加载可能超过普通 API 的等待时间，客户端自设 15 秒超时不能证明服务挂死。超时或取消等待不保证底层操作已撤销，也不自动重发预热。

默认模型为 `whisper_large_v3_turbo`，语音语言为 `auto`，独立于界面语言。麦克风就绪并开始录音后，输入框和全局浮窗提前准备模型，录音无需等待准备结束；停止后等待同一次准备成功再提交音频。打开设置和等待麦克风授权不准备模型。模型未准备时按需下载，已下载内容由引擎复用，推理在本机完成。准备与转写显式传递同一语言，避免引擎默认英语与 `auto` 选择不一致造成模型切换。转写期间显示通用处理状态，不因开始新一次录音就宣称首次使用或正在重新下载。麦克风失败、缺少引擎、无语音及后端失败分别显示资源型错误，技术详情保留原诊断；同一实例切换英文→中文→英文不重放录音或转写。

## Harness 全局听写

在桌面应用打开“设置 → 语音输入”，选择启用状态，点击快捷键框并直接按下组合键，再点击保存。快捷键框只捕获按键，不接受文本编辑；单个字母、单独修饰键、自动重复及输入法组合输入不覆盖已有组合，Tab 保留焦点导航。默认组合在 macOS 显示为 `⌃ + ⌥ + Space`（Control、Option、空格），在 Windows 显示为 `Ctrl + Alt + Space`；按一次开始录音，再按一次结束并转写。快捷键字段、输入框快捷键说明与默认说明共用平台格式化，捕获结果保存为 Electron 加速键，未修改的已存组合保留原值。打开设置只读取状态，不注册新快捷键、录音、下载模型或开启其他应用。普通浏览器保留输入框录音，并说明跨应用听写需要 Harness 桌面应用，不提供独立 Hex 安装入口。

全局录音使用独立、不可夺取前台焦点的 Harness 浮窗，与输入框复用 WAV 编码、真实音量及本机转写接口。浮窗支持停止和取消；转写已被后端受理后，关闭观察只使结果失效，不宣称撤回后端操作。新操作以独立 id 管理，旧结果不能覆盖新的录音。浮窗重新加载、崩溃或关闭会撤销其录音归属，不重放音频或插入。

浮窗页面的语言和主题存储监听独立于桌面桥；普通浏览器中的“需要桌面应用”提示也跟随当前界面语言，并同步 HTML lang，卸载后撤销监听。没有桌面桥时不录音、不准备模型、不转写。

已知授权拒绝等自有错误仅通过资源身份提供双语引导，不把内部错误名称或重复英文提示放入技术详情。真实底层错误的诊断原文仍经主进程回执及浮窗保留；切换语言只更新呈现，不重新申请权限、录音或转写。

转写文字先复制到剪贴板，再按原目标处理：

- 原目标为 Harness 输入框时，经主窗口回执直接追加草稿，不模拟系统粘贴，不发送消息。校验输入框实例、对话、草稿修订、操作代次、焦点及组合输入状态；切换后再返回原对话也不能接收旧结果。同一插入 id 不重复追加。
- 原目标为其他应用时，macOS 核对前台应用 PID，Windows 核对前台窗口句柄；结束时目标与起始目标不一致，或仍有修饰键按下时只保留剪贴板，不注入按键。系统权限的申请、拒绝后重试及辅助功能授权入口见 [系统权限与再次授权](../desktop/README.md#系统权限与再次授权)。
- 系统发送粘贴按键只报告已请求，不能证明目标应用已插入文字。回执未知或原生失败保留剪贴板结果与诊断，不自动重试粘贴或草稿插入。

快捷键偏好保存在 Electron 用户目录的 `voice.json`，仅保存开关与组合键，不保存录音或转写正文。只接受当前格式；损坏原件保留并明确报错。保存核对原字节，拒绝已观察到的外部修改；更换快捷键失败保留原注册，文件写入失败撤销本次新注册。该检查不保证与无锁外部编辑器之间的原子 CAS。关闭页面不撤回已接受保存；结果未知时只回查状态，不重放写入。

退出 Harness 会停止快捷键准入，等待已开始的插入收尾，释放浮窗，再关闭后端所属服务。它不停止用户独立运行的其他 Hex 实例，也不设置开机启动或改写其快捷键。

## 构建与分发

桌面准备由 `desktop/prepare-voice.mjs` 核对真实 Mach-O／PE 文件头、操作系统、CPU 和内容身份，再编译 macOS 粘贴辅助程序或包含 Windows 辅助脚本。麦克风用途说明使用双语资源，写入应用元数据及本地化 `InfoPlist.strings`。引擎、辅助程序及独立录音页面都属于安装包必需资源。

桌面打包直接使用随版本库分发的官方预编译引擎 `harness/resources/hex/<平台>-<架构>/`（当前 macOS arm64 与 Windows x64 均为 3.3.0），**不在打包时编译引擎源码**，因此不需要 Rust／C/C++ 编译器／CMake／MSVC／Vulkan SDK，也不需要设置 `HARNESS_HEX_BINARY`：

```sh
npm --prefix desktop run package -- --x64
```

升级或新增平台引擎的标准入口是 `node scripts/vendor-hex-engine.mjs`（流程见 [Hex 资源说明](../harness/resources/hex/README.md)）。已有合法的自备引擎时，可用 `HARNESS_HEX_BINARY` 显式覆盖取件来源：

```sh
HARNESS_HEX_BINARY=/absolute/path/to/hex \
HARNESS_UPDATE_REPOSITORY=lengweiping1983/SuperHarness \
npm --prefix desktop run package -- --arm64
```

`harness/resources/hex/` 是源码运行和打包的唯一引擎资源目录，同时保留各平台子目录；不再创建第二份源码工作副本。wheel 仅包含本机平台的引擎、许可证和清单，sdist 保留全部平台资源。显式自备引擎只覆盖安装暂存副本，不改写版本库资源；桌面运行时记录相对路径、系统、CPU 和 SHA-256。从版本库引擎取件时还会记录版本与来源（`engine.json` 清单），打包前重新核对实际文件身份、内容与版本，不一致直接拒绝打包；校验实现见 `desktop/hex-engine-manifest.mjs`。准备阶段还在临时数据目录中直接启动随包 `hex service --embedded`，完成带认证的健康检查并关闭，不访问用户 discovery、下载模型或录音。这证明随包服务可以启动，不能代替麦克风、识别质量或系统粘贴验收。

SDK／源码未携带引擎时仍可显式复用已有 Hex 安装。Windows 指针读取有界，拒绝损坏版本及越界路径；有随包引擎时不读取外部安装指针。用户模型、历史、配置和损坏 discovery 均不自动清理或迁移。默认数据位置仍遵循 Hex，`HEX_APPLICATION_SUPPORT_DIR` 可显式覆盖。

## 本机接口与服务所有权

输入框与全局录音浮窗共用 `POST /api/v1/voice/transcriptions`：原始 `audio/wav`，最多 2 MiB、单声道 PCM16、16 kHz、60 秒，返回原文 `transcript`，不自动提交消息。接口拒绝非回环来源和共享身份，响应不缓存。公开契约、生成浏览器类型与响应验证沿用协议源。

`POST /api/v1/voice/preparations` 使用相同本机边界，显式准备默认模型和语言，成功返回 `ready: true`，不录音或转写。管理器按认证端点、模型和语音语言复用已确认的成功，避免每段音频再次预热推理；并发准备与转写共用所属锁，端点变化、转写失败和关闭后不沿用旧成功。准备失败或结果未知时，原录音操作不自动重复准备或上传；取消、切换对话及关闭页面使原结果失效，后端已接受准备仍完成所属收尾。

转写成功的 `Server-Timing` 响应头分别记录 `voice_queue`、`voice_prepare`、`voice_inference`，单位为毫秒，用于区分管理器排队、准备和引擎请求耗时，不包含音频和转写正文。引擎请求计时包含本机 HTTP 及引擎内部等待，不能直接当作纯计算耗时。语音接口返回 `route/not-found` 时，界面提示检查运行后端与应用版本并重启，不增加旧路由兼容或自动重放请求；当前路由是否可用仍应核对实际运行服务。

`GET /api/v1/voice/dictation` 只读报告平台、CPU 准入 `cpu_supported`、引擎是否可用 `available` 及资源型原因，不宣称模型或权限就绪。Windows 引擎要求 AVX2，后端通过 [`IsProcessorFeaturePresent(PF_AVX2_INSTRUCTIONS_AVAILABLE)`](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-isprocessorfeaturepresent) 查询系统实际提供的能力，不启动 Hex 试探，也不按 CPU 名称推断；其他平台不要求 AVX2。该系统标志由 Windows 10 2004 及以后版本支持，系统未报告支持或查询失败时不开放语音入口；查询失败使用独立的错误资源。

界面在确认 CPU 准入后才挂载输入区录音按钮及其快捷键，并在设置导航、搜索、定向页面和命令面板提供语音输入页。Windows 不支持 AVX2 或能力尚未确认时隐藏这些入口；引擎缺失与 CPU 不支持保持区别，支持的机器仍可查看引擎缺失提示。能力观察只在相关界面可见时进行，关闭或隐藏后的迟到结果失效。桌面主进程在恢复已保存的全局快捷键前读取同一能力；不支持或读取失败时不注册快捷键、不打开录音浮窗，保留原有 `voice.json`。服务管理器在准备、转写及复用服务前同样检查 CPU 准入，拒绝时不启动引擎。

显式原生适配入口 `POST /api/v1/voice/dictation/open` 和 `harness-voice` 仍供源码／SDK 使用，调用 Hex 自身的应用与命令树，也受 CPU 准入限制；Harness 桌面全局听写不使用这些启动入口。它们保留系统应用身份、显式命令参数、未知打开结果只读回查及不重复启动的边界。

智能体工具 `transcribe_audio` 接收 `audio_path`、可选 `model` 和 `language`，默认与界面相同。相对路径必须具有调用工作目录，读取最多 64 MiB，效果为 `execute`。服务管理器串行拥有完整准备与转写，取消等待仍等待已开始的线程收尾。

没有可复用认证端点时，管理器启动 `hex service --embedded`，通过 stdout 接收 API 版本、进程、随机回环地址和 token，以 stdin 租约绑定所属进程；不发布 discovery 或占用其他应用的本地 API 锁。复用前核对进程及认证健康响应。HTTP 不读取代理、不跟随重定向、不重放失败请求，响应读取有界；关闭先拒绝新操作，等待所属线程，再收回自启进程和读取线程，失败保留句柄与原错误。

## 回归依据与验收边界

`VoiceButton.test.tsx` 覆盖录音、真实音量归属、重复操作、组合输入、跨对话及全局草稿回执；固定每次转写显示首次下载提示、往返对话接收旧结果及重复插入等触发条件。`VoiceCapture.test.tsx` 经真实浮窗组件覆盖就绪与开始竞争、单次提交、取消／替换／卸载后的迟到结果、延迟麦克风授权、未确认插入及授权引导不显示重复技术详情。`VoiceInputPage.test.tsx` 使用真实页面验证只读打开、显式保存、英中英切换、无独立安装入口、未知保存只回查及迟到读取隔离，并核对 macOS／Windows 快捷键字段、默认说明和保存值；`desktopVoice.test.ts` 覆盖显示别名转换与字面 Control 不变为 Command。

`desktop/tests/voice-feedback.test.mjs` 使用受控系统权限拒绝经过 `DesktopVoice.toggle`、浮窗就绪回执、事件发布及 `voiceReply`，核对只传授权资源、不读取原目标，并保留真实外部诊断及嵌套自有错误的边界；不申请真实系统权限或启动录音。

`tests/test_voice_cpu.py` 使用 Win32 API 替身核对 AVX2 标志、系统调用失败与原异常、其他平台准入，以及能力读取、准备、转写、原生打开和 CLI 拒绝后的无启动及数据保持。`useVoiceInputSupported.test.ts` 经过共享 HTTP 验证 CPU 回执、缺失引擎、失败及隐藏后的迟到响应；`conversationSuggestions.test.tsx` 与 `voiceVisibility.test.tsx` 核对真实输入区、设置导航／搜索／定向页面和命令面板的英中英可见性。`desktop/tests/voice-cpu.test.mjs` 保留全局听写恢复、能力读取失败、快捷键与配置原件的针对性回归，属于显式桌面专项；这些替身与组件回归不代替 Windows 实机验收。

`tests/test_hex_tools.py`、`tests/test_voice_api.py` 与 `tests/test_voice_windows.py` 保留本机边界、音频准入、认证、SSE、取消及失败收尾，并验证随包引擎不被损坏的外部安装覆盖。模型准备回归核对 `auto` 在准备和转写中的一致性、并发复用、认证端点替换、失败失效及不重放；API 回归经过实际应用装配检查语音路由，并核对准备准入及阶段计时。预热失败用例使用合法空对象请求到达引擎失败分支，保留单次调用、原始原因和资源身份；WAV 误投预热入口另行核对 bad-json 及准备／转写均未执行，不与合法音频转写夹具混用。`VoiceButton.test.tsx`、`VoiceCapture.test.tsx` 验证录音期间准备、停止等待、失败不上传与取消隔离；`VoiceInputPage.test.tsx`、`desktopVoice.test.ts` 验证实际按键捕获与只读字段；`voiceApi.test.ts` 保留准备回执校验和缺失路由的资源反馈。桌面目录保留安装包完整性与更新状态回归；全局听写主进程、系统快捷键及原生输入链路仍需显式桌面专项和实机验收，不能以组件单测代替。

常规验证不启动桌面或浏览器专项，也不证明麦克风硬件、前台应用粘贴、辅助功能授权、真实模型质量或跨平台实机布局通过。Windows 原生分支仍须在 Windows 实机核验；macOS 本地无签名包不能被描述为已签名或公证发行。
