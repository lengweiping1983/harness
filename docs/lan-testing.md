# 局域网共享对话

以下以工作主机 Mac `192.168.1.14`、受邀电脑 Windows `192.168.1.15` 为例，替换为实际私有 IPv4。智能体、项目文件和任务队列在工作主机执行，受邀电脑使用浏览器访问。

## 启动与地址

在 Mac 仓库根目录运行；`HARNESS_HOME` 使用已有对话所在的实际运行目录。管理和共享入口由同一个 Harness 实例提供：

```sh
cd /path/to/harness
HARNESS_HOME="$HOME/.harness" .venv/bin/python -u -m harness.cli --ui --port 8766 --share http://192.168.1.14:8766
```

保持启动终端打开，结束时按 Ctrl+C。已有相同服务时使用其入口，不重复启动。

| 操作方 | 地址 | 用途 |
|---|---|---|
| Mac 主持人 | `http://127.0.0.1:8766` | 管理对话、邀请、批准和执行 |
| Windows 受邀者 | 完整邀请链接，以 `http://192.168.1.14:8766/shared#token=` 开头 | 申请加入和共享对话 |
| Windows 连通测试 | `http://192.168.1.14:8766/api/v1/access/status` | 返回共享入口状态；`enabled` 为 `true` |

`--share` 接受无路径、查询串和凭据的私有 IPv4 HTTP 地址，本机管理入口保持回环监听。私有 IP 与回环地址可以分别监听同一端口。Windows 的 `127.0.0.1` 指向 Windows 自己；邀请链接使用工作主机的共享地址，不替换为受邀者地址或另一实例地址。HTTP 传输不加密，用于可信局域网。

## 申请加入与提交需求

1. Mac 打开 `http://127.0.0.1:8766`，创建或打开测试对话；运行真实模型前配置模型连接。
2. 点击“邀请协作”，再点击“启用对话共享”。面板中的共享地址由当前实例提供，应为 `http://192.168.1.14:8766`。
3. 选择“协作者”，点击“生成单人邀请”，复制包含 `#token=...` 的完整链接，交给 Windows 用户。
4. Windows 用 Edge 或 Chrome 打开链接，填写显示名，点击“申请加入”。待批期间页面自动查询状态；保留原标签页，刷新时会从标签页存储恢复领取证明并只读回查，不再次申请。关闭标签页或存储不可用时可能需要重新邀请。
5. Mac 在同一对话成员面板核对申请，点击“批准加入”。
6. Windows 等待状态更新或点击“刷新状态”，再点击“进入共享对话”。
7. 两端各提交一条可识别的文本需求，在 Mac 队列和 Windows 待执行列表核对。智能体在 Mac 执行，Windows 显示公共回复；刷新后核对作者与消息仍一致。
8. Mac 移除 Windows 成员，核对该成员失去访问权限。再次加入须使用新邀请。

邀请为单人领取，多人分别生成；受邀电脑不需要安装 Harness、复制数据库或配置模型密钥。共享需求沿用原任务队列，结果未知时先查询原提交回执，不自动重复发送。

加入后的本机与共享对话共用 `ConversationPane` 和 `Conversation`；输入区共用 `ComposerSurface` 的编辑器、卡片和工具栏，由业务适配器控制权限。共享页面不挂载左右栏。

## 角色与审批

| 角色 | 对话能力 |
|---|---|
| 观察者 | 读取公共历史 |
| 协作者 | 读取公共历史、提交需求 |
| 管理员 | 读取、提交、对话范围控制与成员管理 |

需要受邀者审批时，主持人选择“管理员”生成邀请，或修改已加入成员的角色。共享页面按可见轮询更新能力，也可显式刷新；服务端在提交时重新检查权限。管理员可在问题卡片中提交决定；竞争决定由服务端问题身份和版本校验处理，关闭或冲突后读取当前状态。

审批结果未知时，保留原标签页和答案。再次操作先查询原回执；只有明确查无回执且答案与原请求一致时，才允许显式重试原请求。不要为未确认的审批新建需求。角色、邀请、提交与回执协议见 [接口文档](api.md#对话邀请与成员)。

## 连通排查

在 Windows PowerShell 执行：

```powershell
Test-NetConnection 192.168.1.14 -Port 8766
Invoke-RestMethod http://192.168.1.14:8766/api/v1/access/status
```

核对 `TcpTestSucceeded` 和 JSON 中的 `enabled`。连接失败时检查局域网、工作主机服务和路由器客户端隔离；macOS 防火墙提示时允许该 Python 服务接收入站连接，无需关闭整个防火墙。Windows 是主动访问方，无需为此开放 Windows 入站端口。

共享地址未显示时，核对管理端口、启动参数和共享监听日志。`session/not-found` 时核对邀请对话是否属于提供共享入口的同一实例及运行目录，不复制活动数据库到另一实例。

## 实现与回归入口

启动及地址校验见 `harness/web/lan.py`，邀请状态恢复见 `InvitationPage` 与 `invitationRecovery`，角色定义见 `session_invitations.py`，审批回查见 `sharedDecisions`。`web/tests/shared-session-smoke.mjs` 验证受控共享对话与本机页面的一致性、左右栏隔离、语言与主题、输入法、草稿、只读权限及未知提交回查；网络连通检查使用上文实际地址与 PowerShell 命令。
