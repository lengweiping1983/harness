# 架构与模块

应用装配入口为 `harness/app/harness.py` 中的 `Harness`，命令行入口为 `harness/cli.py`。

Superagent 由 `superagent_cli.py`、`app/superagent_config.py` 和 `app/superagent_bootstrap.py` 装配唯一 `SuperagentService`。普通问答和复杂文件目标共用 Source → Gate / Evaluation → Ticket / Mandate → Mission / PlanRevision → Scheduler → 原生 Harness → Report / Artifact / Review → Outbox，任务复杂度只决定冻结计划和完成契约。

`app/superagent_coordinator_store.py` 保存实例协调事实、控制、原生模型调用与本机请求引用；原始 Session、Run、Tool、Worktree 和后台作业继续归 Harness。`superagent_execution.py`、`superagent_dag_scheduler.py` 与 `superagent_executor.py` 负责有界调度、资源隔离、原 Run 回查和执行准入；真实文件交接经 `superagent_artifacts.py`，质量门由宿主冻结候选并以独立 Reviewer 核验。

`superagent_source_registry.py` 与 `superagent_authorization.py` 核验来源、Scope、Mandate 和 Subscription。`superagent_input_delivery.py`、`superagent_mission_instruction.py` 将跟进和指令固定到原 Assignment / Run / Turn；`superagent_coordination.py` 与 `superagent_watchdog.py` 保存同库控制和监督事实。未知副作用只回查原操作，暂停或关闭阻止新的准入。

`superagent_delivery_runtime.py` 从冻结结果建立原目标 Outbox，发送前核对账号、资源和当前授权；`superagent_github_http.py`、`superagent_feishu_http.py` 及 `superagent_http.py` 提供认证 HTTP 和本机监听器。`superagent_provider_adapters.py` 与 `superagent_effect_recovery.py` 只读确认未知发送。`superagent_local.py`、`superagent_state.py`、`superagent_status.py` 与 `superagent_queries.py` 提供同库本机操作、状态摘要、分页和任务详情；运行观察文件不承担独立账本。`superagent_workbench.py` 由主 Harness 持有，Web 设置页经本机专用 HTTP 入口复用相同查询与控制；`superagent_operator.py` 将来源／策略修订及回执原子提交，并仅查回未知原操作。媒体引用与有界获取复用当前来源和消息核验，不自动注入模型。完整配置和实际边界统一见 [Superagent 模式](superagent.md)。

## 源码与修改入口

运行入口以 `harness/app/harness.py`、`harness/cli.py` 为准，Web 路由由 `harness/web/api/` 注册，公开类型由协议生成器同步；前端 `web/src/store/` 持有对话投影，不能代替后端持久事实。修改前按 [代码生成与防回归](code-generation.md) 核对调用、资源归属与异步边界。

## 模块职责

独立执行器通过可信宿主构造参数 `ExecutionRuntime(..., environment=...)` 选择 `ExecutionEnvironment`，工具参数不能切换提供器。默认 `LocalExecutionEnvironment` 复用原所属进程创建与回收，命令及 Git 查询共用该边界；取消、超时和清理异常继续传播。能力快照是实现声明，不是实机验收回执。环境变量由调用方提供，提供器不保证凭据隔离。

| 执行路径 | 审批／路径边界 | 进程回收 | 文件与网络隔离 |
|---|---|---|---|
| 普通开发工具 | 当前权限策略及文件观察保护 | 各工具现有生命周期 | 宿主环境，不承诺操作系统沙箱 |
| 独立执行器默认提供器 | 项目授权及路径策略 | Windows Job／Linux 所属进程组／macOS 所属进程组；其他平台拒绝 | 宿主环境，不隔离文件与网络 |
| Academy | 独立实验目录及课程限制 | 独立运行器回收 | macOS Seatbelt／Linux bwrap；不可用时拒绝，Windows 不降级到无隔离运行 |

Superagent 的远程执行沿同一 Executor Port 经签名设备网关进入原生 Harness，支持 1–32 台设备，原 Mission 租约归协调账本，原生回执归设备。NativeRunner 在可信宿主内装配同一内核与进程内 ModelBroker，不依赖 Docker 或 Unix Socket；可选 Linux Rootless Docker Runner 使用独立 UID 与 Unix Broker。创建 Worker 前通过适配器可选的 reserve_mission 容量准入，满载不创建未知 Worker；两种方式不自动互相降级。详细权限、配额和恢复边界见[产品页](superagent.md#隔离与远程-worker)。单台原生真实 CLI 已验证；可选隔离、物理多机和跨平台专项仍需独立证据，企业治理未实现。

轮次交付投影位于 `harness/session/turn_delivery.py`，验证回执位于 `harness/session/verification.py`，HTTP 收尾读取位于 `harness/web/api/turn_completion.py`。它们复用既有轮次和工具日志，不另建运行事实源；查询在不可变事件快照上计算，返回前核对所属历史与目录。可信宿主可用 `Harness(..., codex_gateway_home=...)` 将网关账号目录显式装配到其拥有的数据范围，默认产品路径不变；离线评估使用独立临时目录，不修改全局环境变量。

| `harness/skills`、`plugins`、`connectors` | 技能发现、插件包与外部 MCP 服务生命周期 |

独立执行器的 `execution/pipeline.py` 编排已确定的命令、验证和图片依赖，执行事实仍属于既有工具回执、作业和证据。`mcp_server/companion.py` 通过独立回环监听只读执行器事实，保存单次消息意图；可选浏览器扩展在绑定的 ChatGPT 普通聊天中请求接续。桥不调用模型或项目命令，发送确认不代表开发完成。协议及限制见 [网页开发与自动接续](chatgpt-development.md)。

显式准备资料后的本机 OpenCode 匿名通道见 [本机模型接口](opencode-local.md)。它复用官方运行时发送请求，工具执行与对话历史仍由 Harness 管理。

## 对话内可视化

`widget_tools.py` 注册 `show_widget` 与 `widget_guidelines`；`ToolBlock` 按所属工具结果的 `display.widget` 渲染。SVG 与 HTML 围栏继续通过 `Markdown` → `LiveChart`／`CodeBlock` 分发，HTML 的类型判断独立于高亮语言别名。原生供应商的参数解析诊断经过桥接保留，再由工具校验拒绝执行，不能把损坏 JSON 伪装成空对象。载体、沙箱、状态与回归见 [对话内可视化](conversation-visualizations.md)。

## Academy 学习域

harness/academy 独立管理课程包、隔离代码实验、无工具的模型实验、原生智能体带练、学习证据、检查点与回执。带练复用核心 `AgentLoop`，使用独立内存会话与仅限课内的工具注册表，执行仍经过 Academy 沙箱和持久回执；不改写主对话事件。模型实验、带练、制课与点评由宿主安排异步执行，分别保存自身输入与结果。见 [Harness Academy](academy.md)。

## 一次对话运行

1. 网页 HTTP／WS 提交进入 `RunController.submit` 的持久队列；CLI 经 `Harness.stream` 调用 `run_async`，SDK 可直接调用 `run_async`。它们最终共用 `RunController.execute` 的运行准入和执行身份，但不能把直接调用视为持久排队提交。
2. `Harness.run_async` 装配对话身份、权限与上下文，智能体循环组织模型请求。CLI／SDK 流迭代器提前关闭会取消并等待其启动的执行；网页连接断开不等于撤销已经受理的队列写入。
3. `llm` 的共用 SSE 入口处理字节及事件边界，只向适配器提供 JSON 对象；非对象事件明确报错。适配器解释模型流式结果，工具参数必须是可解析的 JSON 对象，解析失败不产出该工具调用；单模型与路由共用这一边界。具体工具参数仍经过注册表的 schema 校验和权限闸执行。
4. 运行启动通过 `RunController._commit_start` 先提交持久记录，再更新同一内存运行对象；对话先提交持久事件，再发布状态。`WebContext` 的事件桥把实时投影送给订阅对话。
5. 轮次终态、队列和目标状态分别持久化。恢复过程标记中断，不重新执行结果未知的副作用。

HTTP 处理线程通过 `WebContext.call` 将协程调度到实例事件循环；不能在请求线程另起不受管理的业务循环。路由闭包属于当前 `WebContext`，不存为跨实例的类级缓存。

HTTP 查询保留显式空值，与未传字段区分。运行总览和全局终端输出从 `harness/web/query.py` 的同一声明生成公开参数及执行校验，共用现有 Schema 校验器；未知、重复及无效字段在读取运行注册表前拒绝。只有明确省略对话字段才允许全局查询或唯一终端拥有者解析，不再并列维护两套查询字段或默认值。

MCP 请求由连接层拥有发送子任务。真正发送前同时核验调用方尚未请求取消、当前权限及远端工具声明；HTTP 工作线程回到实例事件循环执行该核验。父调用请求取消即撤销尚未发送的调用，不等待取消逐层传播，也不重试结果未知的远端操作。stdio 和 HTTP 使用相同的连接层取消门槛。

主对话与成员通过 `Harness._bind_agent_services` 绑定共用的技能解析、身份服务、上下文控制和工具目录策略。请求配置、运行身份、生命周期、权限继承和预算分别由其既有所有者维护；公共绑定不改写这些状态。

普通对话、团队命令与未携已有智能体的外部运行器共用 `app/goal_budget.py:resolve_execution_budget` 选择回合预算：仅 active 且 armed 的目标使用持久目标预算，否则使用普通预算。携已有智能体的外部调用保留其原预算。模型完成式与智能体流循环共用 `llm/stream_merge.py` 的思考块及签名归并；检查点、增量广播与路由续接仍由原消费者管理。计划模式的只读闸门、审批版本、回合边界和提示词契约见 [计划模式](plan-mode.md)；安全、隐私、敏感数据与本地凭据的控制面/执行面边界见 [安全、隐私与本地凭据](security-privacy.md)；Goal 的状态机、Codex 对照、续接准入、证据回查和双语提示词契约见 [长程 Goal、续接与可核验完成](goal-longrun.md)。

模型物理请求的预算计量由 `core/response_cost.py` 独立负责；失败重试按实际请求归档身份累计，重复回执不重复计量，混合估算不能标记为全部由供应商报告。智能体循环复用此结算，不另维护一套请求费用。

设置页通过 `ProviderConnections` 保存供应商和接口，Key 池绑定接口并由该接口下全部模型共享。请求解析到固定模型和配置快照；鉴权拒绝持久标记对应 Key，限流和瞬时故障可尝试同一接口的其他 Key，原生供应商在 HTTP 200 流内返回明确的上游瞬时错误时也沿此路径处理，已交付内容不自动重放。凭据耗尽不会换模型或供应商。原单接口 SDK 传输仍独立使用现有适配器。

通用原生供应商通过受监督 Node 子进程桥接固定版本 pi-ai。发行包包含打包实现与目录，OAuth 和 Bedrock 的动态入口在构建时纳入包内；子进程取消后等待回收。文本、思考、签名、工具、用量与错误转换为既有模型事件。凭据刷新使用接口级锁和持久化确认握手，刷新后的令牌保存完成才继续请求。两种 OpenCode 指定端点保留已有专用传输。详情与供应商对照见 [模型供应商](model-providers.md)。

首次 `Harness.ensure_started` 共享所属启动任务；只有自动化、连接器和启用的 MCP 目录注册完成后才设置已启动。等待者取消不取消该共享任务，启动失败不隐式重连；关闭先取消并等待启动，再继续原资源回收。对应回归为 `tests/test_harness_startup_lifecycle.py`。

## 事件和上下文

`SessionEvent` 与 `SessionHeader` 定义在 `harness/session/events.py`。完整日志用于恢复、审计和工具证据，表面投影用于模型上下文。压缩与工具结果裁剪不能删除权威业务状态；待办恢复扫描 `todo/write` 日志，计划、目标和队列各有持久记录。

轮次事件归属由 `harness/session/turn_scope.py` 统一确定，供恢复报告、文件操作审阅、净变化及还原使用。唯一 `turn/start` 确定起点，首个 `turn/end` 或下一个 `turn/start` 确定终点；显式属于其他轮次或运行的事件不作为证据。轮次到运行的查询只认开始事件的 `run_id`，不扫描结果正文、相似提示词或近似时间补找身份。缺失和歧义均保留原记录并明确暴露。

`harness/session/tool_activity.py` 是界面统计、时间线和恢复报告共用的工具生命周期投影。同一调用标识跨步骤复用仍表示不同执行；投影引用原始事件，压缩节点不产生新的执行事实。恢复报告在此基础上严格检查开始记录、唯一结果和精确身份，未知结果不能继承先前执行的成功状态。

模型请求诊断、文件变更和运行状态有独立查询路径；不要将 UI 草稿当作持久对话事实。前端运行图标通过实际活动运行判断，不能从流式文本或队列长度推断。

`harness/core/browser_verification.py` 为本轮成功的 `write/edit` 与浏览器调用记录工具结果序号。成功写入或编辑 `.html/.htm` 文件，即使本轮没有浏览器调用，也在最终回答前检查缺少的运行验证；语法校验不代替页面验收。对于已有浏览器检查，如果最后修改、浏览器输入或失败之后缺少同一当前页面的截图和诊断，诊断或后续健康计数仍有告警、缺失、丢弃，或用户持有控制权，则追加一次交付复核；清单全部勾选不跳过此检查。只读浏览、失败写入和明确未改变文件的操作不触发。普通观察成功不清除重载失败，导航和输入使旧检查失效。复核状态每轮重新建立，最多追加一次模型请求，仍受原预算、停止和引导约束；不自动接管、重放操作、修改清单或把工具事实转换为验收通过。这是给模型的纠正机会，不能保证模型遵从，也不证明截图已经看懂或交互满足需求。最终业务结论仍须核对实际证据。

## 团队

常驻角色选择由挂载控制器维护；单次 `/agent` 调用有独立语义。提示词驱动团队通过宿主约束的协作原语派工。成员身份、依赖、权限和上下文由宿主管理；严格验收依赖可核验证据。`RunDirectory` 查询队列及委派关系，取消权限沿真实运行身份链判定。

`AgentLoop.run_id` 是当前 `AgentRun.id`，轮次开始、工具调用、输出及成员消息应用均使用这一身份。成员配置完成后由调度器绑定自己的运行，父子关系由 `parent_run_id`、`parent_session_id` 与 `root_session_id` 表达。同一私有对话续接为新运行时更新身份，历史轮次保留原始关联；内部不再维护第二个 `agent_run_id` 属性。原生与外部成员共用此规则，预算及权限继承仍按各自既有规则执行。

成员派工时解析请求配置，由该执行任务持有配置快照；等待容量和首次调度之后不再读取父智能体的当前请求配置。显式成员模型和思考强度仍在宿主配置钩子后应用；父级权限、共享预算和计划约束继续在绑定时继承，不能把冻结模型配置当作冻结授权。

成员的对话关闭、交付回调、归档和终态广播由管理器同一个收尾任务完成。正常结束、容量等待中取消、首次调度前取消和直接取消执行句柄都汇合到这一任务，不在中断入口再次改写终态。等待超时只结束观察；中断或关闭则等待已拥有的收尾完成，即使调用者重复请求取消也不能遗落交付。父级释放成员之前必须完成执行与收尾两个句柄，成员已输出完成不能代替这一条件。

`AgentRun.settled` 是终态、执行句柄和收尾句柄均已结束的派生判断，不保存第二份运行状态。成员上下文复用、followup、团队容量／替换／依赖／完成检查、文件恢复与工作树环境复制统一使用它；不能只凭执行句柄已取消便释放仍在交付的对话。环境复制按工作区路径判定占用，其他工作区继续可用。运行总览将执行或收尾尚未结束的成员加入历史首屏，全部结束后恢复普通分页。原收尾句柄现在明确由运行记录的 `finalization_task` 持有，只存在内存，不能作为构造输入或写入存储及公共响应。

成员派工在上下文分配前、团队工作树准备前和实际执行前共用 `require_accepting` 检查。关闭范围及其后代返回 `agent/parent-closing`，祖先关系沿 `RunDirectory.controls` 判断；其他分支继续可用。关闭操作持续拥有范围，全部重叠操作及已接受成员完成收尾后才重新开放，取消等待者不会留下后台成员。`shutdown(None)` 明确关闭全局，空字符串范围报错。中断和范围关闭共用运行对象的停止路径，不重复遍历同一后代分支。

## 项目 Git 操作

工作树、交付、源快照、环境文件预检、暂存和只读审阅共用 `harness/app/git_process.py` 的宿主 Git 进程入口。每次启动清除继承的 `GIT_*` 覆盖，只采纳当前内部操作显式给出的临时索引、交付作者或只读选项，避免进程环境把操作重定向到另一个项目。

工作树服务解释命令的预期退出码：合并冲突、未命中忽略规则和未产生首个提交各保留原业务含义，其他退出状态明确报错。只读审阅保留专用超时及补丁输出上限，大补丁进入临时文件后只读取预览范围；Git 提交超时仍报告结果未知，不自动重放。初始化入口对显式仓库环境覆盖的拒绝规则保持生效。

## 桌面隔离

桌面原生能力通过对话、来源及生命周期隔离。网页工作台不会因此获得 Electron 权限。页面、下载、对话框、截图及后端重连分别由原生管理器处理；Node 用例位于 `desktop/tests/*.test.mjs`，目前覆盖启动配置、环境隔离、后端停止生命周期、浏览器 IPC 来源与对话控制权隔离及对话框事件适配；当前没有原生端到端用例。安装包后端清除继承的 `PYTHONHOME`（Windows 按大小写不敏感匹配），明确使用自带解释器、应用包路径和独立用户站点设置。

桌面 `BackendSupervisor` 先接管启动返回的后端，再判断是否正在退出；退出期间迟到的结果由 `close` 统一停止，停止失败向调用方报告，不因启动已取消而吞掉清理错误。

桌面 `stopChild` 按子进程对象共用正在进行的停止 Promise，退出或失败后释放。并发停止只拥有一套信号、退出观察和超时，失败后新的显式停止仍可重试；不据此宣称 Windows 后代进程树已完成实机验收。

原生浏览器 React 面板仅在活动时观察布局；检查器保留已访问页签不意味着保留 DOM／滚动／尺寸观察。停用沿用 effect 清理隐藏原生视图并关闭键盘上下文，重新打开时重新测量布局。

## 真人协作接入

`SessionAccess` 是对话权限唯一事实源；`SessionInvitations` 在同一对话日志记录邀请和待批申请。两者共用变更锁，批准只写一条携带邀请消费信息的访问事件。`SessionCredentials` 将浏览器凭据绑定成员加入周期；降权立即以当前能力判断，移除后旧凭据不可通过重新添加恢复。

HTTP 适配位于 `harness/web/api/collaboration.py`，共享入口先执行精确来源检查，再验证浏览器凭据及最新权限。成员撤销沿现有 WS 订阅核权路径断开读取。前端邀请和成员面板使用公共 HTTP 传输、版本比较、可见时轮询及卸载隔离。访客入口 `/shared#token=hi1.…` 去除地址栏 fragment，申请批准后兑换 HttpOnly Cookie，公共历史使用服务端统一公开投影。

已实现邀请、成员角色、公开历史、真人普通需求提交与原队列回执。`AgentRun.requester` 从接入层身份构造，成员加入周期只在内部持久化；队列启动前再次核权。Core 通过注入的消息来源提供器取得运行归属，外部智能体／团队入口复用同一来源。

`harness/web/lan.py` 让本机完整入口与私有 IP 共享入口使用同一 Harness、事件循环、运行队列和数据库；退出时先关闭共享监听，再关闭运行和本机监听。只允许显式私有 IPv4，管理入口保持回环。`shared_projection.py` 对 HTTP 与 WS 使用统一公开内容白名单。未知实时事件仅留下序号占位，避免因裁掉私有帧触发重连循环。

成员可按版本修改、移除自己当前加入周期内的未执行需求，仍复用 RunController 和对话限定运行接口。管理员通过共用问题卡片提交审批，决定由原问题版本与回执确认。共享访问范围见 [接口文档](api.md#对话邀请与成员)，局域网启动见 [共享指南](lan-testing.md)。

共享协作的公开错误资源统一放在 `ui.collaboration.error.*`，由后端资源源生成浏览器子集。API 与实时错误按机器码呈现，访客本地语言切换不改变宿主模型语言或授权状态。计划模式策略也直接从语言资源读取；开发者叙述在实际提交时解析，不使用导入时固定的文本。

### 多人审批提交边界

`SessionDecisions` 组合现有 `SessionAccess`、Session 日志与 `QuestionBroker`，不另建审批执行引擎。Broker 按问题串行化提交；业务钩子在权限锁中重查权限、加入代次、问题版本与请求号，然后写入决定，成功后才唤醒原 Future。同步回答不能越过正在提交的决定。请求连接取消不取消已接受的提交；问题自身取消仍会阻止恢复工具。重启只提供决定回执，不重放未知副作用。公共接口与共享管理员界面已接通；卡片审批能力与正文只读操作分离，成员能力变更复用任务面板原轮询，不另建权限轮询。

## HTTP 传输与协议快照

共享 HTTP 层的超时、取消、错误及生成响应契约回归位于 `web/src/lib/__tests__/http.test.ts`。传输层不自动重发写操作；操作是否已提交由对应业务读取权威状态核对，不以连接恢复或 HTTP 重试替代。

设置接口 `/api/v1/settings` 与 `/api/v1/ui-settings` 的 GET／PATCH 响应也从既有公共 OpenAPI 生成运行时契约。共享传输拒绝结构不符的成功响应；业务调用方继续负责读回确认写入内容。

OpenAPI HTTP 响应的不可变 JSON 字节由当前路由实例缓存，键为当前语言和路由模板快照；请求仍返回独立响应对象与 `Cache-Control: no-store`。直接调用协议生成函数返回独立文档，不能把内部缓存等同于浏览器缓存。

## 运行身份与资源收尾

`core/turn.py` 是 `AgentStatus` 与 `TurnResult` 的唯一定义位置，只承担实时状态及轮次结果的数据和序列化。循环、团队命令和外部智能体命令共同引用它；包级与现有循环模块公开导出指向同一类型，不维护转换副本。`core/runs.py` 继续负责运行记录和终态判定，不与轮次结果合并。

本地词元估算入口归属 `llm/context_accounting.estimate_tokens`，仍由统一的来源投影计算；摘要、运行控制和循环共享它。调用方需要适配器思考口径时显式传入，默认保守计入全部思考。估算与供应商实际计量保持不同语义，不通过导入循环模块取得纯计算函数。

原生网页权限的页面清理先移除该标签页的全部请求、超时与授权，再通知拒绝回调。取消回调失败只记录诊断，不能阻断同页其余资源释放；其他标签页不受影响。普通应答与清理共用请求脱离路径，来源和标签页仍须匹配。

文件观察策略属于一组文件工具定义，由 `build_fs_tools(..., observation_policy=...)` 在装配时固定，不能通过模型参数改变。Harness 为自己的工具传入配置；独立执行器沿用安全默认值。进程不再持有可由另一实例改写的观察策略开关；观察证据与版本检查继续复用现有实现。

无模型 `ExecutionRuntime.close` 共用唯一清理任务，调用开始即停止新任务准入；取消等待者不能取消已接受工作。复用 `join_cleanup` 等待执行、作业及监视器收敛后关闭存储，清理失败向全部等待者报告；`closed` 不是资源清理完成的证明。

`OwnedProcess.stop_owned` 在原控制锁内通过 `join_cleanup` 等待底层停止线程结束，再传递调用者取消；重复取消不提前释放进程控制权。随后进入的调用先核对原生句柄的退出证据，不重复停止已退出的进程。

macOS 的 PTY 停止通过系统 `libproc.proc_listchildpids` 逐级记录所属后代，反向发送终止信号，再沿原前台进程组和 Shell 收尾；不启动 `/bin/ps`。枚举容量不足时增长缓冲区，达到上限或权限拒绝明确失败，不将不完整列表视为空树。其他 POSIX 平台沿用 `ps` 进程表。枚举与发送信号仍不是原子操作，不保证捕获枚举后新派生或已重新托管的进程。

ConPTY 适配器沿用同一取消边界，并将原生停止和退出／控制台断开等待归入单次清理任务；控制锁在两者均收敛后才释放。普通停止入口与交互终端共用 `join_cleanup`，不复制取消等待循环。

终端运行库探测和安装命令同样复用 `join_cleanup`：各调用方只定义自身的停止、输出回收与句柄关闭顺序，公共入口负责等待取消边界，不在各业务路径复制等待循环。

`RunController.begin_close` 在所属循环的同步段固定暂停队列保留集、停止准入并取消根驱动；`close` 等待同一个所属关闭任务。排队运行由其驱动负责向操作传递取消，不能再同时取消其操作；用户已取消的操作处于收尾时，也不通过驱动再次传播取消。关闭任务观察首次固定的全部句柄，同一原错误经驱动和操作返回时只汇集一次。并发或重复关闭继续复用原任务，`join_cleanup` 隔离等待者取消，不重算恢复依据。回归见 `tests/test_run_shutdown.py`。

`Harness.close` 将跨循环派发留在入口，在所属循环内先调用 `runtime.begin_close`，再建立唯一清理任务。登录取消及各资源仍按原顺序由 `_close` 逐项尝试回收，但慢资源等待不再留下接收新运行的窗口，也不让目标自动续跑进入关闭后的启动拒绝分支。资源清理、SessionEnd 钩子或对话关闭失败均不跳过后续资源。单项失败保留原异常类型，多项失败以异常组保留全部原始错误；取消等待不能打断剩余清理，并发与重复关闭取得同一结果。对应回归为 `tests/test_harness_shutdown.py` 与 `tests/test_prompt_source_identity.py`。

`TerminalSessionService` 在启动进程前登记创建任务归属。`close_owner` 与 `close_all` 先停止范围内的新建准入，等待已接纳的创建完成，再逐项回收；并发关闭共享回收任务，重复取消不能遗落迟到进程。一个 owner 失败仍尝试其他 owner，失败实例和名称占用保留，后续显式关闭可以重试；范围回收结束后可重新创建。对应回归为 `tests/test_terminal_creation_ownership.py`，其中创建屏障使用 POSIX 分支，不代替 Windows 实机验收。

普通所属进程与 ConPTY 在创建取消后先等待句柄归属建立，再以单个 finish 任务完成停止和关闭，清理等待复用 join_cleanup；创建收敛与返回值交接仍由各自原入口负责。

重复工具调用提醒器由每个 `Harness` 实例持有，通过统一服务绑定传给主对话与成员循环；关闭时显式绑定 `None`。独立 `AgentLoop` 默认关闭提醒，不读取进程级默认实例。提醒计数在宿主内按对话隔离，创建另一宿主不会改变已有循环的提醒配置。

## 记忆装配

`Harness.memory` 保留项目存储入口供项目功能调用；`Harness.layered_memory` 负责用户、项目、对话的绑定和预算。提示片段仍在每轮次按当前对话和最新用户消息生成，不缓存跨对话正文。统一复用 `ProjectMemory` 的事务、严格数据库结构校验和乐观修订控制；新层使用独立数据库，现有库不迁移。详情见 `storage.md`。

## 对话呈现与语言

普通与受邀对话共用 `ConversationPane` 和 `ComposerSurface`，本机与访客适配器分别处理能力、身份和提交回执；受邀页面不挂载左右栏。请求和工具详情通过父面板活动状态及页面可见性暂停读取，隐藏后拒绝迟到响应。

自有双语文案源为 `harness/i18n/locales/`，前端子集由 `scripts/generate_i18n.py` 生成。语言在实际请求/呈现时解析；公共协议说明同样按读取语言生成独立快照。目录响应不得覆盖较新语言或用户当前业务选择。工具说明通过 ToolSchema 的显式资源身份解析；不根据文本或模块名猜测翻译所有权。

工具策略提供函数根据当前工具集合选择完整资源键，在实际装配时解析语言。提示词注册表将显式language绑定到本次装配，退出后恢复原上下文；摘要策略、对话检索引导和重复调用提醒的模块常量只保存资源键，不保存导入时翻译结果。对应回归为 `tests/test_policy_resource_identity.py`，覆盖同一提供函数与Harness实例的英文→中文→英文切换，并禁用原文反向翻译验证资源身份。后端原文反查代理已删除，自定义提示片段和外部正文保持原样。

## 账号授权

ChatGPT 的配置界面只显示一个多账号管理入口。Harness 对话与本机 Codex 网关共用账号池；当前账号和自动切换选择持久保存，自动切换默认开启，沿用 95% 阈值。网关启用开关独立于 Harness 对话的账号选择，登录订阅账号不会隐藏 API 供应商。

订阅模型通过 `harness/llm/chatgpt.py` 将聊天请求转换为无状态 Responses 请求。函数工具默认显式传递 `strict: false`，保留当前工具 schema 中“省略”与显式值的区别，避免上游自动严格化后要求模型为可选字段补造值；调用方显式提供的 `strict` 保持原值。转换不改写参数 schema 或原声明，宿主的参数类型、权限与证据归属检查仍独立执行。该适配遵循 [Responses 函数调用的严格模式规则](https://developers.openai.com/api/docs/guides/function-calling#strict-mode)，离线执行链回归见 `tests/test_chatgpt_tool_contract.py`。

ChatGPT 登录的到期计时器属于账号实例，取消、替换登录及宿主关闭时同步取消该计时器；旧登录回调只能清理其拥有的监听。监听线程启动失败时直接关闭尚未运行的 HTTP server，避免对未启动 serve_forever 调用 shutdown 产生死锁；定时器启动失败时回收已启动监听。对应回归为 `tests/test_chatgpt_login_lifecycle.py`，使用隔离端口与线程故障注入，不访问在线账号。

ChatGPT 认证的 HTTP 拒绝只按封闭错误码分类地区限制、授权失效、授权拒绝与客户端拒绝；安全验证由 `cf-mitigated: challenge` 标记识别，其他错误保留 HTTP 状态，不回显上游描述或未知错误码，不自动重放令牌请求。回调页由 `harness/llm/chatgpt_callback.py` 渲染双语 HTML，跟随系统明暗主题，无外部资源；响应禁止缓存、引用来源与页面嵌入，并通过 nonce 限制脚本和样式。页面加载后移除地址栏授权参数。`tests/test_chatgpt_auth_diagnostics.py` 与账号语言回归覆盖分类、脱敏、转义和回调响应。

### Codex 订阅网关

`harness/codex_gateway` 提供独立的本机 Responses 网关。`AccountPool` 以默认账号和动态创建的账号槽位组成集合；用户每次首次授权都写入独立目录，账号数量不绑定固定示例数量。凭据、刷新代次和额度快照按账号隔离，账号身份重复时保留记录但只允许一个槽位参与调度。网关运行租约和稳定旁路锁防止多个写入进程覆盖账号登记。

额度读取通过隔离的 Codex App Server 进程调用 `account/rateLimits/read`，不读取桌面客户端凭据，也不启动第二套智能体循环。只接受已确认的 5 小时窗口、周窗口、模型权限和授权状态；已用量达到 95%、额度未知、窗口过期或账号授权失败均不能取得新请求租约。候选按最早重置时间、已用量和稳定槽位 ID排序；所有候选不可用时等待并重新读取，不消耗预留余量。

`ResponsesProxy` 将桌面端原生 Responses 请求、SSE 事件、工具调用、图片和加密推理条目逐字转发；跨账号续跑依赖请求携带的历史而不是 `previous_response_id` 或服务端存储。只有明确的 401/429 且尚未交付响应字节时才重新准入；输出开始、流终态缺失或收尾失败均保持结果未确认，不自动重放。网关只监听回环地址，桌面端通过 `harness.codex_gateway config` 生成 provider 配置和命令凭据辅助入口。

定向回归位于 `tests/test_codex_gateway.py`；真实 Codex 客户端协议探针位于 `tests/codex_gateway_client_probe.py`。探针覆盖动态账号路由、工具结果配对和加密推理条目保持；真实订阅账号的额度读取与跨账号接续需在隔离账号目录中执行在线验收。

## 模型请求的消息顺序与阅读

`Session.build_messages()` 将当前稳定系统提示放在消息首部，随后按表面顺序投影对话历史，最后加入当前运行时开发者消息。Chat Completions 翻译将开发者消息映射为 `system`，因此请求记录可能显示“系统指令 → 用户消息 → 系统指令”。前后两段分别承载稳定规则和环境等运行状态；来源列表中的工具策略、延迟工具目录与顶层 `tools` 定义属于不同输入。

运行时段每次重新放在历史末尾，不保留历次运行状态为消息历史，不能保证上一请求整体成为下一请求的前缀。按需工具加载也会改变顶层工具定义。请求记录的前缀比较只提供本地结构差异，实际缓存命中以供应商报告的用量为准。

缓存复用比例按报告缓存的请求计算：分子为缓存读取 Token，分母为这些请求的输入 Token，输入已包含缓存读取和创建，不再重复计入总用量。桥接在存在正缓存读取或创建时同步传递覆盖输入量；运行库全零的缓存计数无法区分未报告与真实零命中，因此不据此补造报告。归档投影和请求详情遇到正缓存读取但没有覆盖字段时，以该请求已报告的输入量作为分母；汇总前逐请求处理，未报告缓存的请求不混入分母，也不回写归档。明确覆盖为零、读取超过覆盖或覆盖超过输入仍作为异常；有覆盖输入且读取为零则显示 0%。

请求详情中的请求体、单条消息及工具定义复用只读 JSON 展示；请求参数、诊断、运行详情、插件工具输入与 JSON 文本结果也使用同一按需高亮和主题配色，结构化工具参数与结果使用可分页的着色树形查看器。分页保持原始字符范围，原文与格式化切换不改写归档；高亮尚未加载、不可用或内容过大时直接显示原文。大小摘要的输入项按请求原始顺序显示，少于 20 项时全部展示，达到 20 项时默认展示 10 项并按批次展开；最大工具定义按字节大小取前 8 项，工具说明仅在名称上停留或聚焦时显示提示。执行时间线优先使用工具事件保存的说明；旧事件未保存说明时，在名称上停留或聚焦后按需读取来源请求的工具定义。上下文审阅仅汇总事件与报告用量，不构造已移除的输入组成估算。

请求详情分两阶段读取：`part=summary` 返回当前请求的消息预览、工具名、工具说明、参数及大小组成，不读取上一请求或重放历史来源；随后读取完整详情补齐缓存对比和来源关联。诊断读取失败保留已打开的内容，显示错误及重新读取入口；诊断期间保留实时状态观察确认的元数据。概要读取被服务器以参数错误拒绝时，页面保留失败状态与原始诊断，并明确提示在任务结束后更新、重启后端和刷新页面；不回退到完整详情或自动重试。未知档案部分返回 `request-trace/unsupported-part` 及支持清单。原始 `part=body` 直接分页归档文本，不解析整份 JSON。缓存对比以分块字符串比较确定精确公共字符前缀，两类来源分析共用同一历史投影。

`harness/web/read_work.py` 按归档实例和读取键合并在途计算。请求详情的键包含对话、请求记录、内容分区、索引、偏移及对话存储实例；完成或失败后移除，不缓存权限或历史结果。执行时间线列表与工具详情对相同事件及元数据快照共享在途投影，不跨对话或状态变化复用。观察者取消等待不代表后台线程计算已停止。上下文及关联证据的浏览器读取使用35秒专用等待窗口，覆盖后端默认30秒处理窗口；这不代表任意大小历史都保证在该时间内完成。

## 服务注册

`harness/core/events.py` 提供 `EventBus` 与服务容器 `Context`。`EventBus.emit` 按注册顺序等待同步或异步监听器，单个普通异常记录后继续其余监听器，取消继续传播；一次性监听器在调用前移除，避免重入重复执行。成员总线在同一 `emit` 入口追加真实运行身份，再转发到共享总线。

服务容器`Context`只在显式`plugin()`作用域内记录撤销历史，退出时逆序恢复。根级`set()`直接替换当前服务，不保留已替换实例；它不自动关闭服务或撤销事件订阅，资源清理由所有者负责。
