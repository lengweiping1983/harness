# 模型提供商

首次使用打开设置中的模型配置，点击“选择提供商”打开提供商目录弹层，搜索并点选一个提供商，随后填写认证与模型并保存；新增接口默认不勾选模型，已有接口编辑时保留原选择。不会自动建立 OpenRouter、OpenCode 或订阅账号配置。设置页、模型菜单和智能体模型目录只展示已配置的提供商模型及已登录订阅账号的可用模型；单模型环境变量、SDK 配置和模型路由不合成目录条目。没有可用来源时返回空目录与空的当前模型身份，已保存的默认模型或可见性设置不会补回条目；移除提供商后也不会重新出现保底模型。显式单接口 SDK 调用仍使用自己的配置。运行目录由 `HARNESS_HOME` 指定，默认 `~/.harness`。

每个提供商的名称、配置状态、模型数量及模型显示开关、默认模型操作放在同一张卡片中。每个模型始终显示上下文容量，未报告容量时显示“上下文：未知”，不推测默认值。模型名称与提供商实际模型 ID 完整换行，已知输出容量与上下文指标同行排列；操作另起一行并可换行，避免按窗口断点压缩嵌套卡片中的名称。模型按稳定的提供商／接口／模型身份归属，同名提供商或接口不会混合；只有多个接口时才显示接口分组名，单接口不重复提供商名称。设置页打开时重新读取模型目录，不依赖主界面已缓存的列表。管理列表按已保存配置逐行展示模型，可用目录只补充元数据；目录为空或读取失败不会隐藏已保存模型。未出现在可用目录中的模型保留编辑、移除入口，显示目录状态，暂不提供默认模型与显示偏好操作；读取失败可显式重读，不重复保存。已保存模型行直接提供编辑与删除入口：编辑只打开当前模型的 ID、名称和能力参数，删除先在该模型行确认，再从所属接口移除该选择，不删除提供商或其他模型。显示开关和默认模型操作立即保存，不需要进入编辑表单；切换对话模型仍只影响当前对话，关闭显示开关后当前模型仍保留。非提供商配置来源的模型继续单独分组展示。配置卡片不显示未实现的连接测试状态。提供商目录按名称排列，同系列入口相邻；OpenCode 的各接口排在一起，Codex 帐号池归入 OpenAI 一组。此排序只影响显示，不修改配置、模型或 Key 的实际顺序。移除提供商时，确认区直接显示在卡片标题右侧操作的下方，不放到模型列表末尾；模型删除确认同样在当前模型行内靠右显示。两者共用紧凑确认区，取消在前、移除在最右侧，文字和按钮在窄容器内换行；取消不发送写入。提交期间保留确认区并禁用按钮，失败后仍保留当前确认，不自动重发。编辑时依次显示接口协议、接口地址和认证方式，随后配置模型；已知地址由提供商模板默认填写。接口名称沿用卡片标题，不在高级设置中重复提供输入框；接口启用开关、请求头、兼容参数及超时等放在认证之后、模型之前的“高级设置”中，不与模型选项混排。混合原生目录可留空地址使用各模型端点；云接口可通过对应环境字段确定地址。常规编辑不显示添加接口按钮；展开“其他接口设置”后可添加其他接口。一个提供商可以添加多个接口，编辑卡片按接口收展并显示模型列表总数和已选模型数；同一种协议也可以配置不同地址。保留原生协议时，目录中各模型使用自己的协议和地址，不把整个目录强制转成 OpenAI。

API Key 属于接口。该接口的全部模型共用有序 Key 列表，可添加、删除、排序、启停及显式重置失败状态。鉴权失败将该 Key 标为不可用；限流或瞬时错误可切换其他 Key。原生供应商即使以 HTTP 200 返回流内失败事件，只要错误语义明确属于上游空闲超时、暂时不可用、过载或连接中断，也按瞬时错误处理。耗尽后报错，不自动换模型或提供商。已交付内容后失败不自动重放。单 Key 的可重试请求遵循设置的重试上限。

自定义接口返回 HTTP 409 且错误码为 `MODEL_CALL_FAILED` 时，表示提供商没有完成所选模型的调用；不能仅凭该回执断定是网络、凭据或输出上限问题。桥接阻止运行库对此错误自动重试，不轮换或停用 Key，也不自动更换模型。错误卡片提示将技术详情中的 `traceId` 提供给服务商核查；结构化诊断和请求归档同时保留脱敏后的 `provider_trace_id`，已完成工具及轮次证据保留。该诊断不保证远端模型已经恢复可用。

模型区按目录工具栏、手动添加和已选模型分区。目录数量、“选择模型”和“获取可用模型”集中排列，窄屏自动换行。手动添加区在提交前即可填写模型 ID、名称、上下文窗口、输出上限、输入类型和推理等级；名称留空使用模型 ID，容量未知可留空。点击“添加模型”或在文本／数值框按回车，将完整参数加入接口草稿；输入法组合期间不触发。重复 ID 与非法容量在原处提示，至少保留一种输入类型和一个自定义推理等级。成功后清空手动草稿、提示已添加模型，并将焦点留在模型 ID，方便连续添加；已选模型默认收起参数，仍可展开同一组字段继续编辑。获取目录期间暂停手动添加，已填写的手动草稿保持。添加只更新表单，仍须保存提供商配置。候选模型较多时点击“选择模型（数量）”打开模型列表弹层，弹层内搜索、勾选并分页浏览，每页 50 项；“全选”与“全不选”作用于当前筛选结果并在按钮上标明数量，“添加各系列最新版”按模型 ID 的版本和用途分组追加各系列最新版本；日期快照不与无日期别名重复选择，Pro／Flash／Max、模型大小等不同用途仍分别保留，明确不受支持的版本不加入该批次。弹层内的改动点“确定”才写回接口，取消丢弃；批量添加保留已有模型的身份、顺序、启停和高级选项，全不选不移除手工填写的模型。已选模型可删除和上下调整顺序，已选配置每页 10 项；已选项超过 10 项时提供独立搜索，按名称或模型 ID 查找，排序按钮仍按整个接口的真实顺序移动。切换语言保留搜索、分页及草稿，数量减少时将页码限制在有效范围。网址误填为模型 ID、接口地址格式错误与空 Key 均在编辑时校验。保存操作栏只显示保存、取消及实际保存中的反馈，不显示常驻“未保存”。仅有一个接口时不显示接口删除按钮，可从提供商卡片移除整体；多个接口时在标题旁提供删除按钮。提供商编辑和单模型编辑各自使用聚焦表单，编辑期间隐藏其他提供商卡片、订阅账号和独立模型分组；进入表单后滚动到顶部并聚焦首个字段。保存、取消及保存中的反馈集中在表单顶部，操作栏固定在设置内容滚动区顶部，不必滚到表单末尾寻找。保存错误显示在操作栏内并保留草稿；取消不写入，保存成功或取消后返回来源卡片或模型行并恢复其编辑入口焦点。提供商与模型字段分别标明“提供商名称”和“模型名称”。模型选项设置上下文容量、输出上限、输入类型（文本／图片／视频）和推理等级映射。获取模型和保存前，先明确提示缺少 Key、重复 Key 或未完成账号授权，不把这些情况提交为笼统的格式错误。Key 全停用时可保存配置，但获取模型前须先启用一个 Key。模型探测读取当前草稿，不自动保存。刷新提示分别显示完整模型列表的新增、下架数量及从选择中移除的数量；新增模型仍由用户选择。成功目录替换缓存成员并从草稿移除已下架模型，同名模型保留身份、顺序和手工选项；保存时将接口级 `model_catalog` 与选中模型原子发布，重新打开及运行时都使用该缓存。模板仅提供初始目录及同名能力元数据，不把下架成员拼回成功结果。获取期间暂时禁用保存，避免把旧目录提交；同一表单中后续编辑不会被迟到结果覆盖。失败、未支持的列表协议或不完整分页结果保留现有缓存与选择并明确提示，空的完整结果可以移除全部模型。更换接口地址、协议或认证类型会清除该接口的旧目录缓存；修改接口、协议、请求头或凭据会取消旧探测等待并丢弃迟到结果，隐藏或关闭页面同样停止读取。

新增模型优先使用接口报告的思考档位，同名模型补充已知元数据；明确的同版本日期快照可沿用已知系列的思考档位和输入类型，不据此推断窗口、输出上限或跨版本能力。发现链路读取接口明确返回的容量字段（包括 `context_length`、`context_window`、`max_input_tokens`、`max_output_tokens`、`max_completion_tokens` 及 `top_provider` 中的容量）和 `architecture.input_modalities` 中支持的文本／图片／视频类型；不按名称推断容量。界面对未报告容量显示“未知，可手动填写”并提供元数据说明。接口未报告的能力保持未知，可在模型选项手工配置。思考映射随目录及模型保存，目录外模型的显式档位也进入模型菜单和实际请求。

Chat Completions 的模型选项可单独选择推理参数格式：`reasoning_effort`（OpenAI）或 `reasoning.effort`（OpenRouter）；继承时沿用目录、接口及运行库的默认设置，模型显式设置优先于接口。不根据模型名称猜测格式，也不在失败后自动尝试另一种格式。目录通过 `reasoningEfforts` 报告的档位与显式映射同样进入实际请求，包含 `max`／`xhigh`；未报告的档位不补造。选择“模型默认”时不主动发送这两种推理参数，调用方显式扩展仍保留；选择 `off` 与模型默认分别处理。

输入框的模型按钮同时显示所选思考级别，沿用当前对话覆盖或全局默认；保存中和未确认的值标为待确认，目录未支持的选择标为不支持，不将其宣称为实际请求值。只有一个已报告档位时仍可在菜单选择该档位或模型默认。无思考能力且没有所选级别的模型不显示思考标签；实际请求证据继续在生成详情中查看。

OAuth 使用提供商自己的授权流程。登录先暂存服务端草稿凭据，选择模型并保存后才写入配置；授权页地址和设备代码显示在接口内。隐藏页面暂停授权状态读取，取消操作会停止所属授权进程。环境认证与云认证不要求 API Key，可填写对应环境字段，或使用后端进程已有环境、AWS 凭据链、Google ADC 等提供商支持的认证。

OpenAI 的订阅接口统一显示为“Codex 帐号池”，只有一个多账号入口，可选择当前账号或启用自动切换。默认自动切换开启，准入阈值沿用已用 95%；账号需要实际可读取的额度。本机 Codex 网关和 Harness 对话共用账号，网关启用开关独立于对话模型。订阅登录不隐藏其他提供商。

OpenCode Zen 的指定端点 `https://opencode.ai/zen/v1` 保留专用请求映射。本机 OpenCode 接口使用 `https://opencode.ai/inference/openai/v1`，读取本机 OpenCode 资料并沿用原有传输；详见 [本机 OpenCode](opencode-local.md)。原生 OpenCode 混合目录也可保留模型各自的协议和地址。

OpenRouter 在接口未显式选择协议、所选模型也没有协议元数据时，使用统一的 Chat Completions 入口。此规则覆盖手工添加、目录外新模型、空缓存和缺少协议字段的缓存；协议优先级为接口显式选择、所选模型目录声明、OpenRouter 端点默认值。已有模型声明的 Messages 协议及显式选择的 Responses 协议继续生效，运行时不改写已保存配置。其他混合协议提供商仍沿用自己的协议选择规则。

Custom API 的 Chat Completions 接口默认使用 `system` 角色传递系统指令；声明推理能力、选择 `high`／`max` 或使用模型默认，都不会自动将其改为 `developer`。Qwen Token Plan、CN 与 Individual 使用相同的系统角色默认值，包括目录外的新日期快照和手工模型。兼容参数按端点默认值、模型目录、接口配置、模型配置的顺序逐字段覆盖；已明确支持 `developer` 的接口可通过 `supportsDeveloperRole: true` 声明，其他原生提供商继续使用自己的角色规则。不修改已保存的配置或对话。

## 免登录免费模型

在“模型提供商”中选择 **Kilo Free**，将其作为免费渠道配置。新增时自动获取当前免费目录，初始不勾选 Auto Free 或其他模型，可通过“选择模型”搜索、勾选具体模型，再保存；模型菜单按 Kilo Free 分组展示具体模型，支持选择 `Auto Free` 或指定模型执行开发任务。无需登录、API Key、OpenCode 安装或本机资料。协议与地址由渠道固定，界面集中显示匿名状态、模型选择及服务说明。读取失败时保留候选 `kilo-auto/free` 或已有目录，并显示回退状态；可显式再次获取。隐藏或关闭编辑器会取消目录等待，不采用迟到响应。再次选择已添加的 Kilo Free 会编辑原配置，不再新增同一渠道。已有配置及后续刷新保留用户勾选，不自动选择新增模型。保存配置和设为默认模型仍沿用原有显式操作，不修改其他接口或对话。

此入口来自 `dsh-our-free-model` 的 Kilo 免密车道：直接访问 `https://api.kilo.ai/api/gateway/models` 和 `/chat/completions`，不依赖该插件运行，不经过插件维护者的中转。目录只接收上游明确声明 `isFree: true` 的模型；不把名称含 `free`、价格为零或需要账号的渠道自动视为匿名免费模型。容量及输入类型只采用远端报告值，推理档位只采用远端显式变体；未报告值保持未知。刷新成功以新目录为准，失败保留原目录并显示回退状态。

Kilo Free 固定公共地址与 Chat Completions 协议，使用 `anonymous` 认证，配置中不保存 Key 或认证环境变量；生成请求移除认证头，不继承其他提供商凭据。流式正文、思考、工具调用和用量复用 Harness 既有解析器；工具仍经本机注册表、权限检查和执行循环处理。免费不代表不限量：模型上下架、地区、速率及服务状态由第三方决定。部分上游可能记录提示词用于改进服务，请勿发送机密数据。官方说明见 [Kilo 模型与提供商](https://kilo.ai/docs/gateway/models-and-providers)。

OpenCode 匿名通道使用上述 OpenCode Local 入口，需要先准备本机 OpenCode 资料；Kilo Free 不依赖该资料。

针对性离线验证：`.venv/bin/python -m unittest tests.test_kilo_free`。显式在线开发验收：`HARNESS_LIVE_KILO=1 .venv/bin/python -m tests.live_kilo_free_check`，在隔离临时项目中检查免费目录、真实文件写读、生成 Python 函数执行、同对话续接和另一对话隔离；可用 `HARNESS_LIVE_KILO_MODEL` 指定当前免费目录中的模型。在线验收不读取用户项目，不属于默认测试发现。

## 执行预算与流监控

“权限与预算”只提供每轮次步骤上限、每轮次 Token 预算和网络连接超时三个生成控制项；前两项默认无限，留空表示无限，网络连接超时默认 180 秒。模型目录或手工配置中的最大输出 Token 数是能力上限，不是每次请求的默认预算；调用方或轮次预算明确限制输出时，再依据所选模型容量及上下文余量收敛。Harness 不另设单次生成总时长、全局单次输出 Token 或累计响应字节上限；流监控只以网络无活动超时中止等待；有效进展计时用于观察，不触发停止。主对话与订阅／原生提供商请求共用当前网络超时设置。提供商桥接仍校验单条消息的格式和大小，正常的多条流消息不累计为响应大小限额。

原生桥接对采用 fetch 的传输观察真实响应头和正文片段，包括 SSE 心跳及尚未组成完整工具调用的参数；其他原生传输以可观察的供应商事件报告活动。活动上报按网络超时节流，不通过定时保活掩盖无响应。请求发出后的无活动超时、明确的连接中断及供应商库确认缺少结束帧的响应进入有限恢复；已有正文可作为续接锚点，已完成工具保持原结果。已经交付完整工具调用后失败、认证／证书拒绝、协议损坏及凭据刷新结果未知不因该恢复机制重放。请求日志保留首个解析事件时间、错误阶段、类型和代码；缺少这些证据的历史错误不能直接归因为网络不稳。

Chat Completions 与 Responses 在调用方未设置预算时省略可选的输出 Token 参数，使用提供商默认值，即使目录已经报告输出能力也不主动填满；提供商默认值仍可能截断响应，并不表示无限输出。直接 SDK 的 Chat Completions 请求采用同一规则，输入超过已知上下文容量仍在发送前拒绝。显式的 `max_tokens`、`max_completion_tokens`、`max_output_tokens` 与当前业务预算统一取较小值，再收敛到模型单次输出能力和上下文余量；扩展正文不能绕过这一约束，最终只发送所选协议的字段。Messages 等需要必填容量的协议继续由对应适配器提供该值，不把可选参数的省略规则套用到必填参数。运行库的占位容量 8192 不作为 Chat Completions 或 Responses 的默认生成限制。

轮次收到提供商的 `length`／`max_tokens` 截断响应且没有工具调用时，保留该段响应并继续请求续写；不因连续若干段正文相同或为空而主动报错停止。普通 SSE 与原生提供商仅返回思考的截断响应同样交给轮次续写。续写沿用本轮的用户停止、显式步骤／Token 预算、上下文整理和提供商错误处理，每段响应及续写关联仍写入原对话。重复工具结果及收尾纠正同样不按固定次数终止；咨询型提醒与计划审批仍继续生效。

## 运行与构建

Python 包交付 `harness/llm/runtime` 中的桥接程序、提供商目录和许可说明。通用原生适配固定为 `@earendil-works/pi-ai@1.3.0`，运行时不引用外部源码仓库。Python 启动受监督 Node 子进程，通过版本化 NDJSON 传递请求和模型事件，关闭和取消时等待所属进程回收。OAuth 刷新先原子保存新凭据并确认，再继续请求。

源码构建需要 Node.js 22+：执行 `npm --prefix model-runtime ci`，修改桥接源后执行 `node model-runtime/build.mjs`。`node model-runtime/build.mjs --check` 检查发行资源同步，Web 生产构建自动执行该检查。桌面使用随 Electron 提供的 Node 运行时；独立 Python 运行需要 PATH 中的 Node，或通过 `HARNESS_NODE` 指定。

配置只支持当前版本，不迁移旧格式。新建 Key 和手工模型输入均为空，禁用浏览器表单自动补全；输入 Key 后离开编辑框显示固定星号加末四位，已保存 Key 通过服务端遮罩展示。公开接口返回 Key 遮罩与认证状态，不返回 OAuth 令牌；保存使用修订比较，冲突需回查后再编辑。各模型具有稳定的提供商／接口／模型身份，默认选择、对话覆盖、智能体与子智能体目录共用该身份。设置中的模型列表及模型菜单使用模型名称，不展示 `harness/...` 内部身份；目录缺失时显示模型不可用，默认选择和可见性仍通过该身份保存。输入区和模型菜单直接显示模型名称；未手选时显示并勾选默认模型，手选其他模型只作用于当前对话。菜单标题只标明选择操作，当前模型由列表勾选表达。对话的思考强度将“跟随全局默认”作为独立选项，与显式档位及“模型默认”互斥；跟随时不同时高亮生效的具体档位，说明中仍显示当前继承值。新对话草稿修改的仍是全局默认强度。

离线回归不能证明在线账号、额度服务或各平台安装包可用。提供商核对依据与仍待验收的边界见 [提供商实现审查](model-provider-review.md)。
