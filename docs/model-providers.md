# 模型提供商

首次使用打开设置中的模型配置，点击“选择提供商”打开提供商目录弹层，搜索并点选一个提供商，随后填写认证与模型并保存；新增接口默认不勾选模型，已有接口编辑时保留原选择。不会自动建立 OpenRouter、OpenCode 或订阅账号配置。运行目录由 `HARNESS_HOME` 指定，默认 `~/.harness`。

每个提供商的名称、配置状态、模型数量及模型显示开关、默认模型操作放在同一张卡片中。每个模型始终显示上下文容量，未报告容量时显示“上下文：未知”，不推测默认值。模型按稳定的提供商／接口／模型身份归属，同名提供商或接口不会混合；只有多个接口时才显示接口分组名，单接口不重复提供商名称。显示开关和默认模型操作立即保存，不需要进入编辑表单；切换对话模型仍只影响当前对话，关闭显示开关后当前模型仍保留。非提供商配置来源的模型继续单独分组展示。配置卡片不显示未实现的连接测试状态。提供商目录按名称排列，同系列入口相邻；OpenCode 的各接口排在一起，Codex 帐号池归入 OpenAI 一组。此排序只影响显示，不修改配置、模型或 Key 的实际顺序。移除提供商先显示内联确认，取消不发送写入。编辑时依次显示接口协议、接口地址和认证方式，随后配置模型；已知地址由提供商模板默认填写。接口名称沿用卡片标题，不在高级设置中重复提供输入框；接口启用开关、请求头、兼容参数及超时等放在认证之后、模型之前的“高级设置”中，不与模型选项混排。混合原生目录可留空地址使用各模型端点；云接口可通过对应环境字段确定地址。常规编辑不显示添加接口按钮；展开“其他接口设置”后可添加其他接口。一个提供商可以添加多个接口，编辑卡片按接口收展并显示模型列表总数和已选模型数；同一种协议也可以配置不同地址。保留原生协议时，目录中各模型使用自己的协议和地址，不把整个目录强制转成 OpenAI。

API Key 属于接口。该接口的全部模型共用有序 Key 列表，可添加、删除、排序、启停及显式重置失败状态。鉴权失败将该 Key 标为不可用；限流或瞬时错误可切换其他 Key。耗尽后报错，不自动换模型或提供商。已交付内容后失败不自动重放。单 Key 的可重试请求遵循设置的重试上限。

模型可在接口卡上手动填写模型 ID 添加，支持回车，输入法组合期间不触发；新添加的模型自动展开模型选项，可直接调整元数据。候选模型较多时点击“选择模型（数量）”打开模型列表弹层，弹层内搜索、勾选并分页浏览，每页 50 项；“全选”与“全不选”作用于当前筛选结果并在按钮上标明数量，“添加各系列最新版”按模型 ID 的版本和用途分组追加各系列最新版本；日期快照不与无日期别名重复选择，Pro／Flash／Max、模型大小等不同用途仍分别保留，明确不受支持的版本不加入该批次。弹层内的改动点“确定”才写回接口，取消丢弃；批量添加保留已有模型的身份、顺序、启停和高级选项，全不选不移除手工填写的模型。已选模型可删除和上下调整顺序，已选配置每页 10 项；已选项超过 10 项时提供独立搜索，按名称或模型 ID 查找，排序按钮仍按整个接口的真实顺序移动。切换语言保留搜索、分页及草稿，数量减少时将页码限制在有效范围。网址误填为模型 ID、接口地址格式错误与空 Key 均在编辑时校验。保存操作栏只显示保存、取消及实际保存中的反馈，不显示常驻“未保存”。仅有一个接口时不显示接口删除按钮，可从提供商卡片移除整体；多个接口时在标题旁提供删除按钮。保存操作栏随表单滚动保持可见，与编辑卡片同色并贴齐左右边界，按钮与表单字段对齐。提供商与模型字段分别标明“提供商名称”和“模型名称”。模型选项设置上下文容量、输出上限、输入类型（文本／图片／视频）和推理等级映射。获取模型和保存前，先明确提示缺少 Key、重复 Key 或未完成账号授权，不把这些情况提交为笼统的格式错误。Key 全停用时可保存配置，但获取模型前须先启用一个 Key。模型探测读取当前草稿，不自动保存。刷新提示分别显示完整模型列表的新增、下架数量及从选择中移除的数量；新增模型仍由用户选择。成功目录替换缓存成员并从草稿移除已下架模型，同名模型保留身份、顺序和手工选项；保存时将接口级 `model_catalog` 与选中模型原子发布，重新打开及运行时都使用该缓存。模板仅提供初始目录及同名能力元数据，不把下架成员拼回成功结果。获取期间暂时禁用保存，避免把旧目录提交；同一表单中后续编辑不会被迟到结果覆盖。失败、未支持的列表协议或不完整分页结果保留现有缓存与选择并明确提示，空的完整结果可以移除全部模型。更换接口地址、协议或认证类型会清除该接口的旧目录缓存；修改接口、协议、请求头或凭据会取消旧探测等待并丢弃迟到结果，隐藏或关闭页面同样停止读取。

新增模型优先使用接口报告的思考档位，同名模型补充已知元数据；明确的同版本日期快照可沿用已知系列的思考档位和输入类型，不据此推断窗口、输出上限或跨版本能力。发现链路读取接口明确返回的容量字段（包括 `context_length`、`context_window`、`max_input_tokens`、`max_output_tokens`、`max_completion_tokens` 及 `top_provider` 中的容量）和 `architecture.input_modalities` 中支持的文本／图片／视频类型；不按名称推断容量。界面对未报告容量显示“未知，可手动填写”并提供元数据说明。接口未报告的能力保持未知，可在模型选项手工配置。思考映射随目录及模型保存，目录外模型的显式档位也进入模型菜单和实际请求。

OAuth 使用提供商自己的授权流程。登录先暂存服务端草稿凭据，选择模型并保存后才写入配置；授权页地址和设备代码显示在接口内。隐藏页面暂停授权状态读取，取消操作会停止所属授权进程。环境认证与云认证不要求 API Key，可填写对应环境字段，或使用后端进程已有环境、AWS 凭据链、Google ADC 等提供商支持的认证。

OpenAI 的订阅接口统一显示为“Codex 帐号池”，只有一个多账号入口，可选择当前账号或启用自动切换。默认自动切换开启，准入阈值沿用已用 95%；账号需要实际可读取的额度。本机 Codex 网关和 Harness 对话共用账号，网关启用开关独立于对话模型。订阅登录不隐藏其他提供商。

OpenCode Zen 的指定端点 `https://opencode.ai/zen/v1` 保留专用请求映射。本机 OpenCode 接口使用 `https://opencode.ai/inference/openai/v1`，读取本机 OpenCode 资料并沿用原有传输；详见 [本机 OpenCode](opencode-local.md)。原生 OpenCode 混合目录也可保留模型各自的协议和地址。

Qwen Token Plan、CN 与 Individual 的 Chat Completions 接口默认使用 `system` 角色传递系统指令，包括目录外的新日期快照和手工模型。兼容参数按端点默认值、模型目录、接口配置、模型配置的顺序逐字段覆盖；可通过 `supportsDeveloperRole` 显式调整，不修改已保存的目录或对话。

## 执行预算与流监控

“权限与预算”只提供每轮次步骤上限、每轮次 Token 预算和网络连接超时三个生成控制项；前两项默认无限，留空表示无限，网络连接超时默认 180 秒。模型请求的输出 Token 依据所选模型容量、上下文余量及当前业务预算计算。Harness 不另设单次生成总时长、全局单次输出 Token 或累计响应字节上限；流监控只以网络无活动超时中止等待；有效进展计时用于观察，不触发停止。主对话与订阅／原生提供商请求共用当前网络超时设置。提供商桥接仍校验单条消息的格式和大小，正常的多条流消息不累计为响应大小限额。

原生提供商桥接在分发前将请求预算收敛到所选模型的单次输出能力，再由提供商库检查上下文余量。对于 Chat Completions，目录与手工配置均未报告输出能力且调用方未设置预算时，省略输出 Token 参数，使用提供商默认值；既不把上下文余额当作输出上限，也不把运行库占位容量 8192 当作生成限制。已知输出能力与较小的显式预算继续生效；其它协议仍按其必填容量要求处理。

轮次收到提供商的 `length`／`max_tokens` 截断响应且没有工具调用时，保留该段响应并继续请求续写；不因连续若干段正文相同或为空而主动报错停止。普通 SSE 与原生提供商仅返回思考的截断响应同样交给轮次续写。续写沿用本轮的用户停止、显式步骤／Token 预算、上下文整理和提供商错误处理，每段响应及续写关联仍写入原对话。重复工具结果及收尾纠正同样不按固定次数终止；咨询型提醒与计划审批仍继续生效。

## 运行与构建

Python 包交付 `harness/llm/runtime` 中的桥接程序、提供商目录和许可说明。通用原生适配固定为 `@earendil-works/pi-ai@1.3.0`，运行时不引用外部源码仓库。Python 启动受监督 Node 子进程，通过版本化 NDJSON 传递请求和模型事件，关闭和取消时等待所属进程回收。OAuth 刷新先原子保存新凭据并确认，再继续请求。

源码构建需要 Node.js 22+：执行 `npm --prefix model-runtime ci`，修改桥接源后执行 `node model-runtime/build.mjs`。`node model-runtime/build.mjs --check` 检查发行资源同步，Web 生产构建自动执行该检查。桌面使用随 Electron 提供的 Node 运行时；独立 Python 运行需要 PATH 中的 Node，或通过 `HARNESS_NODE` 指定。

配置只支持当前版本，不迁移旧格式。新建 Key 和手工模型输入均为空，禁用浏览器表单自动补全；输入 Key 后离开编辑框显示固定星号加末四位，已保存 Key 通过服务端遮罩展示。公开接口返回 Key 遮罩与认证状态，不返回 OAuth 令牌；保存使用修订比较，冲突需回查后再编辑。各模型具有稳定的提供商／接口／模型身份，默认选择、对话覆盖、智能体与子智能体目录共用该身份。设置中的模型列表及模型菜单使用模型名称，不展示 `harness/...` 内部身份；目录缺失时显示模型不可用，默认选择和可见性仍通过该身份保存。输入区和模型菜单直接显示模型名称；未手选时显示并勾选默认模型，手选其他模型只作用于当前对话。

离线回归不能证明在线账号、额度服务或各平台安装包可用。提供商核对依据与仍待验收的边界见 [提供商实现审查](model-provider-review.md)。
