# 项目上手与 README

目标：产出一份**与当前代码一致**的上手文档，让新人在不了解背景的情况下能完成安装、启动和首次改动。

## 工作方式

1. **先摸底，后动笔**。用 `glob`、`grep`、`read` 扫描真实结构：
   - 包管理入口（`pyproject.toml`、`package.json`、`go.mod`、`Cargo.toml` 等）
   - 启动入口、脚本目录、CI 配置、测试目录
   - 已有的 `README*`、`AGENTS.md`、`docs/`——存在则在其基础上修订，不另起炉灶
2. **只写验证过的事实**。版本要求、启动命令、环境变量必须来自真实文件；无法确认的标注“待确认”，不编造。
3. **结构建议**（按需取舍，不堆砌）：
   - 一句话定位 + 核心能力
   - 环境要求与安装
   - 启动 / 构建 / 测试命令（逐条可执行）
   - 目录导览（只列关键目录）
   - 配置项与环境变量
   - 贡献入口（行为准则、验证命令）
4. **复杂项目先列计划**：用 `todo_write` 维护扫描与写作步骤，逐项推进。
5. **交付**：写完用 `present` 把文档声明为交付物；如修改了既有文档，向用户说明改动点。

## 质量红线

- 文档中的每条命令必须能从源码推断或直接验证；宁缺毋滥。
- 不删除用户已有的内容，修订时保留原文档结构与已有链接。
- 中文项目用中文写文档；中英文混排时注意术语与空格。
