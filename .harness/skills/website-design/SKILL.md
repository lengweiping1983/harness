# 网站设计

目标：交付一个**能直接打开、视觉完整**的静态网站，而不只是一堆代码片段。

## 工作方式

1. **先澄清再动手**。至少确认：网站类型（落地页 / 官网 / 文档站 / 活动页）、受众、必备内容板块、风格偏好（简洁 / 科技感 / 温暖 / 品牌色）。信息不足时用 `ask_user_question` 一次性问清，不要边写边猜。
2. **信息架构先行**：列出页面与板块清单（导航、首屏、功能区、页脚），用户确认后再写代码。
3. **视觉决策一次成型**：确定配色（主色 + 中性色 + 强调色）、字体层级、间距节奏与圆角语言，全站保持一致；不使用逐元素随意取色。
4. **实现**：用 `write` 生成站点文件——单页站点一个自包含 `index.html`（内联样式与脚本），多页站点用共享的 `styles.css` 与相对链接。要求：
   - 响应式：移动端与桌面端都可用
   - 中文排版：合理的行高与中英文间距
   - 可访问性：语义标签、可聚焦、对比度足够
   - 零外网依赖：不引用随时可能失效的外部资源
5. **预览与迭代**：
   - 关键视觉（首屏、核心板块）可先用 `show_widget` 以 HTML 片段在对话中内联预览确认方向，再落成文件。
   - 落成文件后让用户在侧栏打开该 HTML：默认就是渲染后的网页（脚本可运行，但页面被关在沙箱里，拿不到本机数据），点"查看源代码"切回源码。多文件站点的相对资源（样式、脚本、图片）会按目录结构解析，不需要额外起服务。
   - 需要真实服务器行为（路由、后端接口、构建产物）时，再用 `terminal_open` + `terminal_send` 在项目目录启动静态服务，工作台会把终端输出中的本地地址显示为预览入口。
6. **交付**：用 `present` 把入口文件（及相关页面）声明为交付物，并说明如何打开与后续修改方式。

## 质量红线

- 内容优先：文案写真实内容，不用无意义的 Lorem 占位；数据类内容标注来源或示例性质。
- 不生成无法运行的代码：脚本与样式引用必须与实际文件一致。
- 图片素材用纯色块、渐变、SVG 或 `show_widget` 生成的示意图替代；不用来路不明的外部图片链接。
- 涉及中国地图时必须使用合规来源并包含南海诸岛等完整疆域，不手绘地图轮廓。
