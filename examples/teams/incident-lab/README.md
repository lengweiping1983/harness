# 故障诊断室

用于故障排查、性能异常、事件复盘与恢复方案评估。可只做离线分析，也可在明确授权下结合实时只读工具；不是自动生产运维机器人。

先安装本目录三名成员，再安装 incident-lab-diagnosis，均选择相同范围。在会话选择“故障诊断室”并正常发送任务。默认不启用技能，可按具体系统在编辑器选用。模型与现有配置一致。

示例提示：

> 根据指定目录中的变更与遥测记录分析本次超时。给出当前影响、竞争解释与下一项最有区分力的检查，比较必要的止损方案。只读，不执行重启或回滚；证据不足不要认定根因。输出格式自行选择，简洁但可追溯。

验收关注任务实际要求：时间线与版本是否一致；是否保留能改变判断的竞争解释；止损是否有前置条件和回滚；是否区分实际恢复与尚未验证的根因。没有统一问卷、强制轮数或方案数。仅有日志中出现关键词不能证明因果；仅有建议不能证明已操作或恢复。

资料未提供某指标只表示当前未知，不等于指标不存在或无法取回。复核时还应检查是否把建议写成已授权操作，降级、熔断与并发限制也属于需要评估影响的变更。

权限边界：主理人及三名成员均声明 `access=read`。主理人的声明由宿主限制为读取及协作控制，不能直接执行命令、写文件或调用未知副作用工具；成员受自己的只读约束。任务记录、派工与通信仍可正常进行。这是工具级限制，不是操作系统沙箱，也不保证远程工具的声明正确。

验证现状：构造时间线任务已实际运行两名成员并核对成员原始证据；团队可识别唯一根因与恢复证据不足。早期主理人配置未受宿主只读限制，曾执行任务禁止的命令并错误自报未执行；现主理人也显式配置只读，相关宿主边界另有回归，并在同输入真实运行中确认无命令与文件写入调用、派工与证据核对正常。报告仍可能过长，当前不作为完整事故处置质量验收通过。请以宿主真实记录核对授权遵守，不能用最终自述替代。

因果分析需先检查观察是否满足假设条件：前后时段同口径不等于其它因素受控，符合预期也不等于唯一原因已被证明。主动诊断优先考虑隔离回放或非生产验证；生产检查先说明授权、影响、停止与回滚条件。报告以本题决策需要为准，不要求打印固定因果表或完整事故模板。

因果压力案例复测中，团队已将实验建议放在隔离／预生产环境并明确生产权限边界；但仍可能把未受控前后对比表述为单因素、混淆主动实验与观察性检查。当前提示是方法指导，不能代替逐条审阅因果主张，也没有跨任务准确率保证。
