# 架构评审室

用于系统设计、跨模块演进、同步/异步改造、状态与恢复语义、性能和可维护性取舍。它做只读评审，不自动写代码或部署。

先安装三份成员，再安装 architecture-lab-review，均选择相同范围；在会话选择“架构评审室”后正常发送任务。主理人与成员均显式只读，默认技能为空，可按具体领域另选技能。未启用技能不影响正常读取与协作工具。

示例：

> 阅读[代码／设计资料]，评审[本次设计决策]。硬约束是[约束]，重点检查用户可见行为、状态何时持久化、失败后的恢复，以及性能结论是否有同口径证据。按需要选择角色，给出取舍和最小验证建议，只读，不修改或部署。格式按问题选择。

验收关注：事实能定位到当前资料；受理、完成与持久提交没有混淆；推荐明确代价和未知；测量收益不凭框架名称推断；迁移与回滚建议有前提。未测恢复与性能只列验证计划，不能当已实现保证。

这是领域方法起点，不等于正式外部架构认证，也未证明跨任务稳定性或世界排名。沿用宿主工具权限与原始证据通路，不是操作系统沙箱；远程工具仍依可信副作用声明受控。开放探索不要求固定候选数、流程轮数、评分表或唯一结论。

当前验证边界：构造案例已完成两名成员的真实独立评审，能区分受理与持久完成并保留用户偏好未知，但仍出现测量时点命名、成本优先级和实验环境建议问题。提示已补充对应边界；尚未证明完整架构判断准确性或跨任务稳定性。主动验证仅在获授权隔离副本与可丢弃数据中建议进行，不能以本文代替生产操作授权。
