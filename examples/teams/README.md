# 可选 Agent 场景团队

当前场景提供独立 Agent 与团队目录，核心不内置、不自动安装。它们是可修改的起点，不限制团队数量或专业领域；可按任务新增定义、组合互补角色和选择方法。它们只有场景定义与提示，没有第二套协作引擎。

工作台另提供无需逐个安装成员的内联团队起点，使用方式及权限边界统一见[扩展能力](../../docs/extensions.md#agent-与团队)。本页说明下面这些目录示例的安装与调用。

| 场景目录 | 选择器名称 | 适用场景 | 预期交付 |
|---|---|---|---|
| decision-lab | 方案决策室 | 对抗、方案取舍 | 候选比较、反证、分歧、验证建议 |
| brainstorm-lab | 头脑风暴室 | 创意发散、问题重构 | 不同路径与假设，按任务决定是否评估和实验 |
| evidence-review | 证据协作 | 集群研究、事实核对 | 按任务呈现证据、竞争解释、未知项 |
| architecture-lab | 架构评审室 | 系统设计、跨模块演进、质量取舍 | 场景与约束、状态协议、风险、可验证演进 |
| experiment-lab | 实验评估室 | 实验设计、效果评估、A/B与基准复核 | 指标口径、识别边界、条件化验证与结论 |
| incident-lab | 故障诊断室 | 故障排查、恢复决策、复盘 | 影响与证据、竞争解释、条件化恢复与验证 |
| delivery-lab | 合同交付协作／并行模块交付 | 集群配合、项目实现 | 任务合同、独立模块实现、合入及验收依据 |
| learning-design-lab | 课程设计协作 | 学习目标、课程结构、渐进路径、评估与 Harness 学习环境 | 结构化课程蓝图、市场基准、质量取舍与未知项 |

## 启动

1. 在项目根目录运行 `python scripts/dev.py`，按启动输出打开 Harness；模型和工具沿用现有配置。
2. 在 Agent 页面浏览场景下的成员目录（含 `AGENTS.md`）并分别安装；再在团队页面浏览并安装对应团队目录。目录名与定义名称一致，成员引用使用这些显式名称。所有定义选择相同的用户级或项目级范围。
3. 打开会话，在输入框 Agent／团队选择器选择上表名称，正常发送需求。各目录 README 提供可直接使用的示例。
4. 后续消息直接继续；需要切换场景时更换常驻选择。显式 `/agent` 是一次性调用，不能代替常驻选择。

也可以从仓库根目录批量安装当前示例，先预览，再显式应用：

```sh
.venv/bin/python scripts/install_example_teams.py --scenario evidence-review
.venv/bin/python scripts/install_example_teams.py --scenario evidence-review --apply
# 安装全部场景（含共享成员的不同团队配置）
.venv/bin/python scripts/install_example_teams.py --all --apply
```

该入口通过本地 `/api/v1` 注册到用户范围，先安装引用成员，再安装团队。相同定义保持不变；任何同名差异或停用配置都会中止，不覆盖已有配置。创建响应失败时只读回确认，不自动重放；部分安装后可重新执行，已核对一致的定义会跳过。它不会启动模型任务，安装可用也不代表团队输出质量已经通过评测。可用 `--base-url` 指定其他本地 HTTP 端口。

安装仅注册定义，不启动模型、任务或外部连接。子任务并发依任务需要启动，依赖与只读权限由宿主执行。参与人数和实际调度受现有预算、成员花名册及并发上限约束；不是无限规模集群。已支持显式启用宿主管理的成员工作树；多人类同时写入与工具授权仍待完成。真实模型质量与成本需要单独实测。

## 项目交付的隔离方式

默认在当前项目协作，不要求配置成员工作树。共享目录内由提示词安排串行开发及交接；项目明确要求隔离时，按项目约定使用已有工作树能力。宿主仍支持显式隔离参数，但团队卡片不再提供工作树开关，普通使用无需设置。
成员依赖完成后，宿主先预检并合入依赖的冻结交付，再启动下游成员。核验者保持只读；交付不自动合并进原项目。工作树及成果在运行结束后保留，后续整合与清理由用户显式操作。工作树能分开文件树，但命令和第三方工具不是操作系统沙箱，不能据此声称完全隔离。

`delivery-lab` 同时提供「合同交付协作」和「并行模块交付」。小任务选前者，可拆成两个独立模块的项目选后者；两者复用同一 planner、builder、verifier 定义。并行模块交付在规划成员完成后支持两个实现成员并发，核验成员依赖两份成功交付。需要实际文件树隔离时使用宿主已有隔离能力；未开启隔离时场景提示要求串行，但提示词不等于成员任务级互斥锁。冲突交付由宿主预检拒绝，下游不会启动，原项目及各份成果仍保留。声明了 write_paths 的工具现在有单次路径互斥，但命令和整个成员任务不在该范围内。

在输入框重新选择当前同一团队会保留已配置的工作树与工作副本选项；切换其他团队时不继承隔离配置。独立编码执行器是另一种执行入口，使用 `/runner`；场景团队的常驻选择仍正常发送需求，不需要手工改写成命令。

[场景任务与验收](ACCEPTANCE.md) 提供团队场景（交付类含两种配置）的可复制任务、追问方式和业务验收标准，并区分离线内核验证与真实模型质量。
