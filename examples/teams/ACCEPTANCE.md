# 场景任务与验收

按 [启动说明](README.md) 安装团队与成员，选定常驻团队，复制下面对应任务并替换方括号内容。模型和工具仍使用当前会话配置；不需要创建另一套编排配置。先用小范围、明确输入验证，再扩大任务。

| 选择团队 | 可直接使用的任务 | 验收时查看 |
|---|---|---|
| 方案决策室 | 对于[问题]，比较[方案 A]与[方案 B]。硬约束是[约束]。需要独立主张和反证；给出能推翻各自主张的条件，保留未解决分歧，提出下一步最小验证。 | 双方实际回复、共同约束、反证来源；不能以“全员同意”代替取舍依据 |
| 头脑风暴室 | 在[约束]内解决[目标]。按需独立构思与重构问题，比较不同原理的候选。输出三个优先实验，分别列出成功和失败判据；不把同义改写算新方案。 | 候选来源成员、实质差异、淘汰理由、可执行实验及未知项 |
| 证据协作 | 研究[明确问题]，限定[时间／资料范围]。拆成不同子问题，优先一手来源，交叉核验关键结论，检查竞争解释。逐条区分观察与推断，列出来源位置和未验证项。 | 原始来源可定位、重复转述不算独立证据、无法获取的资料明确标注 |
| 架构评审室 | 读取[代码／方案]，评审[架构决策]，遵守[约束]，检查质量取舍、持久化与失败恢复，给出下一项验证。只读，不迁移或部署。 | 真实调用与状态边界、关键质量情境、收益测量依据、条件化演进；不把入队受理称作持久完成 |
| 故障诊断室 | 根据[日志／遥测／变更记录]判断[异常]的影响与竞争解释，给出最有区分力的下一项检查和条件化恢复建议。只读，不执行重启或清理。 | 版本与时间线、反例、用户路径与恢复窗口；不把短时无告警当作根因已修复，不虚构已执行操作 |
| 合同交付协作 | 阅读项目规则，为[改动]制定验收合同与文件责任范围，实现并独立核验。报告实际改动、验证命令与结果、未完成项；不自动合并原项目或发布。 | 实际文件、验证输出、独立核验依据；工具成功或提交记录不等于业务完成 |
| 并行模块交付 | 为[需求]划分两个能独立实现的模块，明确各自文件与接口负责人，按依赖交付后独立核验。遇冲突保留成果并返工，不覆盖另一份交付。 | 先显式开启工作树；两份交付及依赖合入证据、冲突阻断、原项目状态 |
| 课程设计协作 | 为[主题]设计课程蓝图，默认检查入门、进阶、精进三级路径，并结合公开课程基准、学习效果和 Harness 环境约束。 | 目标与成果可观察；系列边界由能力和先修关系支持；逐课内容含练习与产出；评估能连接证据；Harness 能力、模拟和缺口分开；市场观察、推断和未知有来源区分；不创建课程文件 |

## 追问与返工

继续在同一会话正常发送，例如“保留现有结论，重新核验第二条证据，并请原成员补充限制”。常驻选择继续生效；主 Agent 可按需使用 followup_task 续接原成员上下文，不需要用户复制成员历史或手动生成运行 ID。需要真正独立判断时，任务应提供完整问题与硬约束，并要求 fork_turns=none；独立背景不意味着获得额外权限。

在成员面板核对真实成员、运行状态和原始回复；查看工具详情中的派工／等待／续接结果。超时不是完成，成员结束不是验收通过。任务板的严格验收还需要实际合同与宿主核验证据；上述聊天示例本身不会自动建立或完成合同。

## 当前验证范围

离线回归覆盖团队验收状态、成员证据归属与跨回合续接；交付验证入口与范围见[开发与测试](../../docs/development.md)。离线通过不能证明某个真实模型已完成上述业务任务，示例定义也不是团队质量保证。

工作台内联团队起点的使用与权限边界见[扩展能力](../../docs/extensions.md#agent-与团队)。可复测的安全、性能、产品与证据研究构造案例及显式在线命令维护在[专业团队验收案例](../../tests/fixtures/specialist_teams/README.md)，这些小案例不代替开放任务审查、严格验收在线端到端、并行交付或固定输入下的质量与成本对照。验收依据应保留在可复测的任务、来源、回归和原始运行中，不依赖可删除的工具临时输出。

实际验收时保留用户授权范围内的输入、模型配置、来源、运行记录、成果与核验结果，按上表检查业务标准。当前没有同输入的质量与成本对照，不作跨产品优劣或性能结论。

## 实验评估室

输入一份已有结果，明确要求仅复核还是设计新实验。例如：计划用户级随机分配1:1，只有处理后活跃人数400/600及完成数40/90，活跃定义随版本变化；旧延迟测持久完成，新延迟测202受理。请 measurement 与 skeptic 分别复核，暂不设计新实验。

按题面核对：能否保留10%与15%、相差5个百分点及描述性相对差50%，同时拒绝直接升级为因果提升；能否识别延迟终点不同；能否区分曝光/活跃人数与随机分配计数，不直接确认分配故障；缺设计与数据时是否避免编造显著性、零丢失或精确样本量。只复核时不应自动执行实验或强制输出完整方案。改变题目与数据后重新判断，以上不是所有实验的固定结论或通用评分表。

实验评估的固定回归入口为 `tests/fixtures/experiment_inference`，通过 `scripts/evaluate_research_team.py` 显式运行和收集。除先前的指标与识别边界，还包括未经提供的取证可达性和成本；不能从“需要这份证据”推成“这份证据现成且最便宜”。评分覆盖有支持、被否证与未知三类，单次通过不替代开放报告审阅。
