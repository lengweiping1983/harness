# brainstorm-lab

在 Agent 页面通过“浏览”分别安装本目录中含 `AGENTS.md` 的成员目录，再在团队页面安装团队目录。在会话输入框的 Agent／团队选择器选择「头脑风暴室」，然后正常发送需求。常驻选择持续作用于后续消息及新会话物化；显式 `/agent` 仅用于一次性调用。安装不启动模型或任务。

示例输入：

> 围绕降低产品首次使用成本提出不同原理的方案，独立构思后交叉评估，给出三个可验证实验。

成员共享现有运行、消息、权限和预算服务。依赖由宿主校验，调度由当前任务决定，不绑定固定三阶段。使用 `list_agents` 查看实际成员身份；`spawn_agent` 启动，`send_message` 沟通，`followup_task` 续接，`wait_agent` 等待，`interrupt_agent` 停止。成员停止或工具成功不等于业务验收。

团队不扩大工具权限；工具不可用或预算不足时明确报告限制。只读成员不能承担文件实现。多人写入前必须明确文件责任范围并使用适当隔离；声明范围不等于操作系统沙箱。所有发布、外部操作仍服从项目授权。团队及成员可分别停用或卸载，不删除用户会话。

1.0.1 补充估算与淘汰纪律：没有源码、实施规模或组织流程证据时，不给精确交付承诺，不把未知依赖说成不可行；人天与日历工期分开。更新后的真实质量仍需独立复验。

探索范围由本次需求决定。只需要发散时，团队保留不同机制、矛盾构想及开放问题，不强制排名、淘汰或安排实验；要求收敛时再评估与验证。未经本次核验的心理、社会或行为背景机制须标为待核验认识或启发性假设；创意不必先获得证据才能保留，但不能把构想效果或成员自信写成已证实事实。
