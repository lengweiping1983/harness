# decision-lab

在 Agent 页面通过“浏览”分别安装本目录中含 `AGENTS.md` 的成员目录，再在团队页面安装团队目录。在会话输入框的 Agent／团队选择器选择「方案决策室」，然后正常发送需求。常驻选择持续作用于后续消息及新会话物化；显式 `/agent` 仅用于一次性调用。安装不启动模型或任务。

示例输入：

> 比较两个技术方案，明确硬约束，组织独立主张与反证，输出取舍、分歧和下一验证。

成员共享现有运行、消息、权限和预算服务。依赖由宿主校验，调度由当前任务决定，不绑定固定三阶段。使用 `list_agents` 查看实际成员身份；`spawn_agent` 启动，`send_message` 沟通，`followup_task` 续接，`wait_agent` 等待，`interrupt_agent` 停止。成员停止或工具成功不等于业务验收。

团队不扩大工具权限；工具不可用或预算不足时明确报告限制。只读成员不能承担文件实现。多人写入前必须明确文件责任范围并使用适当隔离；声明范围不等于操作系统沙箱。所有发布、外部操作仍服从项目授权。团队及成员可分别停用或卸载，不删除用户会话。

1.0.1 根据真实案例补充证据边界：核对“必然”判断的前提和反例，区分部署位置与原文传输、总量与个体行为；重复的成员假设不能替代来源。提示约束本身不构成质量保证，更新后的真实效果仍需复验。
