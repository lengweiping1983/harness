# evidence-review

在 Agent 页面通过“浏览”分别安装本目录中含 `AGENTS.md` 的成员目录，再在团队页面安装团队目录。在会话输入框的 Agent／团队选择器选择「证据协作」，然后正常发送需求。常驻选择持续作用于后续消息及新会话物化；显式 `/agent` 仅用于一次性调用。安装不启动模型或任务。

示例输入：

> 研究一个明确问题，按子问题分工并交叉核对一手来源，输出证据矩阵、竞争解释、未知项和检索边界。

成员共享现有运行、消息、权限和预算服务。依赖由宿主校验，调度由当前任务决定，不绑定固定三阶段。使用 `list_agents` 查看实际成员身份；`spawn_agent` 启动，`send_message` 沟通，`followup_task` 续接，`wait_agent` 等待，`interrupt_agent` 停止。成员停止或工具成功不等于业务验收。

团队不扩大工具权限；工具不可用或预算不足时明确报告限制。只读成员不能承担文件实现。多人写入前必须明确文件责任范围并使用适当隔离；声明范围不等于操作系统沙箱。所有发布、外部操作仍服从项目授权。团队及成员可分别停用或卸载，不删除用户会话。

1.0.1 明确按问题范围提交必要证据、限制无关统计扩展并及时汇总。真实固定案例已在 300 秒内完成三名成员与最终矩阵，但仍有将未知写成事实和超长回复的问题，未通过全部语义验收。提示中的长度和停止要求不是宿主硬性完成证明。

固定资料回归可通过 `scripts/evaluate_research_team.py --run --case tests/fixtures/research_conflicts` 显式启动，随后用 `--collect` 指定输出的 evaluation.json 收集同一次运行。分类与字面引文检查之外，成员来源必须对应本次主运行直接委派、成功完成且无错误的真实子运行；花名册身份、失败或其他回合的运行不能替代。该检查不证明引文对全部理由的语义支持，也不用于限制其他开放研究或头脑风暴任务。
