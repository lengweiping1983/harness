# delivery-lab

在 Agent 页面通过“浏览”分别安装本目录中含 `AGENTS.md` 的成员目录，再在团队页面安装团队目录。在会话输入框的 Agent／团队选择器选择「合同交付协作」，然后正常发送需求。常驻选择持续作用于后续消息及新会话物化；显式 `/agent` 仅用于一次性调用。安装不启动模型或任务。

示例输入：

> 先读取项目规则，针对指定需求制定可核验合同，拆分依赖和文件责任范围，实现后安排独立核验并报告未完成项。

成员共享现有运行、消息、权限和预算服务。依赖由宿主校验，调度由当前任务决定，不绑定固定三阶段。使用 `list_agents` 查看实际成员身份；`spawn_agent` 启动，`send_message` 沟通，`followup_task` 续接，`wait_agent` 等待，`interrupt_agent` 停止。成员停止或工具成功不等于业务验收。

团队不扩大工具权限；工具不可用或预算不足时明确报告限制。只读成员不能承担文件实现。多人写入前必须明确文件责任范围并使用适当隔离；声明范围不等于操作系统沙箱。所有发布、外部操作仍服从项目授权。团队及成员可分别停用或卸载，不删除用户会话。

## 隔离交付

团队默认共享当前项目目录，应串行派工。项目需要隔离交付时，按已有项目约定使用宿主支持的工作树能力；团队卡片无需配置隔离选项。宿主按成员创建独立工作树，把依赖交付预检合入下游工作树后才启动成员。实现者写入自身目录，核验者在自身工作树只读核验。原项目不会自动收到成员变更，运行结束也不删除工作树。使用前请确保 Git 与工作树能力已启用；这不是命令级操作系统沙箱。

## 并行模块交付

同一包还提供「并行模块交付」团队。在有明确独立模块与可用隔离现场时选择它，然后发送：

> 实现需求 X。先读项目规则和现有实现，明确验收合同，把改动分成两个能独立验证的模块，指定各自文件范围与接口。并行实现后合入独立核验，保留冲突与未完成项，不自动改原项目或发布。

主理人与 planner 明确边界后，first 和 second 复用 builder 各自实现；review 复用只读 verifier，依赖两份交付。宿主负责依赖状态和交付合入的校验。任一依赖失败或合入冲突时，下游不能启动。当前只有声明路径工具的单次写入互斥，没有成员任务级共享目录写锁；命令和未声明路径的工具不在该范围内，未启用工作树时仍应串行派工。


## 核验结论

按合同逐项记录“已验证符合／不符合／未验证”。读取当前源码可以支持静态行为检查，却不能单独证明测试已运行、文件与基线逐字节相同或没有历史增删。缺少能力与证据时保留未验证，列出可执行的补验步骤；实际发现不满足条件才返工。主理人不得用成员完成或 Git 合入代替验收，也不得把审阅中的未知项汇总为全部通过。

1.1.1 更新现有成员职责，不改变成员对象、依赖或工具接口；已有安装定义可在 Agent／团队页编辑，不自动改写用户安装。提示约束本身不保证模型语义正确。


开启成员工作树隔离后，当前宿主还会限制主理人的工具发现与执行：主理人保留读取、派工、通信及任务管理，不能自行写文件、运行命令、调用外部写入或未知副作用工具。实现成员仍在自己的工作树写入。限制在团队结束时解除；需要写回原项目时，在结束隔离团队后由用户明确授权普通任务执行。该能力由宿主运行约束提供，团队提示不替代执行检查。


## 回复长度

1.2.0在团队metadata配置`member_reply_max_chars: 400`和`summary_max_chars: 600`。按完整可见回复的Unicode字符数计数，包含空白、标点、Markdown和路径；不是中文字数或token数。宿主在现有完成检查中要求超限回复完整精简，最多复用三次继续尝试；再超限明确失败。所有候选正文保留，不静默截断，不把重写当作重新执行工具。实际验证、失败和未知项必须保留。

两个选项可分别省略，省略时不加对应限制；显式值须为1–100000的整数，布尔值不合法。直接指定单个成员时应用成员限制，不把直接成员正文再次当主理人汇总。长度符合只代表篇幅符合，不证明内容正确；失败时按真实状态处理，不绕过严格验收。已有安装包通过当前更新入口显式更新。


1.2.1为两个交付团队显式设置`member_retry_limit: 1`，同一成员连续失败后最多恢复一次；成功交付后重新计数。超限时宿主拒绝新建运行和工作树，主理人应交付已有成果及未完成项。spawn与空闲followup共用检查，新用户回合不永久继承失败次数。它不保证最终答复预算充足，也不代替严格验收。


1.2.2要求标题、摘要和结论保持相同证据等级：缺基线时写“实现者报告写入X，完整差异未验证”，不能先说“其它文件未变”再在末尾收回。实现者操作记录、当前源码内容、基线差异和实际运行结果分别报告；重复转述不增加可信度。该更新是职责提示，现有宿主验收闸继续生效，不能保证模型自然语言始终正确。
